# File manager (SFTP)

- **File manager (`sftp/ops.rs` (pure helpers + tree walks), `api/sftp.rs`, `ws/filemanager.rs`; tests `tests/sftp_ops.rs` on the SSH lab with a real `sftp-server` + unit tests; frontend `components/tunnels/FileManagerPanel.tsx`, `components/files/`, `hooks/useFileManager.ts` (socket + listing + `link` state from close codes) / `hooks/useFileOps.ts` (REST + upload queue), pure `lib/fileManager.ts` (tested), `lib/uploadXhr.ts`):** the socket still only lists (entries now also carry `bytes` / `mode` / `perm` / `mtime` / `link`; a symlink to a folder lists as a folder); every operation is REST on the pooled shared SFTP channel with the same gate as the other `/api/sftp/*` routes (VIEW + step-up + `allowed_usernames`): `POST mkdir` / `touch` (`{path}`, 409 `exists`, never truncates), `rename` (`{from, to}` or `{paths, destination}` = move; plain SFTP rename, so nothing is overwritten — 409 `exists`; `into_itself`), `delete` (`{paths}`, `?count=1` = dry run `{files, dirs, links, bytes, entries, truncated}` capped at 100k; then children-first removal that never follows links), `chmod` (`{paths, mode: "0755", recursive}`, links skipped, children first), `copy` (`{paths, destination}`: unix devices run `cp -R -p --` over an exec channel so data stays on the device; exit 127 / exec refused / Windows → streamed through the backend, ≤ 256 MB; answers `method: device | stream`), `zip` (`{paths}` → one zip, multi-select download; `download` of a folder too — both **stream** the zip while it is built (`sftp/zipstream.rs`: an async task walks the tree into a bounded channel, a `spawn_blocking` thread owns zip 9's `ZipWriter::new_stream`; no temp file, first bytes at once, so proxies' first-byte timeouts no longer cut big folders; links stored as links, never followed; unreadable entries skipped and listed in `TELEPY-SKIPPED.txt`; Deflate level 1, Stored for compressed formats; roots checked before streaming starts), `GET stat` (lstat + link target), `GET/PUT text` (≤ 1 MiB, NUL in the first 8 KiB = `binary`, non-UTF-8 = `not_utf8`; a save canonicalizes the path (a link's target is edited, the link stays), compares `mtime` + `size` from when it was opened (409 `modified` unless `force`), writes `.<name>.telepy-<rand>.tmp` next to it with the old mode (EXCLUDE) and replaces it with `posix-rename@openssh.com` on a short raw sftp channel of the same pooled connection (the high-level `SftpSession` has no extended requests), else backup → rename → remove; a folder the account can't write = 403 `dir_not_writable`). The root, a drive root and the home folder are `protected`. Errors are `{error, code}` → `files.err.<code>`. Gateway events `files_delete` (who, count, paths — never content) and `files_edit` (who, path, size). UI: click opens (folder / preview / download), checkbox + Ctrl/⌘ / Shift select → bulk bar (zip, move, copy, permissions, delete), drop files **or folders** from the desktop (or "Upload folder", `webkitdirectory`; `lib/droppedFiles.ts` `readDropped`, shared with the RustDesk files panel) to upload (3 at a time, a name clash asks first — same-name folders are merged into, files in them replaced; per-file and all cancel), drag rows onto a folder (or the Up button) to move, keys Enter / Backspace / F2 / Delete (⌘⌫) / Ctrl/⌘ A / ↑↓ / Esc (hint inline when the panel is wide, a popover when narrow, mouse devices only), `FileViewerDialog` = image preview (≤ 10 MiB, blob with the right MIME so SVG renders) or CodeMirror 6 (`components/files/CodeEditor.tsx`, lazy core + one language per file, colours from the design tokens, wrap in localStorage `telepy.fileEditorWrap`, ⌘S saves, conflict callout with Reload / Overwrite); the info button opens `FileFlowDialog` (browser ─ Telepy ─ shared SFTP channel ─ `account@device`, states from `fileSpotStates(link, busy)`, offline 4005 / step-up 4008 shown where they stop). **Downloads use one-time links** (`sftp/links.rs`, `state.downloads`; test `tests/file_transfers.rs`): `POST /api/sftp/download-link/{id}/{username} {paths}` (same gate, step-up included) → `{url: /api/sftp/fetch/tpd_…, name, zip, size, expires_in: 60}`, single use, ≤ 20 per person; the browser opens `GET /api/sftp/fetch/{token}` itself (no bearer; user active + feature `files` + VIEW + allowed account checked again; failures are plain text), so a download goes straight to disk with the browser's own progress instead of `fetch` → blob in memory. Every download carries `Content-Disposition` with `filename*=UTF-8''…` (`sftp::attachment`; Chinese names used to arrive garbled), `Cache-Control: no-store, no-transform`, `X-Accel-Buffering: no`, a single file `Content-Length` (sent with `take(len)`), and is **not compressed** — the backend's `CompressionLayer` predicate and Traefik's `compress` both exclude `application/octet-stream` / `application/zip` (compression dropped Content-Length and only cost CPU). **Uploads go in parts** (`PUT /api/sftp/upload-part/{id}/{username}?path=&upload=&offset=&total=[&overwrite=1][&parents=1][&retry=1]`, raw body ≤ 32 MiB; `DELETE` same path `?path=&upload=` cancels; pure `ops::part_step` / `part_path` / `mkdir_all`): each part is its own request, so Cloudflare's 100 MB request cap and proxies' timeouts never see a big file, progress means "on the device", and a failed part is resent (`lib/uploadParts.retryDelay`: 0 / 408 / 429 / 502–504 / 520–524); the bytes go into a hidden `.<name>.telepy-upload-<id>.part` next to the target and are renamed onto it only when complete (existing file: `overwrite` or 409 `exists`; replaced with its mode kept via `replace_file`), so a failed upload never damages the existing file; 409 `upload_offset` + `received` = resume there, 409 `upload_gone` = start again, a resent last part after a lost answer is recognised as done. Frontend: `lib/uploadParts.ts` (pure, tested), `lib/uploadXhr.ts` `uploadInParts` (XHR per 8 MiB part, renew / step-up / retry), `useFileOps` queue (`UploadJob.target/overwrite/parents/upload/retry`, state `cancelled`, `uploadListRows` keeps the list short for big folders). The multipart `upload` route (CLI fallback, tokens) also writes a part file and renames it. **Unfinished uploads (`uploads.rs` pure `decide` / `sweep` + loop, `db/upload_parts.rs` = `telepy_upload_part`; test `unfinished_uploads_resume_safely_and_are_cleaned` in `tests/file_transfers.rs`):** Telepy records every part file it creates (tunnel, account, uploader, upload id, target, part path, total, received, local name + mtime, lease) and only ever cleans recorded paths — never a pattern scan, never another server's or person's file. `POST /api/sftp/upload-start/{id}/{username} {path, total, overwrite, local {name, modified}, resume, lease?}` (files above one part) answers `{upload, lease, offset, check_from, resumed}`: the same person + target + local identity resumes at the part file's size on the device after `decide` (`Busy` when written within `BUSY_FOR` 30 s by another window — the browser waits and re-asks every 10 s ≤ 6 times; `Stale` when the part file is gone / empty / too big → dropped, fresh), and the first part after a resume carries `check` = SHA-256 of the local `[check_from, offset)` (last 64 KiB) compared with the device copy (409 `upload_mismatch` → part + entry removed → the browser starts a fresh upload; no WebCrypto (plain http) = no resume). Every part must carry the lease once there is one (409 `upload_taken` for another window / another person's id); a part being written refreshes the entry every 10 s (`HEARTBEAT`). A name clash at the finish keeps the part + entry (409 `exists` + `kept`); the UI's Replace re-runs with `overwrite` and the same lease, which resumes at the total and sends one empty part. `GET /api/sftp/uploads/{id}/{username}?dir=` lists the folder's unfinished uploads as the device has them (a vanished part file drops its entry; size from the device) with `mine`, `by`, `active`, `removed_in`, `can_discard` (uploader, owner / ADMIN); `DELETE upload-part` honours the same rule (403 `not_yours`). `uploads::run` (every 10 min) removes entries idle ≥ `RETENTION` (24 h) on an online device (only while the path is still a regular file) with a `files_upload_cleaned` event, waits for an offline device, forgets after 30 days; entries go with the tunnel. Frontend: the panel hides recorded part files and shows "N unfinished upload(s) here" (Continue = pick the same file, checked by `sameLocalFile`; Discard), re-checks every 15 s while one is active; a clash shows amber "Name taken" with Replace / Discard; a local file changed / removed mid-upload = `local_changed`. `telepy cp` streams downloads to disk and uploads in parts (multipart only for an older server). `resolve_path` anchors relative paths (`x`, `./x`) at the home folder. Leftover part files from a tab closed mid-upload stay as hidden files. Single-file downloads `fuse()` their stream: the compression layer polls once more after the end, and the unfused `unfold` panicked, so compressed (browser) downloads hung.
