# Web terminal — page, PTY sessions, shell history, appearance, toolbox

- **Terminal page + path pickers (`app/tunnels/terminal/page.tsx`, `components/tunnels/TerminalConnectPanel.tsx`, `hooks/useTerminalConnect.ts`, `components/flow/PathFlow.tsx` + `ConnectNodes.tsx`, `components/desktop/DesktopPathPicker.tsx`, `lib/flow.ts` + `lib/terminalFlow.ts` (pure, tested), `components/tunnels/TerminalFlow.tsx` + `TerminalInfoDialog.tsx`):** `/tunnels/terminal` without `serverId` (sidebar "Terminal", `nav.terminal`) is a **connect picker**: the path diagram *is* the form — your browser ─ Telepy ─ device (device + account selects inside the node, live online / offline + tunnel RTT) ─ shell (the device itself or a LAN host from the topology, plus the login) — and "Open terminal" navigates to the same page with `serverId` (+ `lanHost` / `lanUser`); selection in `?tunnel=&lanHost=`, last device in localStorage `telepy.terminalPick`. The remote desktop page's form starts with the same picker (`DesktopPathPicker`: target select, protocol, port in the last node) and keeps quality / clipboard / login below. `components/flow/PathFlow.tsx` holds the diagram blocks (`FlowPath`, `FlowNode` with an optional `control` slot, `FlowLink`, `FlowSteps`, `FlowNow`; straight lines, `@3xl` row / column) used by the pickers and both info diagrams (`DesktopFlow`, `TerminalFlow`); generic copy is `flow.*`. The terminal page's header has an info button (`TerminalInfoDialog`: the active tab's phase from `ShellTab.status` + `closeCode` through `lib/terminalFlow.terminalPhase` / `closeFailure` — 4005 = tunnel, 4006 / device-4003 = device, LAN 4003 = target, LAN 4004 = reach, 1000 / 1005 = the shell ended, both round trips on the links) and "Another device" (back to the picker). The list's open buttons are Terminal / Files / Browser / **Desktop** (`/tunnels/desktop?tunnel=`), tiles four across only when the longest label fits on one line in a quarter of the row (measured in `TunnelOpenButtons` `useTilesAcross` with the pure, tested `lib/openTiles.tilesFitAcross`; labels never wrap), else 2×2 — the old fixed 19rem threshold broke Japanese 「デスクトップ」 per character.
- **Terminal:** one PTY session channel per tab on the pooled connection (`ssh::terminal::PtySession`: pty-req `xterm` → shell, `window_change` on resize); tabs, the file manager and SFTP of the same (tunnel, OS account) share one SSH login, closing a tab closes only its channel, an offline device is refused with 4005 at once (the file manager too — no exec fallback for a device that isn't there). The terminal page mounts `FileManagerPanel` only while it is visible (desktop side panel open / phone files view): a mounted panel is a reconnecting `/ws/filemanager/` socket and counts as "Files" presence; `useFileManager` remembers the last directory per (tunnel, account) so reopening returns there. Only the LAN-host hop still spawns OpenSSH in a PTY (`openpty`; teardown = SIGTERM → SIGKILL of the direct child). Gate tests: `tests/terminal_e2e.rs`, `tests/socks_e2e.rs`. **Detach / reattach (`terminal_detach.rs` = pure `effective` + `Backlog` + the `Shells` registry in `state.shells`; `ws/terminal.rs` `Shell` / `attached` / `keep` / `finish`; tests in `tests/terminal_e2e.rs` on the echo-shell lab):** a shell outlives its socket. After auth the server sends a binary `{type:"shell", id, resumed, offset, reset, detach:{secs, by}, size}`; a socket that drops **without** `{action:"end"}` (network, reload, navigating away) leaves the shell running for the grace = the narrowest of the user setting `terminal_detach_secs` (0 / 60 / 300 / 900 / 1800 / 3600; **0 = end at once, the default**), the site ceiling `terminal_detach_max_secs` (default 1800, 0 = off) and the tunnel's `terminal_detach_policy` (`user` | `never`, owner / ADMIN `PUT /api/reverse/server/{id}/terminal-detach {policy, reauth?}`, relaxing to `user` needs `reauth`; `terminal_detach_setting` event), read again at drop time. While detached: PTY keeps being read (recording, command-rule screen model and pending approvals continue; outcomes are stashed and sent on reattach), the last 256 KiB of output stay in `Backlog` (chunks = text frames, offsets in UTF-16 units like JS string lengths), presence carries `detached: {since, ends_at}` (Live sessions page shows "Detached · ends …", ending it there ends the shell), ≤ 10 detached per user (oldest ended). Reattach = auth frame `resume: <id>` (+ `offset` the browser has seen): same user, tunnel, account and LAN host only (else 4004), unknown / expired = **4015** `shell_gone`; the holder (attached socket or keeper) hands the shell over through a oneshot, an attached old socket gets **4016**; replay = everything after `offset`, or `reset: true` + the whole buffer (from the first newline after a trimmed start) when the offset is unknown or gone. Explicit ends never keep: `{action:"end"}` (closing a tab, switching account, a fresh shell), 4009 from the live sessions page, 4010 sign-out, the shell exiting; on expiry the `terminal_close` event says "ended after N s detached". **Losing access ends shells, attached or detached** (test `tests/terminal_e2e.rs` `losing_access_…` / `turning_…_off_…` / `a_never_policy_…` / `signing_out_…`): the access recheck (see **Access loss** in `sessions.md`; for shells the pure `access_recheck::lost()` checks account disabled → feature → no VIEW → account off the allow-list → detached while the tunnel policy / site now says 0; the user's own later 0 keeps what is kept) ends them via `Presence::end_because(id, ENDED_BY, why)` — the live-session path, so the shell's own `finish` closes PTY / OpenSSH child, recording, pending approval and presence and `terminal_close` reads "ended by … [while detached]: <why>"; attached sockets get 4009 with reason `Telepy (access changed)`, the user `SESSION-ENDED {reason: access_removed|login_removed|account_disabled|detach_off, detached}`. Frontend: pure `lib/terminalDetach.ts` (tested: policy mirror, shell frame, `canResume` = drop codes 1001/1006/1011–1014 within the grace, sessionStorage list per `shellStoreKey(tunnel, account[, lanHost, lanUser])`, timeline states), `hooks/useTerminalDetach.ts` (store + localStorage `telepy.terminalDetach`), `lib/terminalShellSocket.ts` `endKeptShell` (ends a kept shell when the tab has no open socket); `useTerminalPage` and `LanTerminal` (dock list in sessionStorage `telepy.lanDock`, `lanShellEnders` for explicit closes) resume in place with a `ReconnectBanner` ("Reconnecting… (shell kept for N)", "Why?", "Retry now"), reload re-attaches the stored shells (offset unknown → redraw), 4015 opens a fresh shell with a notice; `components/tunnels/DetachTimeline.tsx` (`DetachInfoDialog`: connected ─ drop ─ kept N ─ reattach | time's up, plus which layer decides) behind the Preferences → Terminal info button (`TerminalDetachPref`) and the banner's "Why?" (`ReconnectWhy`, page-level); `TerminalDetachSetting` in the tunnel page; copy under `detach.*`.
- **Shell history (`shell_history.rs` (pure plan / probe parsing / notice + the `run` setup over an `Io` trait, unit-tested), `api/shell_history.rs`, `db/shell_history.rs`; test `tests/shell_history.rs` on the lab with a **real** bash / zsh login shell (`MachineOpts { shell: true, login_shell: Some("/bin/bash") }`: exec sees it as `$SHELL`, a PTY shell request spawns it interactive with HOME / `.bashrc` / `.zshrc` / the history file in the account's scratch home); frontend `lib/shellHistory.ts` (tested), `hooks/useShellHistory.ts`, `components/tunnels/ShellHistory{Pref,Setting,InfoDialog}.tsx`):** Telepy's background probes (device facts, LAN scans, platform / resolver / key lists) are exec channels (`sh -c` / `powershell -NonInteractive`) and never write shell history; only text typed into an interactive PTY shell does — the web terminal (Toolbox runs included) and MCP agent shells. The user setting `shell_history` (`keep` default | `skip`, `/api/user/settings`) plus a personal per-tunnel override (`telepy_shell_history_pref`, `GET/PUT /api/reverse/server/{id}/shell-history {mode: keep|skip|null}` → `{mode, default, effective, source}`, anyone who can see the tunnel, deleted with it) decide it per new shell (`shell_history::effective_for`). On `skip`: the login shell is asked with one exec (`echo $SHELL $PSHOME` → bash / zsh / sh / dash = POSIX, fish, cmd.exe (keeps no history file), PowerShell / ksh / others = unsupported; cached 10 min per (port, account) in `DevicePool::login_shell`; agent shells probe on their own connection), then after the first prompt (output quiet 300 ms) Telepy types one leading-space line — POSIX ` if [ -n "$ZSH_VERSION" ]; then unset HISTFILE; else HISTFILE=/dev/null; fi && printf '%s%s\n' telepy-history-off- <nonce>` (zsh must never get `HISTFILE=/dev/null`: as root it renames `/dev/null.new` over /dev/null), fish `set -g fish_history ''; and printf …` — and only when the joined marker comes back drops everything from the typing through the second prompt (screen stays on the first prompt; tracker, backlog, recording never see it); no marker (read-only `HISTFILE` = an enforced history, never bypassed; wrong shell; a startup script reading input) = the held output goes out unchanged. Result `Applied` → a grey `[Telepy] …` notice first in the backlog (like the recording line), `terminal_open` gets `(shell history off, bash)`, agent `shell_open` returns `history: off | failed | unsupported` (null = kept) and its audit detail says so. Not covered: LAN-host terminals (the hop's shell is unknown), shells started inside, PowerShell / ksh; zsh with `INC_APPEND_HISTORY` / `SHARE_HISTORY` but without `HIST_IGNORE_SPACE` keeps the one setup line. UI: Preferences → Terminal (`ShellHistoryPref`, a switch) and the tunnel page's Sessions tab (`ShellHistorySetting`: my default / save / keep out, terminal feature only), both with the info dialog (you ─ Telepy ─ the device's shell ─ history file, keep / skip toggle, the line per shell, limits); copy under `shellHistory.*`.
- **Terminal appearance (`lib/terminalAppearance.ts`, `lib/terminalSchemes.ts`, `lib/ligatures.ts`, `lib/xterm.ts`, `hooks/useTerminalDefaults.ts`, `hooks/useTerminalSchemes.ts`, `hooks/useTerminalAppearance.ts` (+ `useLiveTerminalLook`), `components/tunnels/TerminalAppearance.tsx`, `SchemeEditorDialog.tsx`, `AppearanceLayers.tsx`, `api/terminal_profile.rs`, `api/terminal_schemes.rs`, `db/terminal_profile.rs`, `db/terminal_scheme.rs`; tests `terminal_profile_per_tunnel` + `terminal_schemes_crud` in `tests/rest_api.rs`, frontend `terminalAppearance.test.ts` / `terminalSchemes.test.ts` / `ligatures.test.ts`):** font (six Nerd Font Mono choices, default `hack`), size (10–24), colour scheme (eleven built-in, default `telepy` = the old palette, plus the user's **custom schemes**), **bold style** (`face` = the real Bold face, default; `bright` = classic brighter colour only, weight 400; `both`) and **ligatures** (off by default; only fonts with `calt` — Fira Code, JetBrains Mono, Cascadia Code, 0xProto — ever join anything, `TerminalFont.ligatures`) in two layers. **My default** = `terminal_font` / `terminal_font_size` / `terminal_scheme` / `terminal_bold` / `terminal_ligatures` in `/api/user/settings` (localStorage `telepy.terminalFont` / `…FontSize` / `…Scheme` / `…Bold` / `…Ligatures`, one `telepy:terminal-appearance` event, backend writes debounced 400 ms). **This device** = a per-user, per-tunnel override in `telepy_terminal_profile` (`GET/PUT/DELETE /api/reverse/server/{id}/terminal-profile`, fields `font` / `font_size` / `scheme` / `bold` / `ligatures`; anyone who can see the tunnel, only affects the caller; PUT replaces the row, a null field follows the default, all null deletes it; deleted with the tunnel), cached in localStorage `telepy.terminalProfile.<id>` and read with `useSyncExternalStore`. The pure `effectiveAppearance(defaults, profile, customSchemes)` says for every field which layer supplied it (an unknown id — a removed font, a deleted custom scheme — or an out-of-range size inherits); `resolveTerminalAppearance` is it without the sources, and the dialog's info button opens `AppearanceLayers` (My default → This device → This terminal, straight lines, each box listing the five fields with "overrides" / "follows default" chips). **Custom schemes** (`telepy_terminal_scheme`: `scheme_id` = `custom-<8 hex>` made by the backend, name ≤ 40, `colors` JSON = `foreground` / `background` / `cursor` / `selectionBackground` + the 16 ANSI keys, optional `cursorAccent` / `selectionForeground`, every value `#rrggbb` (`api::terminal_schemes::validate_colors`, pure); ≤ 20 per user; `GET/POST /api/user/terminal-schemes`, `PATCH/DELETE /api/user/terminal-schemes/{id}`, owner only — someone else's id is a 404) are fetched once per sign-in by `useTerminalSchemes` (module store + localStorage `telepy.terminalSchemes`, cleared on logout) and passed into every lookup (`terminalScheme(id, custom)` / `isKnownScheme(id, custom)`): the terminal page, LAN terminals, the cast player, previews and `--term-bg` / `--term-fg` all go through `useTerminalAppearance(...).resolved`. A deleted scheme is **not** chased through settings: the frontend falls back to `telepy` for an id it cannot find (ids are shape-checked `[a-z0-9-]{1,32}` by the backend; `isSchemeId` client-side). The picker's "Custom" group has New scheme… (`SchemeEditorDialog`: name, import textarea with live detection of **Windows Terminal scheme JSON** (`purple` = magenta, `cursorColor`, a whole settings.json takes its first scheme) and **base16 YAML** (`base00…base0F`, mapped like the base16 alacritty / Windows Terminal templates), text / background / cursor / selection + the 2×8 ANSI grid of native colour inputs, live preview; starts from the current scheme) plus edit / delete on each custom card. **Bold / italic:** `terminal-fonts.css` declares the Nerd Fonts v3.5.1 Mono Bold / Italic / Bold Italic cuts under the same family names (Fira Code has no italic; 0xProto's Bold / Italic sit in `layout.tsx`'s next/font, no Bold Italic — `TerminalFont.faces`), `local()` first, each fetched only when text is drawn with that weight / style; xterm gets `fontWeight 400` / `fontWeightBold 700 | 400` / `drawBoldTextInBrightColors` from `xtermBoldOptions`, `waitForFont(font, bold)` also awaits the Bold face before the first shell (1.5 s guard) when the bold style uses it, and `useLiveTerminalLook` re-measures (monospace round trip) when a late face — Bold, or Italic from `document.fonts`' `loadingdone` — arrives, because xterm's width cache keeps the fallback font's widths otherwise. xterm's cell width can go stale while its per-character width cache (on `<body>`) follows the current font, and the difference becomes letter-spacing on every character (glyphs spaced apart, "the font goes off"): a font / size change on a hidden xterm (background shell tab, minimised or inactive dock terminal) is marked (`markIfHidden`) and re-measured once it shows, and a self-check catches every other path — `ensureMeasured` (`lib/xtermMeasure.ts`, tested) compares the default letter-spacing xterm puts on `.xterm-rows` (≈ 0 when healthy) plus a probe of 32 × W in the current font with that probe, re-measures on a mismatch > 0.25 px (retry every 10 s if it doesn't help) and logs one `[telepy] terminal cell width …` console line; it runs before every fit, on window focus / visibility change and every 4 s (`useLiveTerminalLook`). **Ligatures without `@xterm/addon-ligatures`:** in a browser the addon reads fonts through the Local Font Access API (Chrome only, a permission prompt, installed fonts only), so it never sees a `@font-face` font's GSUB and falls back to a fixed sequence list + `font-feature-settings: "calt" on`; `lib/ligatures.ts` + `xterm.applyLigatures` are that fallback without the 200 KB opentype.js bundle and the prompt — xterm 5.3's DOM renderer merges same-style cells into one span, the browser shapes the ligature (`"calt" on` is required because xterm's letter-spacing makes browsers drop calt; off is explicit too), and a character joiner (`allowProposedApi: true`) keeps a sequence in one span under the cursor / selection. Verified by screenshot in headless Chrome with the real xterm + woff2 files. Edited in Preferences → Terminal (defaults) and the terminal header's Appearance button (dialog with "This device" / "My default" tabs, live preview with bold / italic / ligature samples); open shells (terminal page tabs and the network page's LAN terminals, which use their device's override) pick up every change live, the terminal frame / tab bar follow the scheme through `--term-bg` / `--term-fg`, and the first shell waits for the profile so it never opens in the wrong font. `globals.css` pins xterm's 50,000px measuring div to `position: fixed` — otherwise a dialog (react-remove-scroll makes `body` `position: relative`) widened the phone layout to 1560px.
- **Toolbox — command snippets (`api/snippets.rs`, `db/snippets.rs`; tests `tests/snippets.rs` on the SSH lab + unit tests in the module):** `telepy_snippet` rows in three scopes — `user` (`user_id`; only you see / edit it, usable on every tunnel), `tunnel` (`tunnel_id`; owner / ADMIN edit, usable by whoever can open its terminal = owner / ADMIN or ≥ 1 allowed account, `can_use_tunnel`), `site` (superusers edit, everyone uses); name ≤ 60, command ≤ 4000 (outer newlines trimmed, inner = several lines), description ≤ 500, `variables` JSON `[{name, label, default, secret}]` (≤ 20, `parse_variables`: Python-Template names, unique, a secret never keeps a default), `confirm`, `sort_order`, `use_count` + `last_used_at`; ≤ 200 per scope (400 `{error, code: limit}`); deleted with the tunnel. `GET /api/snippets?tunnel_id=` = mine + that tunnel's (when usable) + site, plus `tunnel {id, name, can_use, can_edit}`, `can_edit_site`, `limit`; `POST /api/snippets` (`scope` default user, tunnel needs `tunnel_id`), `PATCH/DELETE /api/snippets/{id}` (usable but not editable = 403, not usable = 404; the scope never changes), `POST /api/snippets/{id}/used`. **Variables are substituted in the browser** (`lib/snippets.ts` `substitute`: `$name` / `${name}`, unknown names survive, and unlike Python `$$` stays `$$` — the shell's PID); values are never sent to the backend or stored. **Sending = typing:** the panel types through the terminal's own `pty_input` (never a bracketed paste, which would hide the lines from the command-rule guard), one line + `\r` at a time, the next once output settles (`settle` on xterm `onWriteParsed`), and stops when a new blocked / pending banner appears (`ToolboxTarget.banner()` is a getter on a page-level ref, because the phone sheet unmounts after sending); Insert types one line without Enter (multi-line snippets can't be inserted).
