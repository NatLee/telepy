# Remote desktop (RDP / VNC over guacd) and RustDesk in the browser

- **Remote desktop (`desktop/`, `api/desktop.rs`, `ws/desktop.rs`; design doc `docs/remote-desktop.md`; tests `tests/desktop_api.rs` with a fake guacd on the SSH lab):** RDP / VNC to the device itself (`127.0.0.1:<port>` as seen from the device) or to one of its LAN hosts (`telepy_lan_host` row of that tunnel), always through the device's own sshd: `POST /api/reverse/server/{id}/desktop/start` checks `desktop_enabled`, VIEW, the hop account via `permissions::choose_username` / `allowed_usernames` and `desktop_max_sessions`, then leases a pooled device connection and opens the `direct-tcpip` channel up front (`device_offline` / `device_auth` / `target_unreachable` are 502s there) and returns a 60 s single-use ticket. **RDP pre-flight (`desktop/rdp_probe.rs`, pure `parse` + unit tests; test `desktop_rdp_preflight_says_what_answered`):** guacd 1.6 answers `Server refused connection (wrong security type?)` (519) whenever no RDP server answers properly — nothing listening, a connection closed at once, another protocol (verified against a throwaway guacd 1.6.0) — so for RDP the start first sends an X.224 Connection Request + RDP_NEG_REQ (TLS | CredSSP | CredSSP-EX) over a second direct-tcpip channel of the same lease (5 s): closed without a byte = 502 `rdp_no_answer`, silent = `rdp_silent`, another service = `rdp_not_rdp` + `seen` (ssh | http | text | binary), each with `wsl: true` when the target is the device itself and its facts' kernel is WSL (`rdp_probe::is_wsl`, mirrored by `lib/desktop.isWslKernel`); an RDP Connection Confirm passes and the start answers `rdp {security: rdp|tls|nla|nla_ex|rdstls, failure}` (`desktop_open` says e.g. `(RDP, NLA)`). The page maps those codes (`startFailure` extra `seen` / `wsl` → `DesktopFailure.hint` = `desktop.err.wslHint`), turns a later guacd 519 after a passing pre-flight into `desktop.err.rdpHandshake` / `rdpRefusedSecurity` (`sessionFailure(code, msg, start.rdp)`), and shows `desktop.wsl.*` up front for RDP to a WSL device itself (WSL's 127.0.0.1 = WSL, with mirrored networking also Windows' own ports). The test desktop (`echo_service`) answers the pre-flight's Connection Request like an RDP server. `/ws/desktop/{sid}/?ticket=` re-checks access, binds a one-shot rendezvous port (peer must be guacd's IP), does the whole Guacamole handshake itself (credentials never reach the browser; memory only), and guacd's dial-back is piped into the channel. Browser → guacd passes an opcode allowlist only; lengths are re-encoded because guacd counts code points and the browser UTF-16 units. Sessions are presence kind `desktop`, write `desktop_open` / `desktop_close` gateway events (with duration, reason and the stream summary: bytes, frames, average / max frame latency) and end on idle (`desktop_session_idle_timeout`), `…/desktop/{sid}/stop`, or lost access (the access recheck: 4009 with `Telepy (access changed)`, the why in `desktop_close`). Site settings `desktop_*` (own Settings tab). **Clipboard direction is the user's own choice** (both / to_remote / off): the user setting `desktop_clipboard` (`user_management_usersettings`, `/api/user/settings`, which also returns the read-only `desktop_clipboard_limit`), edited on the desktop form's Clipboard field and in Preferences → Remote desktop (with the quality / sound / display defaults of the account's `desktop_display`, the same values as the desktop form) (`hooks/useDesktopClipboard.ts`, one shared store); every start (desktop, RustDesk via tunnel, RustDesk-server device) takes an optional `clipboard` (omitted = the saved choice) and answers `clipboard` (in effect) + `clipboard_limit`. The site setting `desktop_clipboard` is the **ceiling**: the narrower of the two applies (`desktop::Clipboard::within` / `effective`, mirrored by `lib/desktop.ts` `clipboardWithin`; options above it are disabled in the UI). guacd enforces it (`disable-copy` / `disable-paste`); RustDesk streams are opaque to the backend, so `RustDeskViewer` applies it in the tab (off = the peer option `disable-clipboard`, to_remote = remote clipboard events dropped). **Stream stats (`desktop/stats.rs`, pure):** the relay sends the browser `telepy-ping <n>` (answered with `telepy-pong`, settled at the relay, never forwarded) and `telepy-stats <json>` every second — frame round trip (guacd's `sync <ts>` until the browser's echo after drawing = what the user feels), network round trip, the monitor's tunnel latency, fps, bytes, frames behind, guacd-merged frames; the viewer intercepts both before the Guacamole client (unknown opcodes are ignored anyway). **Sound (RDP only):** start takes `audio` (bool, default false; VNC always false — guacd's VNC audio needs PulseAudio) and answers it; on = the handshake's `audio` instruction offers `audio/L8` + `audio/L16` (`desktop::AUDIO_MIMETYPES`, what guacamole-common-js's RawAudioPlayer plays), off = `disable-audio=true` so guacd never loads rdpsnd; guacd → browser is passed through untouched (`audio` / `blob` / `end`), the browser's `ack` is allowed and a browser `audio` (a microphone) is dropped; `desktop_open` says `(RDP, sound)`. The form's Sound switch (RDP + RustDesk, hidden for VNC; `desktop_display.audio`, off by default), the toolbar's sound button (`DesktopViewer` wraps the default player, drops blobs while muted and measures each blob's peak). **Sound diagnostics + autoplay (`lib/desktopSound.ts` pure + tested, `lib/soundTap.ts`, `components/desktop/SoundButton.tsx`):** browsers only let an AudioContext created / resumed inside a user gesture play (Safari strictly; it creates contexts `suspended`), but guacd's player and the RustDesk core create theirs in a WebSocket message — so `primeAudio()` creates + resumes one shared context synchronously in the Connect click (before any await) and in the sound-on click; guacd gets it as `Guacamole.AudioContextFactory.singleton`, the RustDesk core via `installRustDeskTap` (wraps `window.AudioContext` / `AudioDecoder` while the viewer is mounted: the core's `new AudioContext()` returns the shared one, decoded blocks are measured, restored on unmount). Viewers report a `SoundSnapshot` (channel opened, data within 2 s, audible, context state) via `onSound`; `soundReport` classifies off / unsupported / muted / waiting / blocked (data arrives, context not running → a "Click to enable sound" button that resumes it) / playing / quiet (channel open, silent) / none (no channel after 10 s; reason per path: RDP server without audio redirection — Windows policy, xrdp without pulseaudio-module-xrdp; RustDesk on Linux without a signed-in session's sound server; Intel-Mac RustDesk). The streams diagram's sound line follows it (`waiting` / `problem` states). The relay counts bytes on guacd's audio streams (`desktop/stats.rs`: `audio` in `telepy-stats`, null until a stream opened; "Sound data" in the stats popover; `desktop_close` says `sound N` or `no sound channel from the RDP server`). Verified with real sound (440 Hz through xrdp + pulseaudio-module-xrdp, and a Linux RustDesk) in Chromium and WebKit. Tests `desktop_rdp_sound_is_offered_and_relayed`, `desktopSound.test.ts`. **Streams diagram (`lib/desktopStreams.ts` pure + tested, `components/desktop/DesktopStreams.tsx`):** under the info dialog's path, picture / input / clipboard / sound / files as parallel straight lines with direction arrows and a state each — on / oneWay / off (incl. muted) / blocked (site ceiling) / unsupported (not on this way) — plus why; `ROWS` gained sound and files. Close codes 4009 / 4010 have their own copy (`desktop.err.signedOut`). **Quality preset** `quality` on start (`auto` | `speed` = 16-bit, more VNC compression, no font smoothing | `sharp` = 24-bit, lossless), `desktop_display.quality`. **Display (`lib/desktopDisplay.ts` + `lib/desktopZoom.ts` pure + tested, `hooks/useDesktopDisplay.ts`, `hooks/useDesktopZoom.ts`, `components/desktop/DisplayMenu.tsx` (toolbar) / `DisplaySettings.tsx` (Preferences → Remote desktop → Display); test `desktop_resolution_follows_the_window_within_the_site_limit`):** the user setting `desktop_display` (`user_management_usersettings`, `/api/user/settings` + the profile; one JSON object `{scale, percent, resolution, width, height, hidpi, vnc_resize, quality, audio}` checked by the pure `desktop::display::parse` — unknown fields / bad values = field error, percent clamped 25–400; empty = never chosen → null; mirrored by `lib/desktopDisplay.ts` `toServer` / `fromServer`; localStorage `telepy.desktopDisplay` is only the first-paint cache in `lib/desktopDisplayStore.ts`, and `UserSettingsSync` applies the account's value at sign-in or uploads this browser's (incl. the old `telepy.desktopQuality` / `telepy.desktopAudio` keys) while the account has none; test in `user_keys_settings_and_admin_users`) shared by Preferences, the connect form's Display field and the toolbar's Display menu: scaling `fit` (fills the frame, small pictures grow; default) / `shrink` (never above 1:1, the old behaviour) / `actual` (1:1) / `custom` %, as sticky modes over an absolute scale (`Bounds {fit, unit}`, unit = 1 / devicePixelRatio with HiDPI); the menu has − / % / +, fit / shrink / 1:1, the session's resolution status (`resolutionStatus`), HiDPI, "Fill the browser window" (card `fixed inset-0`, Esc still goes to the remote, "Back to the page" exits) and a link to Preferences; mouse users pan a larger picture by moving to its edge (`edgePan`). RDP resolution = match the window (start `resize: true`, default; `resize-method display-update`, the viewer sends `size` 400 ms after the frame settles and at once when the resolution / HiDPI choice changes) or a fixed size (`resize: false`: no resize-method, the relay drops `size`); HiDPI is its own switch (default off: xrdp / most VNC ignore `dpi`, so text gets tiny). VNC: `resize` defaults to false → `disable-display-resize` (guacd 1.6 otherwise sends SetDesktopSize, at connect too); on = virtual desktops (TigerVNC Xvnc, KasmVNC) follow the window, real screens keep theirs. RustDesk: scaled in the browser only (the vendored core's `change_resolution` is unimplemented). `desktop::clamp_size` scales the handshake size and every browser `size` (`ws::desktop::browser_size`) down to `desktop_max_resolution` on the longer side keeping the shape; start answers `resize` + `max_resolution`; `desktop_open` notes `fixed size` / `resizes with the window` when not the protocol default. The frame is `100dvh − 8.5rem` and the card scrolls under the sticky header on connect. **Screens (`desktop/screens.rs`, `GET …/desktop/screens?username=`, same gate as start):** VNC sends every monitor as one framebuffer and guacd has no monitor parameter, so "one screen only" is a browser-side crop (`DesktopViewer` `viewport`); positions come from the device over the pool (`uname -s` → `system_profiler SPDisplaysDataType -json` on Darwin (sizes only) / `xrandr --listmonitors` / PowerShell `Screen.AllScreens`; pure parsers, never an error, device desktops only) and `lib/desktopScreens.ts` places them (normalise + uniform scale; size-only layouts inferred from the framebuffer shape, black-area sampling for vertical alignment; when the device reports nothing usable, `guessScreens` decomposes the framebuffer into 2–4 screens of common aspect ratios (`SCREEN_RATIOS`, sum within 0.5%, closest fit → equal ratios → fewer screens, every order tried, a shorter screen measured from a black band consistent across 9 sampled columns and validated against a common ratio; shown as "guessed from the shape"), chosen in the toolbar's Screen menu (detected screens, always-available even splits via `splitChoices`, and a drag-selected **custom area**: `selecting` mode shows the whole desktop under an `AreaSelector` overlay, `rectFromPoints` clamps it, keys and mouse stay local meanwhile; stored as JSON in `telepy.desktopArea.<…>`), remembered per target in `telepy.desktopScreen.<tunnel>.<host|device>`. **RustDesk** is not rendered (guacd cannot speak it): the page's third mode probes the Direct IP port from the device (`GET …/desktop/probe?port=&username=&lan_host_id=`, same gate and path as start, channel closed at once, no `desktop_enabled` check) and shows the `ssh -L 21118:…` command from the command sheet's `rustdesk` recipe (alias from `/tunnels/server/config/{id}`) for the native app; LAN scans probe 21118 and `lanConnect` names it. **Keyboard / IME:** focus lives in a `Guacamole.InputSink` textarea (IMEs only compose in editable elements — this is why Chinese from a Windows browser reaches a Mac's VNC), "Type text" sends composed text as paced Unicode keysyms (`keysymForCodePoint`), "Send Ctrl as ⌘" remaps Control → Meta (auto-on for Darwin devices from a non-Mac browser, `telepy.desktopCtrlAsCmd`). **Touch zoom (same zoom module):** both viewers (guacd and RustDesk) lay out through `useDesktopZoom().layout(frame, content, unit)` — the scale of the current mode, the frame clipping and a clamped pan; the crop `viewport` is the content, so screens / areas compose with it; two-finger pinch / pan (one finger stays the remote mouse: tap = click, long-press = right click), a − / % (tap = fit) / + pill top-right on coarse pointers, and on phones (`(pointer: coarse) and (max-width: 639px)`) a shrunk picture opens at `PHONE_ZOOM` (1.5 × fit); a new session, another screen / area, a resolution change or a changed preference re-applies the starting mode. Frontend: `/tunnels/desktop?tunnel=<id>[&lanHost=<id>]` (sidebar, tunnel actions menu, LAN host dialog), `components/desktop/DesktopViewer.tsx` (guacamole-common-js, lazy-loaded), `DesktopStats.tsx` (toolbar latency / stream button + breakdown popover; `lib/desktopStats.ts` pure, tested), `DesktopFlow.tsx` + `DesktopInfoDialog.tsx` — the info button's live path diagram (browser ─ Telepy ─ device ─ desktop, each spot waiting / active / ok / failed from `lib/desktop.ts` `spotStates`, round trips on the links while connected), copy under `desktop.*`. **Ways to connect** (`components/desktop/ConnectionWays.tsx` + pure, tested `lib/connectionWays.ts`): a dialog comparing RDP / VNC through the tunnel (guacd) and RustDesk through the tunnel — both paths in aligned columns (browser ─ Telepy ─ device ─ desktop; tunnel = double line, local hop = dashed) with an encryption ruler whose spans run node centre to node centre (TLS / SSH / the protocol's own; `layerColumns`, labels wrap inside their box) and a "draws the picture" badge, then a fact table (cards on phones) and how to choose; the current way (`wayFor`) is marked. Opened from the desktop page header, the protocol field's hint and the info dialog's footer; copy under `desktop.ways.*`. When a fact changes, update `ROWS`. Telepy deliberately reaches RustDesk **only through the tunnel**: a "Telepy as RustDesk's ID / relay server" mode (devices without a tunnel) was built in #201–#208 and removed again to keep one path that every other feature (terminal, files, presence, recording, sharing) already covers; the research stays in `docs/engineering/rustdesk-id-server.md`, and the data migration `2026-10-26-drop-rustdesk-server-devices` deletes its saved logins (`tunnel_id` = 0) and drops its two tables (columns `telepy_credential.rustdesk_device_id` / `desktop_rustdesk_server` stay, unused). **Saved logins (credential vault; `vault.rs`, `db/credentials.rs`, `api/credentials.rs`; tests `tests/credentials_api.rs`):** per-user `telepy_credential` rows bound to one target (protocol `rdp` / `vnc` / `rustdesk` / **`ssh`** + tunnel + optional LAN host / port), CRUD at `/api/credentials` (owner only, admins included; the password is never returned, only `has_password` / `has_key`); an `ssh` row (the LAN hop's login, see the Network page bullet) holds a password and / or an unencrypted private key (`private_key`, checked with `russh::keys::decode_secret_key` and stored normalised in OpenSSH format; passphrase keys are refused) sealed together as JSON (`api::credentials::SshSecret`), and `secret_kinds` (`password` / `key` / both; empty = an older password-only row) says what is inside without unsealing; PATCH replaces the given part and an empty string removes it (one part must remain); the secret is AES-256-GCM-sealed with a key derived from `SECRET_KEY` (`telepy-vault-v1:`) and AAD `telepy-credential:{user}:{id}`, so a row moved to another user or id does not open. `desktop/start` takes `credential_id` instead of login/password/domain, refuses a different target (field error `credential_id`), touches `last_used_at` and names the login in `desktop_open`. Rows go with their tunnel / LAN host. Frontend: the desktop page's "Saved login" select + "Save this login" checkbox (`hooks/useSavedLogins.ts`; instances reload on the `telepy:saved-logins-changed` window event) and the preferences modal's Saved logins tab (`components/layout/SavedLogins.tsx`), copy under `vault.*` / `desktop.saved*`.
- **RustDesk in the browser (`rustdesk/` — `mod.rs` sessions + tickets + reaper, `codec.rs` pure framing; `api/rustdesk.rs`, `ws/rustdesk.rs`; test `tests/rustdesk_api.rs` with a fake RustDesk device on the SSH lab; design + measurements `docs/engineering/rustdesk-spike.md`, user flow in `docs/remote-desktop.md`):** the community TypeScript port of RustDesk's web client (AGPL-3.0, vendored as one prebuilt bundle in `src/frontend/public/vendor/rustdesk-web-core/` with its LICENSE / NOTICE / README recording the release and checksum — never edit the bundle, re-vendor) runs in the tab and Telepy **fakes hbbs and hbbr on one WebSocket** instead of running them: `POST /api/reverse/server/{id}/rustdesk/start` (same gate as desktop start: `desktop_enabled`, VIEW, step-up, `choose_username`, `desktop_max_sessions` counts guacd + RustDesk) runs `desktop::prepare` (pooled lease + `direct-tcpip` to the target's Direct IP port, default 21118) and returns a 60 s single-use ticket; the core connects to `/ws/rustdesk/{sid}/?ticket=` twice — the first binary message decides the role (`punch_hole_request` = id role → answered with a `relay_response` naming the same URL; `request_relay` = relay role → takes the prepared channel and re-frames WS messages ⇄ RustDesk's `BytesCodec` TCP framing, ≤ 16 MiB per frame). **The RustDesk password never reaches the backend** (the core answers the hash challenge in the browser). Presence kind `rustdesk`, events `rustdesk_open` / `rustdesk_close`, close codes 4404 / 4403 / 4013 (device closed) / 4014 (stopped: `POST /api/reverse/server/rustdesk/{sid}/stop`, reaper, idle) / 4400 / 4009. Frontend: `components/desktop/RustDeskViewer.tsx` (canvas from `onVideoFrame`, hidden textarea for IME, cursor from `cursor_data`, auto-continues the insecure-connection msgbox because the tunnel is encrypted; one viewer per page — the core is a window global) + pure `lib/rustdesk.ts` (`rustdesk.test.ts`: key-name table, mouse JSON, peer info, quality → `StreamStats`, msgbox / close-code classification); the desktop page's RustDesk mode has a password field and connects in the browser by default, the native-app path (probe + `ssh -L`) sits behind a disclosure; above it a **"Get that computer's RustDesk ready" checklist** (`components/desktop/RustDeskSetup.tsx`, pure `lib/rustdeskSetup.ts` + test): direct IP access on, a permanent password (not "Use one-time password" only), macOS Screen Recording / Accessibility, and the system service (advice only), each with a flat mock of the RustDesk / macOS screen using RustDesk's own labels; states come from an automatic probe per target (`autoProbe` in `useDesktopPage`), the last connect failure (`rdDirectIpOff` / `rdPassword` / `rdNoDisplay`) and `rdReady` (a session to this target connected); only the step to look at now shows its mock, and it folds to one row once ready; the Screen menu lists the peer's displays (`switch_display`) and RustDesk's own quality profiles; `DesktopFlow` has an `inBrowser` variant. Saved logins work here too (`protocol: rustdesk`, no login): the start takes `credential_id` and **returns the unsealed password** in `password` — the one exception to "the vault never returns a password", because only the browser core can answer RustDesk's challenge. The stats popover (`engine="rustdesk"`) hides frame round trip / frames behind and merges the monitor's tunnel RTT (`onRdStats`). Scope: screen, mouse / keyboard, clipboard text, display switching, quality, **sound** and **files** — no terminal (use the app). **Sound:** the core decodes RustDesk's Opus with WebCodecs; off = the peer option `disable-audio` set before login (the device never starts its audio service), switched live from the toolbar via the core's `option:toggle`; shared preference `desktop_display.audio`. What the device sends (RustDesk 1.5 source): Linux = the PulseAudio / PipeWire monitor, captured by the connection-manager process of the signed-in session (no session = no sound); Windows = WASAPI loopback of the default output; macOS Apple silicon = system sound via ScreenCaptureKit (Screen Recording permission); macOS Intel = only the "Audio input device" (microphone by default) — a loopback device such as BlackHole is needed. The checklist shows a "Sound from a Mac" advice step (`sound` in `lib/rustdeskSetup.ts`, `visibleSteps`) when sound is on and the last peer of this target was a Mac (`rdPlatform` in `useDesktopPage`). **Files panel (`components/desktop/RustDeskFiles.tsx`, pure `lib/rustdeskFiles.ts` + test):** RustDesk transfers files on a second connection, so `POST /api/reverse/server/rustdesk/{sid}/files` (owner of a connected screen session; 409 `not_connected`, 503 `file_transfer_disabled`) creates a child session (`rustdesk::Kind::Files`, `parent`; same target / account, own ticket and channel; no slot, no presence, no webhook; ≤ `MAX_FILES_PER_SCREEN` (2) per screen, the oldest goes — a reload or React's double effect overlaps two; ended with its parent via `end_children`). The panel runs a **second copy of the core in a hidden same-origin iframe** — inside one core only the top-most session gets video, so a files session there would freeze the picture — and drives the core's file API (`read_remote_dir` (asked once after login, "" = home), `send_files`, `select_files` + `send_local_files`, `confirm_override_file`, `cancel_job`; events `file_dir` / `job_*` / `update_folder_files` / `override_file_confirm` / `selected_files`). Pickers need the user's gesture, so the save picker opens in the page and its handle is swapped into the iframe's `showSaveFilePicker`, and uploads come from the page's own file input / drop (the iframe input's `click()` is patched to take them); browsers without a save picker buffer downloads in memory, hence ≤ 2 GB per file. **Folder / delete / rename ops (pure `lib/rustdeskFileOps.ts` + `lib/zipStream.ts`, tests; E2E recipe in `docs/remote-desktop.md`):** a folder downloads as one .zip built in the tab (client-zip, MIT, streaming + ZIP64): save picker inside the click → `read_dir_to_remove_recursive` (= `ReadAllFiles`; its `file_dir` answer carries the id, plain listings have id 0) → `ReadEmptyDirs`, which the core answers (`empty_dirs`) but cannot send, so the panel encodes it (`readEmptyDirsMessage`) and sends it on the iframe's tracked WebSocket (4 s timeout for older peers) → ask above 500 files / 2 GB (inline in the job row) → `send_files {is_dir: true}` with the iframe's `showDirectoryPicker` swapped for `zipDirectoryHandle` (each file the core writes streams into the zip; then `missingFiles` adds the 0-byte files the core never opens, plus empty folders) → piped into the picked file, or collected in memory (≤ 2 GB, refused up front). Delete: files `remove_file`; folders listed with hidden files, confirmed with the counted contents, then every file `remove_file` with the listing's id and `remove_all_empty_dirs` (RustDesk only removes emptied trees); multi-select. Rename / move = `rename_file` (the device joins `new_name` to the old parent, so `../x` or an absolute path moves it; `planRename`). New folder `create_dir`; folder upload (`webkitdirectory` or a dropped folder via `webkitGetAsEntry`, empty folders kept) creates the folders first. Each action waits for its id's `job_done` / `job_error` and shows the peer's message. Info button → `RustDeskFilesFlow.tsx` (browser's second core ─ relay ─ tunnel ─ device's RustDesk ─ disk, `rdFileSpots`, the four actions' state); the streams diagram's Files row lists download / upload / rename / delete with their state (`StreamRow.ops`, page state `fileActivity`). **Audit (`rustdesk/file_audit.rs`, pure, unit-tested; `codec::file_op` / `file_reply`):** the relay reads the files session's plaintext `file_action` / `file_response` and writes `rustdesk_file_delete` / `rustdesk_file_rename` gateway events (paths and counts, never content): a folder delete (listing → removes → remove_dir, same id) is one event once the folder step is answered, single files / renames when answered, leftovers when the session ends; tracking capped at 256 jobs. Site setting `desktop_file_transfer` (default on): off → no child sessions, `file_transfer: false` in the start response, the reaper ends open ones. **Login guard (`rustdesk::codec::LoginGuard`, unit-tested):** the only thing the relay parses is the browser → device peer `Message`'s top level — a `login_request` must be remote control on a screen session and file transfer on a files session, a `public_key` with content (encryption; Telepy's fake hbbs never hands out the device key, so only a modified client would), a `file_action` / `file_response` on a screen session (the core's file API only uses the file-transfer connection) and > 32 messages before a login are refused; refusals close 4403 and `rustdesk_close` says `refused: …`. Tests: `rustdesk_files_session_and_login_guard`, `rustdesk_file_operations_are_relayed_and_audited`.
