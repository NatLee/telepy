# OAuth 2.1 for MCP clients, the MCP server, agent sessions

- **OAuth 2.1 (MCP connectors, `oauth/` + `api/oauth.rs` + `db/oauth.rs` + `auth/mcp.rs`):** Telepy is its own authorization server. Discovery at `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource[/mcp]` (Traefik routes `/.well-known/oauth-*` to the backend); `POST /api/oauth/register` (RFC 7591, public); the authorization endpoint is the **frontend** page `/oauth/authorize`, which calls `GET/POST /api/oauth/authorize` with the web JWT (the web login lives in localStorage, so the backend cannot see it on a redirect); the page (`app/oauth/authorize/page.tsx` + `hooks/useOAuthConsent.ts`, blocks in `components/oauth/ConsentSections.tsx`) forwards the client's query verbatim, sends a logged-out user to **`/oauth/login?next=<this url>`** — not `/login` (`lib/oauthFlow.ts` `loginPathFor`; `safeNextPath()` in `useLoginPage.ts` only accepts same-origin paths; the 401 handler in `lib/auth.tsx` keeps a consent URL as `next`), shows the client name **and** `redirect_host` (registration is open, names are attacker-controlled), the signed-in account with "Not you? Switch account" (`logout(next)` → back to the same request on `/oauth/login`), earlier active grants of the same client (`existing`; "Replace the earlier connection" sends `replace: true`, and the token endpoint revokes those grants only after the new code is redeemed — `OAuthCode.replaces`), scopes with read-only / can-change chips, tunnels as All (incl. later ones) vs Only selected (search from 7, select shown / clear), a sticky decision bar with a summary, then `window.location.assign`s the returned `redirect_to` and **stays on a result view** (custom-scheme apps such as `cursor://` do not navigate away; the form must not come back); errors without `redirect_to` are shown without redirecting; a 403 `mfa_enrollment_required` renders `EnrollmentGate` and reloads after. **The OAuth sign-in page** (`app/oauth/login/page.tsx`, static so the first paint already looks different) is deliberately unlike `/login`: `AuthShell` with `ConnectAppAside` (app ─MCP→ Telepy ─SSH→ devices + steps sign in / choose / back to the app; `ConnectProgress` strip below `lg`) instead of the product highlights, the shared `components/auth/LoginForm.tsx` topped by `AppRequestCard` (name, return host, requested scopes) and a "Cancel and go back to <host>" button; it reads the public `GET /api/oauth/authorize/preview` (`hooks/useOAuthPreview.ts`: same validation as the consent data, returns `client`, `redirect_host`, `scopes`, `cancel_to` = the `access_denied` redirect — never account data), so a broken request is explained before any sign-in. Shared pieces live in `components/oauth/ConnectFlow.tsx` (`SCOPE_META`, `OAuthProblem`, `AppTile`, `ReturnsTo`); copy under `oauth.*`. `next.config.ts` sends `X-Frame-Options: DENY` + `frame-ancestors 'none'` for `/oauth/*`. **CLI sign-ins vs MCP apps:** `telepy login` registers anew as `telepy CLI (<host>)` on every sign-in, so its grants are ordinary OAuth grants; `oauth::cli_host` (pure, mirrored by `lib/cliClient.cliHost` / `lib/cliSignIns.isCliGrant`) tells them apart — labels only, the name is self-declared. Grant JSON carries `kind` (`cli` | `app`) + `cli_host`, CLI grants also `calls` (24 h / 7 d / errors / last, `db::api_calls::grant_summaries`, index on `grant_id`); the consent data's `existing` = the same app (`oauth::same_app`: same client, or the CLI on the same host) so re-running `telepy login` on a computer offers to replace its earlier sign-in, and `cli {host, signed_in, limit}`; at most `oauth::MAX_CLI_SIGNINS` (10) live CLI grants per person — creating one more revokes the least recently used (`cli_overflow`, pure; like GitHub's per-app token cap); test `cli_sign_ins_are_told_apart_replace_per_computer_and_are_capped` in `tests/oauth_api.rs`. The consent page speaks of the CLI when it asks (title, "not an AI app" callout, replace / limit notes, result view → `/tunnels/api?tab=cli`). Everywhere else the OAuth apps list is called **MCP apps** and leaves CLI grants out with a pointer to the API page (`ConnectedApps`, the AI activity page's Your MCP apps, the MCP reach dialog); `ConnectedAppDialog` opened on a CLI grant (from AI activity — `telepy exec` uses agent sessions) labels it as the CLI, hides MCP tool names and links its calls. Browser sign-in still follows the `mcp.connect` feature (the Access hint says so). MCP apps (`components/layout/ConnectedApps.tsx`; a row opens `ConnectedAppDialog` + `hooks/useConnectedApp.ts` = `GET /api/oauth/grants/{id}`: scopes → tools, tunnels, redirect URIs / hosts, open sessions, call totals and the last 20 tool calls, revoke; also opened from app names on the AI activity page for your own grants, admins any) appear in the preferences modal's Connected apps tab **and** on the **MCP page** (`/tunnels/mcp`, `hooks/useMcpPage.ts`; sidebar section "AI" next to AI activity): endpoint URL taken from the RFC 9728 `resource` (so it reflects `PUBLIC_URL`; falls back to origin + `/mcp`; dev proxies `/.well-known/*`), copy-ready setup per client, scope → tool table, session rules; the Settings page has an "AI access" tab (`?tab=ai`) with the `ai_*` site settings and the MCP endpoint; the **AI activity page** (`/tunnels/activity` = mine, `/tunnels/admin/activity` = everyone's, one `components/activity/AiActivityView.tsx` with `scope`; `hooks/useAiActivityPage.ts`) lists open AI sessions from `GET /api/ai/sessions` (close = `DELETE`), the audit log from `GET /api/ai/activity` (both `?scope=mine` by default — admins too: own + on tunnels I own — and `scope=all` admins only, 403 `admin_only`; tunnel filter, `?app=<grant>` → `grant_id`, the admin page also user (`?user=`, linked from Manage user); the personal page adds "Your connected apps" (show calls / details & revoke, API tokens, connect) and a whose-calls filter (my apps / others on my tunnels, pure `lib/aiActivity` `WhoFilter`); grouped by day like the Logs page, steps of 300 up to the backend's 1000; tool type / failed only / search client-side via `lib/aiActivity.ts`; commands and paths sit in `components/ui/clamped-text.tsx` — collapsed to 3 lines (errors 2) with "Show all N lines" and copy, newlines kept, long tokens wrap anywhere, because agents' commands run up to 2000 characters), and refreshes on the `AI-SESSION-OPENED` / `AI-SESSION-CLOSED` notifications; the tunnels page toasts those only when `by` is someone else (an agent on a tunnel you own). Tool and close-reason names are translated via `activity.tool.*` / `activity.reason.*` (tables in `lib/aiAccess.ts`, with the scope → tools list); `GET /api/ai/activity` also takes `grant_id`; `POST /api/oauth/token` (authorization_code + PKCE S256 only, refresh_token rotated on every use, compare-and-swap), `POST /api/oauth/revoke`, `GET /api/oauth/grants`, `GET/DELETE /api/oauth/grants/{id}` (Connected apps; admins may open / revoke anyone's), admins `GET /api/user/users/{id}/grants` (Settings → Users → Manage, tab "Connected apps" = `ConnectedApps userId`; its "AI activity" tab is `components/activity/UserActivity.tsx` over `/api/ai/activity?user_id=`, sharing `CallRow` and `lib/aiActivity.withTimes` with the AI activity page, which takes `?user=<id>` as its starting filter). Authorization codes live in memory (`tokens.rs`, 10 min, single use); grants in `telepy_oauth_grant` (refresh token SHA-256 only, optional tunnel restriction, scopes `tunnels:read` / `ssh:exec` / `ssh:files`). Access tokens are 1 h JWTs with `token_type: "mcp_access"` — not accepted by the REST extractor, and web tokens are not accepted by `auth::mcp::resolve`, which also re-checks the grant and the user on every request (revocation is immediate). Issuer = `PUBLIC_URL`, else derived from X-Forwarded-Proto/Host.
- **MCP server + AI sessions (`mcp/`, `ai/`, `api/ai.rs`, `db/ai_audit.rs`; user doc `docs/mcp.md`):** `POST /mcp` is rmcp's Streamable HTTP service in stateless mode (`legacy_session_mode = false`, JSON responses, `NeverSessionManager`, host check disabled because every request needs a bearer) behind `require_token`, which calls `auth::mcp::resolve` and answers 401 + `WWW-Authenticate: Bearer resource_metadata=…` (Traefik router `backend-mcp`, no compression; rmcp rejects requests without a `Host` header). The `McpPrincipal` reaches tools through `Extension<http::request::Parts>`. Tools: `list_tunnels`, `tunnel_status`, `ssh_session_open/exec/list/close`, `sftp_list/read/write`; scope checks return a tool error (`isError`) that tells the agent what to ask for. An AI session is one russh `DeviceConn` reused by every command (exec channel per command, ≤ 4 at once, no PTY), owned by (user, grant) — MCP 2026-07-28 has no transport sessions — and closed by the agent, the web (`DELETE /api/ai/sessions/{id}`: user, tunnel owner, admin), idle / max-lifetime (site settings `ai_session_idle_timeout` 600, `ai_session_max_lifetime` 7200, `ai_max_sessions_per_user` 3), device offline, grant revocation (immediately, from `revoke_grant_by_id`) or lost permission/username (reaper every 30 s, `ai::reap_once`). Opening/closing notifies the user and the tunnel owner (`AI-SESSION-OPENED` / `AI-SESSION-CLOSED`); every tool call is a `telepy_ai_audit_event` row (100k cap) served by `GET /api/ai/activity` (admins all; others own + own tunnels). Tests: `tests/mcp_api.rs` runs a fake device sshd (russh server: `sh -c` exec + local `sftp-server`).
- **Interactive shells + agent browsers over MCP (#107; `ai/shell.rs`, `ai/browser.rs`, `docker/kasm-browser/cdp.py`; tests `tests/mcp_api.rs` (fake sshd PTY echo shell + fake session-manager), `docker/kasm-browser/tests/test_cdp.py`):** `shell_open/send/read/resize/close` (scope `ssh:exec`): a PTY channel (`xterm-256color`) on the AI session's `DeviceConn`, ≤ 2 per session and counted against its 4-channel semaphore; a reader task feeds a `TerminalGuard` (the web terminal's vt100 `LineTracker`, + `screen_text()` / `cursor()`), the recorder and a 256 KiB unread buffer; `shell_read` = raw `output` since the last read + `screen` text + cursor, waiting ≤ 10 s. `AiShell::send` gates every Enter like the web terminal (`split` → `read_at` echo wait → `candidates` → `command_rules::check`): block → `\x03` + tool error, approve → `agent_approval` (45 s; still waiting leaves the line on the prompt and a later `""` + Enter reuses the approval), input after a stopped Enter is dropped (`unsent`). Shells close with the session (`session_closed`), on `shell_close`, or after the session's idle timeout (reaper); shell use touches the session. Audit rows `shell_*` (input only via `describe_input`, 200 chars); recorded tunnels record agent shells (`telepy_terminal_recording.kind = agent`, `Recorder::start_kind`); `/api/sessions` (kind ai) and `/api/ai/sessions` carry `shells`. `browser_open/navigate/read/screenshot/click/type/close` (new scope `browser:use`): `AiBrowser` wraps an ordinary `RemoteBrowser::start` session (same SOCKS, same kasm session, `remote_browser_max_sessions`) in `state.ai.browsers`, counted with SSH sessions in `ai_max_sessions_per_user`, same idle / lifetime / revocation / permission / device-offline reaper (+ `remote_browser.ping` keeps it alive and detects it gone), step-up refused, presence kind `browser` with client = app, `browser_open` / `browser_close` gateway events, `AI-SESSION-OPENED/CLOSED` + `mcp.session_*` webhooks with `kind: "browser"`; ending it from Live sessions closes it there (`ai::browser::close(.., by)`) and later tools say "ended by <user>" (`closed_reason`). Actions go backend → session-manager `POST /sessions/<id>/cdp` (X-Internal-Token, ≤ 30 s) → `cdp.py` (stdlib, own minimal WebSocket client) → Chromium's `--remote-debugging-port=<CDP_BASE 9300 + display>` on the container's loopback only; the backend never talks CDP. URLs pass `ai::browser::normalize_url` (http / https only — `file:` would read the container). Screenshots are MCP image blocks (≤ 1280 px), never stored; `browser_type` text is audited by length unless `sensitive: false`. Frontend: `lib/aiAccess.ts` (`SCOPES`, `TOOL_LABELS`, `REACH_BRANCHES` + pure `reachFor`, tested), the MCP page's "What can an app reach?" button → `components/mcp/AgentReachDialog.tsx` (app ─ Telepy ─ device ─ LAN / internet, branches lit by the picked connected app's scopes), `SCOPE_META['browser:use']` (can change), activity category `browser` + screenshot note, Live sessions "N shells" chip, Recordings "MCP agent" chip; copy under `mcp.reach.*`, `activity.tool.*`.
