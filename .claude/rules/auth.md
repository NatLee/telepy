# Sign-in — two-factor, single sign-on, web sessions, your devices

- **Two-factor sign-in (`mfa/`, `mfa/passkey.rs`, `api/mfa.rs`, `db/mfa.rs`; tests `tests/mfa_api.rs`):** an account has 2FA when it has an enabled TOTP or at least one passkey. `/api/auth/token` and `/api/auth/google/token` then answer `{mfa_required, mfa_token, methods}` instead of tokens (`api::mfa::complete_login`); `POST /api/auth/mfa/verify` finishes with `totp` / `recovery_code` / `passkey` (options from `/api/auth/mfa/passkey/options`). Passwordless: `POST /api/auth/passkey/options` (discoverable, `mediation: conditional`) → `POST /api/auth/passkey/login`. Management under `/api/auth/mfa*` and `/api/auth/passkeys*`; adding/removing a factor and regenerating recovery codes need a `reauth` proof once the account has any factor (`require_reauth`, 403 `code: reauth_required`), and so does approving an MCP app on the OAuth consent page. Admin reset: `DELETE /api/user/users/{id}/mfa`. TOTP = RFC 6238 SHA-1/6/30 s, ±1 step, last step stored (no replay, compare-and-set); the secret is AES-256-GCM-sealed with a key derived from `SECRET_KEY` (rotating it breaks existing TOTP — users fall back to passkeys / recovery codes / admin reset). Recovery codes: 10, SHA-256 only, issued with the first factor and cleared with the last. Lockout: 10 failures per user per 15 min (a success resets it), 5 tries per `mfa_token`, challenges and WebAuthn ceremonies live in memory for 5 min and are single use. Passkeys use `webauthn-rs` 0.5 (links OpenSSL; `libssl-dev` / `libssl3` in the Dockerfile), RP ID = host of `PUBLIC_URL` / forwarded headers (`localhost` allows any port; IP addresses are rejected because browsers refuse them); credentials are stored as the serialised `Passkey` with the counter updated on use. Error bodies are `{error, code}`. Frontend: `lib/webauthn.ts` converts the webauthn-rs JSON options to/from `navigator.credentials` (no library; registration asks for `residentKey: "preferred"` so autofill can find the passkey), `lib/mfa.ts` maps error codes to `security.*` keys, `hooks/useReauth.tsx` + `components/auth/ReauthDialog.tsx` are the promise-based "confirm it's you" step used by `components/layout/SecuritySettings.tsx` (the Security tab of the preferences modal) and the OAuth consent page, `RecoveryCodesDialog` shows codes once; the login page (`hooks/useLoginPage.ts`) handles `mfa_required`, the passkey button and conditional-UI autofill (`autocomplete="username webauthn"`, aborted before any modal passkey prompt); admins reset a user from Settings → Users → Manage. **Required factors:** two independent site switches `mfa_require_totp` / `mfa_require_passkey` (default off; an admin can only turn one on once their own account has that factor, 400 field error otherwise). While an account lacks a required factor (`api::mfa::enrollment_missing`, flags cached ≤ 5 s in `MfaStores.requirement`, invalidated on save) the `AuthUser` extractor answers 403 `{error, code: mfa_enrollment_required, missing}` everywhere except `mfa::allowed_while_enrolling` (profile, `/api/user/settings`, `/api/auth/mfa*`, `/api/auth/passkeys*`, `/api/auth/sign-ins`), WebSockets close with 4007 (notifications still connect), MCP tokens are `invalid_token`; logins still succeed. The profile carries `mfa_missing`, and `AppLayout` then shows `components/auth/EnrollmentGate.tsx` (explanation + `SecuritySettings` + sign-out, "Continue" once done so the recovery codes dialog survives); `apiFetch` refetches the profile on that 403.
- **Single sign-on — OIDC relying party (`oidc/` = `mod.rs` pure + unit tests, `client.rs`, `flow.rs`; `api/oidc.rs`, `db/oidc.rs`; test `tests/oidc.rs` against a fake provider on 127.0.0.1 (discovery, JWKS, token endpoint; the test "approves" by parsing the authorize URL); user doc `docs/sso.md`; frontend pure + tested `lib/sso.ts`, `components/settings/OidcProviders.tsx` + `hooks/useOidcProviders.ts`, `components/layout/SsoLinks.tsx`, `components/sso/` (`SsoResultView` = `/tunnels/sso`, `OidcFlow` info dialog); copy under `sso.*`):** providers in `telepy_oidc_provider` (slug `[a-z0-9-]{1,32}`, not `links` / `redeem` / `test-result`; issuer https, http only for loopback; client secret sealed with the vault, AAD `telepy-oidc-provider:<id>`, never returned — PATCH without it keeps it, `""` removes it = public client; `scopes` always with `openid`; `username_from` email | preferred_username; `allowed_domains`; `create_users` default on and **independent of `allow_registration`**; `link_by_email` default off; `enabled`). Links live in `social_account` with provider `oidc:<id>` (the id, so a renamed slug keeps them) + `unique_id` = `sub`; deleting a provider deletes its links. **Flow:** the button is a full navigation to `GET /api/auth/oidc/{slug}/start[?next=][&intent=]` → state / nonce / PKCE in memory (`Flows`, 10 min, capped) + an HttpOnly `telepy_oidc_<state[..16]>` cookie (Path `/api/auth/oidc`, SameSite Lax) → the provider → `GET /api/auth/oidc/{slug}/callback` (each provider its own path = mix-up defence; the pending sign-in must name the same slug and the cookie must match) → code exchange (`client_secret_basic`, else `client_id` in the form) → id_token verified (`ALGORITHMS` asymmetric only, iss = the discovery document's, aud, azp, exp/nbf with 60 s leeway, nonce; an unknown kid refetches the JWKS once; discovery + JWKS cached 1 h; the provider client follows no redirects) → `plan` (linked by sub → link by a verified email (`email_verified` true, the account not linked to another sub here) → create (username taken = refuse) → refuse; `allowed_domains` first, for every sign-in) → `complete_login(.., "sso", ..)` (Telepy's own 2FA still applies) → a one-time ticket bound to a new `telepy_oidc_t_…` cookie → `/login?sso=<ticket>[&next=]` → `POST /api/auth/oidc/redeem` (public, in `ssh_host_guard`'s list and `NO_REFRESH_PATHS`) answers the password sign-in's JSON. Failures navigate to `/login?sso_error=<code>&sso_provider=<slug>` (`lib/sso.SSO_ERROR_KEYS`). **Linking:** `POST /api/auth/oidc/links/{id} {reauth}` (reauth once the account has a factor) stores an intent bound to this browser (`telepy_oidc_i_…` cookie) and answers `{url}` to navigate to; the callback links it (`sso_linked_elsewhere` / `sso_already_linked`) and lands on `/tunnels/sso?linked=<slug>`; `DELETE …/links/{id} {reauth}` refuses the last way in (400 `last_sign_in_method`: no usable password, no passkey, no Google, no other link — `db::oidc::other_ways_in`, mirrored by `lib/sso.canUnlink`); `GET /api/auth/oidc/links` lists enabled + linked providers. **Admin** (superusers, 403 `admin_only`): `GET/POST /api/site/oidc`, `PATCH/DELETE /api/site/oidc/{id}` (field errors; `callback_url`, `links`, `has_secret`, `public_url_set`), `POST /api/site/oidc/discover {issuer}` (forced discovery + key count, `ok: false` + `error`), `POST /api/site/oidc/{id}/test` (an intent: works on a switched-off provider, signs nobody in) → `/tunnels/sso?test=<ticket>` → `POST /api/auth/oidc/test-result` (the admin who started it) = `{claims, would {action sign_in | link_by_email | create | refuse, username?, code?}}`. The public `GET /api/auth/sign-in-page` adds `sso [{slug, name}]` (enabled ones; `SignInLook.sso`, null = unknown, kept by `rememberSignInLook`), drawn by `LoginFormView` above the Google button (the preview too); `useLoginPage` redeems `?sso=` once (module set; React dev runs effects twice) and shows `?sso_error=`. Events `sso_provider` / `sso_link` (tunnel-less, admin Audit log); sign-ins are method `sso`. **Groups → roles (`oidc/roles.rs` pure + unit tests: `claim_groups` — the whole path as one claim name first, then dotted levels (`realm_access.roles`); arrays of strings / numbers or one string; missing / another type = None —, `allowed`, `desired`, `plan`; tests `provider_groups_become_admin_rights_and_user_groups` + `sso_rules_target_roles_and_groups_and_shares_follow` in `tests/oidc.rs`):** provider columns `groups_claim` (default `groups`, `check_claim_path`) and `required_groups` (JSON; "only these groups may sign in": no claim = `sso_no_groups`, none listed = `sso_group_not_allowed`, checked in `plan` after the domains), rules in `telepy_oidc_group_rule` (`idp_group` → `admin` | `group` + the id of a **role or an admin-kept group** — never a personal group: validation `known` = `db::features::sso_targets`, else a `group_rules` field error; ≤ 100, replaced whole by `group_rules` on create / PATCH, omitted = kept; rules and grant records of a deleted role or admin-kept group go with it, `db::oidc::forget_user_group` from `api/access.rs` and SCIM). Every sign-in through the provider runs `apply_roles` before `complete_login`: matched **exactly**; a token without the claim changes nothing unless the provider has granted this person something before (`roles::groups_or_none`: then the claim is set up and its absence means no groups — Keycloak and Entra ID leave it out for people in none — so its grants go; found against a real Keycloak); adds what the rules call for and records it in `telepy_oidc_grant`, but something the person already has (given by hand) is neither added nor recorded; takes away only recorded grants no longer called for (both kinds; `current` reads `sso_groups_of` = roles + admin-kept groups); the last active administrator is never demoted (`kept_last_admin`, record kept); then `features.invalidate()`, `group_shares::kick` when an admin-kept group was joined or left (access follows at once), an `sso_role` gateway event, and `access_recheck::kick` when something was taken away. Deleting a provider drops its rules and records; the memberships stay as ordinary ones. Admin JSON adds `groups_claim`, `required_groups`, `group_rules [{idp_group, target, group_id, group_name}]` (`group_name` = the role's name or the group's label), `scim_groups_as`, and the list's `user_groups` (roles `[{id, name}]`) + `share_groups` (admin-kept groups `[{id, name}]`); the test sign-in adds `groups_claim`, `groups` (null = no claim) and `would.roles {join, leave, admin: grant|revoke|keep_last|null}` (only with rules or records). `GET /api/access` marks `groups[].sso_members` / `share_groups[].sso_members [{user_id, provider}]` and `users[].sso_admin` — the access page shows a building icon / note (`access.viaSso` / `adminViaSso` / `ssoMembersHint`). Frontend: the provider dialog has side tabs connection / accounts / groups and roles (`FIELD_TAB` sends errors to their tab; rule rows = provider group → Administrator / user group; admin-rule warning), pure `lib/sso.ts` `groupLines` / `tidyRules` / `ruleValue`; copy under `sso.roles.*`. **Signing out at the provider (RP-Initiated Logout; test `signing_out_also_signs_out_at_the_provider_when_asked` in `tests/oidc.rs`, pure `oidc::end_session_url` unit-tested):** provider column `end_session` (default off; JSON `end_session` + `post_logout_url` = `<base>/login`, which the admin registers at the provider). Every SSO sign-in stores its provider and id_token for the new web session in `telepy_oidc_session` (sealed, AAD `telepy-oidc-session:<sid>`; with a second step `Flows::put_awaiting_mfa` holds it until `api::mfa::mfa_verify` calls `oidc::after_mfa`); `POST /api/auth/logout` looks it up before revoking and answers `end_session_url` (`end_session_endpoint` from discovery + `id_token_hint` + `post_logout_redirect_uri` + `client_id`; null when off, no endpoint, or not an SSO sign-in) and drops the record; `db::retention` purges records of sign-ins that are gone. Frontend: `revokeSession` returns the URL and `lib/auth.tsx` `endSignIn(next, atProvider)` opens it (waits ≤ 1.5 s) only for the person's own Sign out (`logout()` without `next`) — forced sign-outs (401, revoked elsewhere) and switching account on the consent page stay in Telepy; the dialog's connection tab has the switch, the redirect URI to copy and the discovery check's sign-out endpoint; copy under `sso.logout.*`. **SCIM provisioning (`scim/mod.rs` pure + unit tests: resources, Okta / Entra PatchOp dialects, `attr eq "v"` filters, paging; `scim/api.rs` = a plain axum `Router` merged in `app.rs`, deliberately outside the OpenAPI document; `db/scim.rs`; tests `scim_provisions_accounts_and_groups_that_sso_then_signs_in_to` + `scim_pushes_groups_or_roles_as_the_provider_says` in `tests/oidc.rs`):** `/api/scim/v2` (`Users`, `Groups`, `ServiceProviderConfig`, `ResourceTypes`, `Schemas`; `application/scim+json`; errors in the SCIM error schema with `scimType`) authenticates with a per-provider bearer `tps_…` (provider columns `scim_token` = SHA-256, `scim_token_prefix`, `scim_token_created`, `scim_last_used`; `POST /api/site/oidc/{id}/scim-token {reauth}` → `{token, prefix, base_url}` once, replacing stops the old one; `DELETE` = provisioning off, accounts stay; `scim_token` events). Users: username = `userName`'s local part through `oidc::clean_username`; an existing account of that name is never taken over (409 `uniqueness`) unless this provider made and deleted it (`telepy_scim_user.deleted` → re-adopted); name / email follow; `active: false` = `access_recheck::account_disabled` (last active admin kept, event says so), back on = `kick_device_keys`; DELETE = deactivate + mark deleted (204). Groups become **roles or admin-kept groups per the provider column `scim_groups_as`** (`role` default | `group`; provider JSON + POST/PATCH, another value = field error; existing mappings keep the row they point at) (description "Managed by <provider> (SCIM)", `telepy_scim_group`; `ScimGroupRow.purpose`); SCIM only touches rows it mapped (others 404; personal groups never); members replaced except people this provider doesn't manage; a name taken in the same namespace (roles among roles, groups among admin-kept groups) = 409; DELETE deletes the row (+ its SSO rules, grant records, group shares); a role change = `features.invalidate` + `end_denied_sessions`, a group change = `group_shares::kick` (`kick_with` on delete). `scim_user` / `scim_group` events. SSO's `plan` adds `Provisioned` (after the sub lookup, before link-by-email: an account this provider provisioned with the same email or username, `db::scim::provisioned_for`; test sign-in action `link_provisioned`). Admin JSON adds `scim {active, prefix, created_at, last_used_at, users, groups}` per provider and `scim_base`; the user list adds `provisioned_by`. Frontend: the provider dialog's fourth tab `components/settings/OidcScim.tsx` `ScimTab` (base URL, token state + create / replace / turn off with `useReauth`, the new token once, counts, what it does, Okta / Entra fields), list note, user list "via <provider>" + the Manage modal's hint; copy under `scim.*`.
- **Web sign-in sessions (`auth/sessions.rs`, `db/web_sessions.rs`; test `tests/web_sessions.rs`):** every login opens a `telepy_web_session` row and the refresh token carries its id (`sid`). `POST /api/auth/token/refresh` **rotates**: it returns a new `access_token` **and** `refresh_token` and slides the row's expiry, so people who keep using Telepy never get logged out; a replaced refresh token still works for `ROTATION_GRACE` (60 s: two tabs renewing at once, a lost response) and gets the *same* new token back; used later = someone else holds it → the whole session is revoked (`revoked_reason = reuse`). `POST /api/auth/logout {refresh}` revokes (public, no access token needed; always 200); a disabled account cannot renew (401 `signed_out: disabled`; disabling revokes every session with reason `disabled`, see **Access loss**); pre-upgrade tokens (no `sid`) get a session on their first renewal. Lifetimes are the site settings `signin_lifetime` (default 30 days, 5 min – 365 d; the whole sign-in, sliding) and `signin_access_lifetime` (default 1 h, 1 min – 24 h), read at issue time (`sessions::lifetimes`); the old `ACCESS_TOKEN_LIFETIME_MINUTES` / `REFRESH_TOKEN_LIFETIME_DAYS` env vars are gone. Expired / revoked rows are purged a day later by `db::retention`. Frontend: `lib/session.ts` (pure, tested: JWT `exp` / `iat`, the renewal lead = 2 min capped at half the lifetime, which 401s never renew), `lib/api.ts` `refreshSession({force})` = single flight + a Web Lock across tabs + re-reads localStorage after the lock (another tab may have renewed) and stores both tokens, outcome `ok | rejected | error`; `apiFetch` renews and retries **once** on a 401 (login endpoints and token-less requests excepted) and only a *rejected* renewal dispatches `api:unauthorized` (an unreachable server leaves the sign-in alone); `AuthProvider` renews in the background before expiry, at once when a tab becomes visible and is due, re-arms on `telepy:access-token` / `storage`, follows a sign-out from another tab, and calls `revokeSession` on logout. **The context's `accessToken` is not updated on background renewals** — the terminal / file-manager / remote-browser effects depend on it and would tear their sessions down — so anything that sends a token reads `localStorage` at send time (apiFetch, the sockets' auth frame; `RemoteBrowserPanel` uses `apiFetch`). Settings page: the **Sign-in** tab (`?tab=signin`, keys `signin_*` + `mfa_*`); seconds-based settings are edited with `DurationField` (number + seconds / minutes / hours / days, stored as seconds).
- **Your devices — list and sign out web sign-ins (`api/web_sessions.rs`, `auth/sessions.rs` `SessionGuard` / `revoke_sid` / `revoke_all`, `auth/devices.rs`; tests `tests/web_sessions.rs` + unit tests):** access tokens carry the session's `sid` too (`Jwt::access_in`; `Jwt::access` = no sid, tests / tools), and the rows keep `method` / `second_factor` (`token_pair(state, user, meta, method, second_factor)`). `GET /api/auth/sessions` → `{sessions [{id, ip, geo, user_agent, device, created_at, last_seen_at, expires_at, current, sign_in_method, mfa_method}], signin_lifetime, access_lifetime}` (`current` = the request's `sid`, via the `CurrentSession` extractor); `DELETE /api/auth/sessions/{id}` and `DELETE /api/auth/sessions?others=1` (without `others`: all, this one included) revoke with reason `user`; admins: `GET/DELETE /api/user/users/{id}/sessions[/{sid}]` (reason `admin`; an admin signing themselves out everywhere keeps the current browser). **A revocation bites at once:** `sessions::revoked` marks `state.sessions` (moka, 5 s TTL — another process sees a DB revocation within 5 s) so `session_from_access_token` (the `AuthUser` extractor and every WS auth frame) answers 401 `{code: token_not_valid, signed_out: <reason>}`, the refresh endpoint answers the same for `user` / `admin`, and `Hub::session_ended(sid)` closes that browser's sockets with **4010** (close reason = the reason): `ws::auth::first_message*` returns a `SessionWatch` (subscribe first, then re-check the cache) that every auth-frame socket selects on; desktop / RustDesk sessions remember the starting `web_session` and watch it too. Logout and refresh-token reuse go through the same path. `last_used_at` is written on every renewal and at most every 5 min on REST use (`note_use`, in the background). **New-device alert:** a successful sign-in whose country (GeoIP, from the stored IPs) or browser family (`auth::devices::ua_family`, the same table as `lib/userAgent.ts`) is absent from the account's successful sign-ins of the last 90 days (`is_new_device`, pure; an empty history never alerts, and the country only counts once the history has ever shown one — a history of internal addresses only, e.g. before `TRUSTED_PROXY_HOPS` was fixed or GeoIP installed, makes the first visible country no alert) sends `SIGN-IN-NEW-DEVICE {ip, geo, device, user_agent, method, second_factor, at}` to the user and the personal webhook `account.sign_in_new_device` (`sign_ins::record`). Frontend: `components/layout/SignInDevices.tsx` (Security tab above the sign-in history; admin Manage-user modal with `userId`): sessions grouped by browser + OS (`lib/webSessions.ts` `groupSessions`, pure + tested), "This browser" chip, IP + `IpPlace`, signed in / last active / ends, method, per-row sign-out (this browser = normal `logout()`), "Sign out everywhere else" under the list; the i button opens `SessionInfoDialog` (`SessionLifeDiagram.tsx`: sign in ─ this browser's sign-in, renews every N ─ N days unused ─ signed out, this browser's end, other browsers, and what sign-out cuts; data from `sessionDiagram`). `lib/api.ts` keeps the `signed_out` reason (`noteSignedOut` / `signedOut`), `ReconnectingSocket` turns 4010 into `api:unauthorized`, and `AuthProvider` then shows "signed out from another device / by an administrator"; terminals print `security.signedOutXterm`; `NewSignInNotice` (AppLayout) toasts the new-device notification. Copy under `security.devices.*`.
