# Device proxy

User doc: `docs/proxy.md`. This is **not** the declined "service → public URL" idea: it is an authenticated way *out* through a device, on the same path as everything else (the device's own sshd opens each connection), off by default.

- **Core (`proxy/mod.rs`; unit tests there; `tests/proxy_api.rs` on the SSH lab — a real device sshd and a TCP service reached through it):** a tunnel as a network proxy for OAuth apps and personal API tokens with the scope **`proxy:use`** (`oauth::SCOPES`, so tokens get it too; feature **`Feature::Proxy`** `proxy`; `Feature::for_scope`). `authorize(state, principal, tunnel, account)` runs every gate in order — site switch `proxy_enabled` (**default off**: an upgrade opens nothing; 403 `proxy_disabled`), scope (403 `token_scope`), feature (403 `feature_disabled`), tunnel by id or unique name inside the credential's tunnels and VIEW (404 `tunnel_not_found` for all three; 400 `tunnel_ambiguous`), step-up tunnels refused (403 `step_up_refused`), an allowed device account via `choose_username` (403 `no_account` / 400 `username`), device online (502 `device_offline`) — and returns the **proxy session** of that (credential, tunnel, account): created on first use with a transport `Lease` from the pool (502 `device_login_failed`), ≤ `MAX_SESSIONS_PER_CREDENTIAL` 8 per credential. `ProxySession::open(host, port, max)` takes a slot first (429 `proxy_busy` past `proxy_max_connections`, default 64, 1–1024), checks the host (`valid_host`: letters / digits / `. - _ :`, never a leading `-`; 400 `bad_target`), resolves names the device's way (`ssh::resolve` — a Mac's sshd dies on a name; 502 `resolve_failed`) and opens a direct-tcpip channel (502 `connect_failed`). `ProxyConn::relay` copies both ways until either side ends **or the session's `stop` watch fires**. A session closes when idle (`IDLE` 60 s with no connection), when ended by its person / the tunnel owner / an admin, or when `lost()` says so on the 10 s pass (`reap_once`: device connection gone or offline, switch off, credential revoked or expired, account disabled, feature off, tunnel deleted / step-up turned on / VIEW lost, account no longer allowed) — closing cuts every connection at once. Events on the tunnel: `proxy_open`, and `proxy_close` with `close_summary` (reason, connections, bytes each way via `human_bytes`, the first `MAX_TARGETS` 20 distinct `host:port` + "and N more"); hub `PROXY-SESSION-OPENED` / `PROXY-SESSION-CLOSED` to the person and the tunnel owner. Telepy never reads the bytes.
- **Ways in:** `GET /ws/proxy/?tunnel=<id|name>&host=&port=[&account=]` (`ws/proxy.rs`) — `Authorization: Bearer` with an OAuth access token or a `tpt_…` token (`auth::mcp::resolve_delegated`; a web JWT is a 401); **everything, including the device reaching the target, happens before the upgrade**, so a failure is a plain HTTP status with `{error, code}` and 101 means connected; then binary frames are the bytes (`ws::gateway::WsStream`). It rides the web port, so CDNs pass it (the SSH-over-WSS idea).
- **REST (`api/proxy.rs`; allow-list rows with `proxy:use`, tunnel = handler):** `GET /api/proxy/tunnels` → `{enabled, allowed, scope, max_connections, idle_seconds, endpoints {websocket, http_proxy}, tunnels [{id, name, online, accounts, default_account, blocked: step_up | no_account | offline | null}]}` (a token passes `check_allowed` first and sees only its tunnels; a web sign-in always gets an answer, with `enabled` / `allowed` saying why not); `GET /api/proxy/sessions[?scope=mine|all]` (a token: the ones it opened; web: own + on tunnels I own; `all` admins) and `DELETE /api/proxy/sessions/{id}` (404 `proxy_not_found` for anyone else).
- **CLI `telepy proxy [<tunnel>[@account]] [--port 8118] [--browser [url]]` (`src/cli/src/proxy.rs`: pure `parse_request` / `host_port` / `socks5_request` / `ws_url` / `refusal_parts` / `advice` / `http_error` / `banner` / `browser_args` + unit tests; e2e `proxy_reaches_the_devices_network_from_this_computer`):** without a tunnel it lists `/api/proxy/tunnels`; with one it listens on 127.0.0.1 and **one port speaks both HTTP proxy and SOCKS5** (first byte 0x05 = SOCKS). Each connection = one `/ws/proxy/` WebSocket (`telepy_carrier::connect_ws_bearer`, which returns `Ok(Err(Refused {status, body}))` for an HTTP refusal; `Api::bearer_now` renews an OAuth token in `spawn_blocking`). `CONNECT` answers 200 then relays; a plain `GET http://…` is rewritten to origin-form with the `Proxy-*` headers dropped and `Connection: close` added (one request per connection, so responses are never parsed). Refusals reach the client as an HTTP error / SOCKS code and are said once per kind in the terminal with what to do (`advice`); an unreachable target stays quiet. `--browser` starts Chrome / Chromium / Edge / Brave with `--proxy-server` and its own profile under the config dir. No SSH key, no root. This is the answer to "do we still need a server-side browser": for a person at their computer, no — `telepy proxy --browser`; the remote browser stays for computers nothing can be installed on, and `telepy browse` / MCP `browser_*` for scripted browsing.
- **Frontend:** the API page's **Proxy** tab (`?tab=proxy`, only with feature `proxy`; `components/api/ProxyPanel.tsx`, `hooks/useProxy.ts`, pure + tested `lib/proxy.ts`): the off / denied callouts, the path on `FlowPath` (your program ─ token with proxy:use ─ Telepy ─ tunnel ─ device ─ destination; `pathStates` stops it at the switch or at a blocked tunnel), the two ways in (the WebSocket URL; the standard proxy address when `endpoints.http_proxy` is set, else a note that the default is the WebSocket, the way SSH rides the web port, and that `telepy proxy` turns it into an ordinary proxy), examples filled with the picked tunnel (`cliExample`, `listExample`, `pythonExample`, `httpProxyExample`), and the open sessions with **End** (refetched on `PROXY-SESSION-*`, every 5 s while any is open). Site settings get a **Device proxy** tab (`proxy_` prefix in `lib/siteSettingsTabs.ts`). `proxy:use` is in `SCOPE_META` (can change), `TOKEN_SCOPES` / `CHANGING_SCOPES`, `aiAccess.SCOPES` (no MCP tools), `FEATURES` + `FEATURE_ICON`. Copy `proxy.*`, `oauth.scope.proxyUse*`, `access.f.proxy*`, `settings.groupProxy` / `proxyBanner`, `siteSettings.proxy_*`.
