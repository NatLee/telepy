# Sign-in page look — standard or discreet

- **Sign-in page look — standard or discreet (`api/auth.rs` `sign_in_page`, `api/site_settings.rs` `normalize_text`; test `tests/sign_in_page.rs`; frontend `hooks/useSignInLook.ts`, pure + tested `lib/signinLook.ts`, `components/auth/DiscreetShell.tsx` + `discreet.css`, `components/auth/SignInScreens.tsx`, `components/auth/SignInLookSettings.tsx`, `components/ui/preview-frame.tsx`):** site settings `signin_page_style` (`/login`), `signin_oauth_style` (`/oauth/login` for apps) and `signin_cli_style` (the same `/oauth/login` when `telepy login` asks — the client named `telepy CLI (<host>)`, `lib/cliClient.cliHost`; data migration `2026-10-28-cli-signin-style-from-oauth` started it from the OAuth one), each `standard` | `discreet` | `tapi` (`api::site_settings::SIGNIN_STYLES`), and `signin_consent_style` (the same three) for the **approval (consent) page** `/oauth/authorize` (apps and the CLI alike; default standard, no migration): `components/oauth/ConsentScreen.tsx` `ConsentFrame` (standard = `AuthShell` + `ConnectAppAside` / `ConnectProgress`; discreet = `DiscreetShell wide` — a 32rem card; the shell is `overflow-clip`, not hidden, so the sticky decision bar still follows the viewport) around `ConsentForm` (the same content in both: app, return host, account, earlier connections, scopes, tunnels, decision bar with `surface`), shared by the page and the settings preview (sample app, inert actions); `/oauth/login` picks the look with `pageForClient` and paints the empty frame until the preview says who is asking, only when the two styles differ (`needsClient`); for the CLI the standard look, the consent page's aside and the app tile speak of the terminal (terminal ─HTTPS─ Telepy ─SSH─ devices, back to the terminal, copy under `oauth.cli.*`), plus `signin_page_message` = the **typed lines**, one per line (≤ 6 lines × 80 characters, each trimmed, blank lines dropped — `normalize_text` / `lib/signinLook.ts` `messageLines` / `joinLines` / `messageProblem`; blank = three built-in greetings in the visitor's language), read by the public `GET /api/auth/sign-in-page` → `{style, oauth_style, cli_style, consent_style, message}` (no `cli_style` from an older backend = the OAuth one, no `consent_style` = standard). **`telepy login`'s done page (`/oauth/done`, `app/oauth/done/page.tsx`, `components/oauth/CliDone.tsx`; pure `lib/oauthFlow.parseCliDone`, tested):** the authorization-server metadata announces it as the Telepy extension `telepy_cli_done_page` (`oauth::CLI_DONE_PAGE`); the CLI (`src/cli/src/oauth.rs` + pure `signed_in.rs`) keeps the loopback request open, checks `state` and exchanges the code first, then answers **303** to `<page>?client_id=&result=ok|denied|failed[&reason=state|exchange|error]` — the page only understands those fixed words (never shows URL text) and follows `signin_consent_style`: standard = the CLI flow panel all done + the result, commands to try, what the grant may do (scopes / tunnels from `GET /api/oauth/grants` when this browser is signed in) and a CLI guide link; discreet = one card with the result. Without the metadata field (older server) the CLI serves its own self-contained page (`signed_in::fallback_page`: Telepy glyph, light / dark from the system, en / zh-TW / ja from Accept-Language, no scripts or external resources). Tests: `browser_sign_in_with_pkce_and_loopback` in `src/cli/tests/e2e.rs` (303 + `result=ok`, then a denial → `result=denied`). **Tapi look (`components/auth/TapiShell.tsx` + `tapi.css`, canvas painters `components/auth/tapiScenes.ts`, pure + tested `lib/tapiStage.ts`; result signals `lib/signInSignal.ts`):** Tapi next to the card in **a scene per page** (`sceneFor`): sign-in = `tea` (a cup of milk tea, pixel pearls rising), app connection = `mail` (paper planes with dashed trails bring the request, Tapi holds a letter), CLI sign-in and the CLI done page = `terminal` (always dark, characters drifting up, the bubble is a `tapi@telepy:~$` prompt line), approval = `desk` (grid paper, faint OK stamps / check marks landing away from the card (`stampAt` + `env.avoid` from `[data-tapi-solid]`), Tapi in **sunglasses centred on the face** — `SUNGLASSES` at column 6 so the frame's centre is column 12.5, between the eyes, as the user asked; lenses black with a white glint). One canvas per page (`runScene`: shared env, painter `setup` on size / theme, pixel-snapped, a mouse pushes things aside, a background click or a poke = the scene's surprise, stops off screen, one still frame under reduced motion). **Every scene has a ground along its lower edge** (`groundDepth` ≈ 9.5 % of the height, 44–128 px, less on phones) — with the header on top and nothing below, the page read top-heavy although Tapi is vertically centred: tea = pearls settled at the bottom of the cup (`pearlBed`, two staggered layers under a mound profile `bedHeight`, the front layer stirred by the mouse; rising pearls come out from behind it) over a tea that gets richer towards the bottom (`--tapi-tea-bottom`), mail = a drifting two-layer sea of pixel clouds (`cloudTops`, one seamless `CLOUD_PERIOD` loop pre-drawn once), terminal = tmux's status bar (`statusLine`, local time; only the clock when narrow), desk = none (grid paper already fills the page). A page taller than the window keeps its ground at the end of the page. The bubble types the admin's lines, else the scene's own three (`SCENE_LINES`, `tapiLook.<scene>.line1–3`; `signinLook.tapiLinesNote` says so), every possible text stacked invisibly so the size never changes; the pixel wordmark (`pixelGlyph`: 5 × 9 font, 3 × 3 cells, outline + shadow only outside the letter, proportional widths) sits below. Moods (`moodFor`, pure): a reaction > signing in > password (turned around = `backView`, startled when shown) > code > username (happy, a hop per character) > pointer on Tapi (waves) > asleep after 40 s > idle; the approval page adds flashes from DOM hooks — `data-tapi-scope="changes"` ticked = `careful`, `data-tapi-decision="approve"` = `stamp` (a big OK stamp lands beside Tapi) / `deny` = `bye`; the CLI done page passes `fixedMood` (`done` / `bye` / `oops`). Scene props via `sceneSprite` (envelope, sunglasses; none on the back view). The OAuth / CLI Tapi page keeps the standard card content (`AppRequestCard`), the approval page the full `ConsentForm` (wide card, Tapi sticky). Copy under `tapiLook.*`; the settings panel offers three looks on all four pages, the Tapi hint names each page's scene (`signinLook.tapiScene.<page>`), and the info table has a Tapi column. Discreet = only "Telepy" (letters rising), the lines and a background on **one `<canvas>`** (a sunflower / Fermat-spiral dot field from `sunflower()` with a ripple from the word, a wavefront ring and two orbits; maths pure + tested in `lib/discreetField.ts` — the old keyframe curves, pointer push, rings, `approach` easing, `backingRatio`; `runField` in `DiscreetShell.tsx` draws at real screen pixels incl. the preview iframe's scale (cap 2×), batches dots per opacity step, stops while off screen (IntersectionObserver), re-reads the colour tokens when `<html>` changes, and draws one still frame under reduced motion). It used to be one CSS animation per dot: ~860 composited layers per page (~1700 with both preview frames) and per-dot restyling on hover, which is what stuttered — keep it on the canvas, don't go back to per-dot DOM animations next to the shared `LoginForm`; the header (language / theme) is in the flow, so a tall form (the OAuth card with Google) never covers it, and the phone grid has an explicit `minmax(0,1fr)` column. **Typewriter (pure `lib/typewriter.ts` + `hooks/useTypewriter.ts`, tested):** one line = typed once and kept; two or more = typed, held, erased, the next one typed; graphemes via `Intl.Segmenter` (CJK one at a time, slower; a pause after punctuation; deterministic wobble), `reconcile` carries on from the shared start when lines / the pinned line change. Caret = a zero-advance inline-block in the primary colour (never wraps on its own or pushes centred text), solid while typing / erasing, blinking when idle, a kept single line blinks three times and fades; a just-typed trailing space becomes a no-break space; every line sits invisibly in the same grid cell so the height never changes; reduced motion = the whole line, no caret. **Pointer effects (mouse only, `(hover: hover) and (pointer: fine)`, not with reduced motion; in `runField`):** dots within 120 px are pushed aside and lit (the pointer is rotated into the spinning field's frame; push / heat / parallax follow with exponential easing, frame-rate independent), parallax on the field and both orbits, letters hop with their neighbours on hover (`.dsc-lift`, the outer `.dsc-char` keeps the hit area), the rule grows, and entering the word (`dsc-burst` event, ≤ every 1.2 s) sends a ring drawn on the canvas that lights and nudges the dots it passes. The settings editor (`components/auth/SignInLinesEditor.tsx`): built-in greetings (listed in the admin's language, "Start from these") or own lines as rows like a text editor (Enter splits at the caret, Backspace at the start joins, ↑↓ move between rows, a multi-line paste = one row each — pure `pasteRows` / `mergeUp` / `moveRow` / `removeRow`; per-row counter, move / remove), and the focused row is **pinned** in the preview (`pinnedLine`; `DiscreetShell` / both screens take `pin`) with a "Typing line N" chip; the OAuth variant keeps the app name, return host and cancel, its scopes wait for the consent page. **The static HTML must stay neutral for both looks:** the pages render `SignInPending` (empty surface) until the look is known (`useSignInLook`: re-asked whenever a sign-in page mounts, cached in localStorage `telepy.signinLook` so a returning browser paints the right look at once; an older backend / odd answer = standard), the OAuth login's Suspense fallback and the consent page while signed out are `SignInPending` too, and the root `metadata.description` is just "Telepy" — never put product copy into anything prerendered on `/`, `/login`, `/oauth/*`. Site settings → Sign-in has the panel (`SIGNIN_LOOK_KEYS` are left out of the generic list): standard / discreet toggles that save at once (and `rememberSignInLook` for this browser), the lines editor (Save / Discard), a live preview — `PreviewFrame` portals the real `SignInScreen` / `OAuthSignInScreen` with `LoginFormPreview` (the same `LoginFormView`, inert, no `useLoginPage`, drawn Google button) into same-origin iframes (1280 and 390 wide) whose head stylesheets, `<html>` attributes and body class mirror the page, so breakpoints follow the simulated screen; both screens are as tall as the tallest of the four pages at that width (≥ 800, rounded up to 20 — `previewHeight`), measured live by an invisible `PreviewSizer` (all four pages stacked in one grid cell of a zero-height off-screen iframe, so `min-h-screen` collapses; `useMeasuringPreview()` lets `DiscreetShell` skip its canvas and typing there), so switching pages never resizes the frames and nothing is cut off — and the "How it works" dialog (visitor ─ empty frame ─ the look in use ─ Telepy on `components/flow/PathFlow`, a standard vs discreet table, and what it does not hide: API paths, scripts, MCP discovery, the device port). Copy under `discreet.*` / `signinLook.*`.
