# Tunnels list and tunnel page (frontend)

- **Tunnels list data:** `GET /api/reverse/server/dashboard` returns `{tunnels, ports, latency}` in one round-trip; the list serializer uses a precomputed permission map + share counts (no per-row queries). Owner / ADMIN viewers also get `shared_with [{id, username, permission}]` (one query for all tunnels, sharing order, the permission in force; `null` for everyone else), which the "Shared with N" chip shows on hover / focus / tap (`components/tunnels/SharedWithChip.tsx`: up to 8 names, then "… and N more").
- **Tunnels list rows are dense (`components/tunnels/TunnelTableRow.tsx`, `components/tunnels/quiet.ts`):** the list view (≥1200px) is two lines per row — every column a primary line plus a quiet one (name + pin / labels + description truncated; status + latency / last seen + way in; port + OS / public + LAN IP + what needs attention; relation + sharing / who is using it) — because stacking every fact as its own chip made a row ~170px of grey boxes. The chip components (`TunnelEndpointChip`, `TunnelLanChip`, `DeviceOsChip`, `TransportBadge`, `DeviceWarningChip`, `DeviceNameChip`, `SshNameChip`, `TunnelAccessBadges`, `TunnelPresenceButton`, `TunnelLabels`) take `variant="text"` = `quiet(tone, …)` (icon + words, no border / background, warning / danger only as text colour); cards keep the default `chip`. Only the host-key alert stays a red chip (rare, must-see). The row's actions are the compact open buttons — labelled only from an `@[84rem]` table container (the wrapper div in `app/tunnels/page.tsx` is the `@container`), icons with `title` / `aria-label` below — and `TunnelActions variant="icon"` (a bare `…`). When adding a fact to the row, add it as quiet text on the matching line, never a new chip.
- **Tunnel page + quick-access menu (`/tunnels/<id>?tab=…`; `app/tunnels/[id]/page.tsx` → `components/tunnels/page/TunnelPageView.tsx` + `OverviewPanel` / `AccessPanel` / `SettingsPanel` / `IdentityPanel`; hooks `useTunnelPage` (the list's `GET /api/reverse/server/dashboard`, this tunnel picked, live status / latency / health / presence from the notifications like the list, other changes refetch; not visible = `missing`), `useTunnelDetails` (the basics / device-key form, reloads after a save), `useTunnelModals` + `useLeaveTunnel` (dialog state shared with the list); pure + tested `lib/tunnelPage.ts`: `TUNNEL_TABS`, `parseTunnelTab` (old dialog names `general` → settings, `connections` → history), `tunnelPageUrl`, `parseTunnelId`, `isTunnelPagePath` (the sidebar counts it under Tunnels), `attentionItems`):** replaced the old details dialog because the ⋯ menu had grown to 17 two-line items (~960 px). Tabs: overview (status, open buttons, needs attention → each item's tab, quick-access tiles that are real links) / connection (`ConnectionTab` + install scripts) / device (facts; hidden without `endpoint`) / identity (device key form + host key) / access (your permission + share end + request access, sharees, login accounts, device keys) / sessions (step-up, recording, detach, shell history) / history (uptime + connections, links to logs / live sessions / recordings / command-rule history) / settings (name, description, labels with their own Save; this tunnel's notification mute; leave / delete). Rail on the left only when the page is ≥ 56rem (`hooks/useWiderThan.ts`, shared with Server health; measure an element present in every render state). **A whole card / row opens the page** (`hooks/useRowLink.ts` over the pure, tested `lib/rowLink.ts`: a click on empty space / text opens it, a click on a control (`ROW_CONTROLS`: buttons, links, fields, menus, `[data-row-ignore]`), from a portal (popover content bubbles through React, not the DOM) or while selecting text is left alone, middle / Ctrl / ⌘ / Shift = new tab; the name stays a real `Link` for keyboard and the context menu, with a chevron after it; the card's button tray and the row's actions cell are `data-row-ignore`, the card's upper part tints on hover); chips open their tab (`onDetails(id, tab)` = `router.push(tunnelPageUrl(…))`). **Every block of a tab is a card** (`SectionPanels` around the tab panel — see UI building blocks) and the wide rail lists the current tab's cards **inside the current tab's box** (`NavTabs as="nav"` + `below={<SectionOutline/>}`: no visible heading, the line under the tab icon, the text aligned with the tab name, the tab's hint hidden meanwhile; scroll-spy via the pure, tested `lib/sectionOutline.activeSection`, a click scrolls there; nothing below two cards) — the user could not tell that the connection tab held two sections when they were plain headings. The way back is `PageHeader back` ("← All tunnels" above the title, never among the right-hand actions) and the header breadcrumb `Telepy › Tunnels › <name>` (`usePageCrumb`). **The ⋯ menu stays the quick way in** (the user asked for it explicitly): one line per item with the hint as a `title`, "Quick access" (port forwarding, SSH config, toolbox, device keys, LAN hosts, share / request access), "Tunnel page" as one row of five icon tiles (`tunnelPage.short.*`), move to group, leave / delete — 427 px in every language; the notification mute moved to the page's Settings. Copy under `tunnelPage.*`.
- **Tunnels list search (`lib/tunnelQuery.ts`, tests `tunnelQuery.test.ts` via `npm test` = `node --test`, Node strips the types; tsconfig has `allowImportingTsExtensions`):** Tailscale-style terms, ANDed: `status:online|degraded|offline|never|up|down`, `shared:in|out|no`, `port:N|A-B|>N|<N`, `lastseen:>3h|<1d|never` (connected = now), `ip:` prefix, `user:` (live presence), `warn:disk|memory|load|reboot|any` (device facts warnings), `key:a,b` = OR, leading `-` negates; other words match name / description / port / IP / users. Filter-looking terms with an unknown key or bad value are listed as ignored instead of becoming text. `components/tunnels/TunnelSearchBar.tsx` = input + "Filters" menu of clickable examples + sort (`name` / `status` = degraded first / `lastseen` / `port`, kept in localStorage `telepy.tunnelSort` via `hooks/useStoredChoice`), ANDed with the filter tiles. The result is paged after all of that (`Pagination`, 12 / 24 / 48 / 96 per page = `CARD_PAGE_SIZES`, so the 1–4 column card grid fills whole rows; localStorage `telepy.tunnelsPageSize`; back to page 1 when the query / tile / sort / grouping changes); in the grouped view each group pages on its own (`useSectionPages`), so every group header stays visible. Keep the parser pure and add a test for every new key.
