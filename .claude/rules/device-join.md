# Device side — scripts, one-command join, carriers, transport

- **Device-side scripts (`scripts/`, `templates/`):** rendered with Python `string.Template.safe_substitute` semantics (unknown `$names` survive, so shell variables in templates are fine). The Docker flavours use `jnovack/autossh` (env-driven, key mounted at `/id_rsa`, defaults to `~/.ssh/id_rsa`) and reach the device's sshd through `host.docker.internal` (`extra_hosts`/`--add-host host-gateway`, Docker 20.10+ / Docker Desktop); the compose one-liner needs `-f telepy-docker-compose.yml`. Scripts only ever *append* the service key to `authorized_keys`. **Every device script asks for `-R 0`** (`SSH_TUNNEL_PORT=0` in the Docker flavours, the join script too): the gateway identifies the tunnel by its key and assigns the number itself, so the number appears nowhere on the device. There is no public `alpine/autossh` image — don't bring it back. **Every script pins the gateway's host keys** (`ScriptContext.gateway_host_keys` from `Gateway::host_public_keys()`): the bash scripts write `~/.ssh/telepy_known_hosts` (the systemd flavour `/etc/ssh/telepy_known_hosts`) and use `StrictHostKeyChecking=yes` + `HostKeyAlias=telepy-<host>-<port>` (the same alias as the join script), PowerShell writes `%USERPROFILE%\.ssh\telepy_known_hosts`, the Docker flavours mount a host-keyed file at `/known_hosts` (jnovack/autossh pins when it exists; `SSH_STRICT_HOST_IP_CHECK=false`) — the compose comment tells the user to save it next to the file. Without gateway keys every script falls back to the old `StrictHostKeyChecking=no`. **The keepalive is decided by a handshake, like the join's** (`scripts::keepalive_probe_sh` for ssh / autossh / systemd, `KEEPALIVE_PROBE_PS` for PowerShell; tests `the_keepalive_is_decided_by_a_handshake` with a stub ssh, `the_powershell_keepalive_follows_the_same_rule` with `PWSH=<pwsh>`): a keyless handshake with `ServerAliveInterval` first; if it fails without being refused / unreachable / a host-key error and one without it completes, compat mode (`ServerAliveInterval 0` + `TCPKeepAlive yes`) — the second try uses no ssh timer (`timeout 30` when present; a 30 s job in PowerShell); user-level scripts pass `"${KEEPALIVE_ARGS[@]}"`, the systemd flavour rewrites its written unit with sed (`TELEPY_COMPAT`). Docker flavours keep the image's own ssh settings (nothing on the host can probe the container's ssh before it runs).
- **One-command device join (#14; `join/mod.rs`, `api/join.rs`, `templates/join_install.sh`; tests `tests/join_api.rs` on the SSH lab):** the web mints a ticket with `POST /api/reverse/join` (`{name?, key_list?}` → `{id, token, command, command_no_sudo, install_url, expires_at, phase}`; owner-only `GET/DELETE /api/reverse/join/{id}`; ≤ 10 open per user, 30 min). Tickets live in memory (`state.join`, token `tpj_…` stored as SHA-256, lost on restart). The device runs `curl -fsSL <base>/api/join/install.sh | sudo sh -s -- --token …` (base = `PUBLIC_URL`, else X-Forwarded-*): a POSIX script (everything inside `main()` so a truncated download does nothing; the only template key is `server_url`, and `$$` must never appear because `safe_substitute` turns it into `$`) that checks the local sshd with `ssh-keyscan`, creates `~/.ssh/telepy_tunnel_ed25519`, registers via public `POST /api/join/{token}` (single use; a failed registration releases the ticket; the same device key again = rejoin the same tunnel, someone else's key = 409; name = web name, else `--name`, else hostname with `-2`… suffixes since names are globally unique; the login account becomes the default username), appends the service key to `authorized_keys`, pins the gateway host keys (`Gateway::host_public_keys`) in `~/.ssh/telepy_known_hosts` with `HostKeyAlias=telepy-<host>-<port>` + `StrictHostKeyChecking=yes`, installs `telepy-tunnel-<id>` (root + systemd → system unit with `User=`; systemd --user + linger warning; macOS → LaunchDaemon/LaunchAgent; else a `nohup` loop + `@reboot` crontab), writes `~/.ssh/telepy-uninstall-<id>.sh`, and polls public `GET /api/join/{token}/status` until the backend's own test login (`ssh::device::connect`, 25 s) says `verified` or `failed` (with an explanation). Device-facing answers are `KEY=value` text (no jq). Phases waiting → registered → connected → verified | failed are pushed to the owner as `JOIN-UPDATED` and logged as `join` gateway events. Tested for real in Debian containers (root, non-root, rejoin, systemd, uninstall). **The script decides by what the device has, not by assumptions (user doc `docs/device-join.md`; test `tests/join_script.rs` runs the served script with a real `/bin/sh` against the lab):** shell (BusyBox ash included), HTTP tool (`curl` → `wget` → `uclient-fetch`; device endpoints take `?soft=1` = always 200 with a first line `STATUS=<code>`, and `POST /api/join/{token}` ignores Content-Type, because uclient-fetch has no `--header`, hides status codes and keeps no error body), SSH client identified by `-V` (`OpenSSH_` vs `Dropbear` — stock OpenWrt's `/usr/bin/ssh` *is* dbclient; OpenSSH verified with `-G` over the exact tunnel options, dbclient by `-o help` because it ignores unknown `-o` and exits 0; the dbclient service names `/usr/bin/dbclient` itself since `opkg install openssh-client` repoints `ssh`), key tool per client (`ssh-keygen` → `telepy_tunnel_ed25519`, `dropbearkey` → `telepy_tunnel_dropbear`; dbclient 2022.82 cannot read OpenSSH-format keys; `dropbearconvert` converts when present, else a new key = a new tunnel, said out loud), the SSH server by what listens (`/proc/net/tcp`: a Dropbear bound to the LAN only makes both the host-key check and `-R 0:<addr>:<port>` use that address) and its banner (`nc -w 3`, else `ssh -v`), the host key from candidates (root's `dropbearkey -y /etc/dropbear/*_host_key`, `/etc/ssh/ssh_host_*_key.pub`, `ssh-keyscan` **without `-T`**, OpenSSH loopback `accept-new`) each accepted only after a `StrictHostKeyChecking=yes` handshake with exactly that key (never "install openssh-server" when a server answers), `authorized_keys` asked of the server (OpenSSH → `sshd -T AuthorizedKeysFile`; `--authorized-keys` overrides), else **found by a login, never by distribution** (`find_auth_keys` / `auth_login_with`, after `--check`'s exit since it writes: a throwaway key — `ssh-keygen` for OpenSSH, `dropbearkey` for dbclient with a random `DROPBEAR_PASSWORD` and `HOME` in the temp dir so it never prompts or leaves a known_hosts — goes into each of `$AUTH_CANDIDATES` = the `locate::KNOWN_FILES` list in turn, a loopback login with only that key decides, the line is removed by an exact-count rewrite; a **control** login with the key in no file must fail first, because a passwordless root on a fresh OpenWrt lets anyone in; no tool = the usual place and Telepy's own login tells; verified on OpenWrt 21.02.7 / 22.03.7 rootfs: with a root password their Dropbear reads only `/etc/dropbear/authorized_keys` for root; test `the_join_finds_the_keys_file_the_server_reads_by_logging_in`); `DISTRO` is shown only — `uci` for the Dropbear port and `pidof dropbear` without a banner are capability checks, the service manager (procd `/etc/init.d/telepy-<id>` with `respawn 3600 10 0`, stdout/stderr → `logread`, `env HOME=`, `start` unless `running` — `restart` on a new service prints a misleading "Not found"; systemd; launchd; loop + crontab), and tmpfs under `--ssh-dir`. **Before the token is used** the public `GET /api/join/gateway` gives host / port / user / host keys and the script probes the gateway twice without a key (full KEX ends in `Permission denied`, no gateway event): with `ServerAliveInterval=30` and without — a timeout with and success without is openwrt/openwrt #12574 (fortify-headers `ppoll` time_t; big-endian ath79 like the GL-AR750S turns 30 s into 30 ns, which also empties `ssh-keyscan -T`) and switches to **compat mode** `ServerAliveInterval=0 -o TCPKeepAlive=yes` (`facts.compat = ["no_server_alive"]`, `--compat-no-server-alive` forces, `--no-compat` refuses; dbclient's `-K 30` is unaffected). `--check` = the whole preflight, no token. Registration sends `facts` (`join::parse_facts` allow-list: shell / os / arch / http / client / server / init / keepalive / key_format / authorized_keys / ssh_host / transport / carrier / compat) → ticket JSON, the `join` event line, `telepy_device_install.join_facts` (`GET …/device-install` → `join {facts, summary, at}`, shown in the tunnel page's How it connects tab with a compat callout). A lost registration answer is recovered through `GET /api/join/{token}/status` + `GET /api/join/{token}/config` (the same lines again; never a second POST). The served script ends with `# telepy-sha256: <hex>` (`join::with_checksum`) that it verifies when run from a file; the web also offers "Download, check, run" (`sh -n` first; wget variant for stock OpenWrt) and the `--check` commands (`lib/joinScript.ts`, tested). It writes an install record `~/.ssh/telepy-<id>.install` (what / where / as whom / `KNOWN_HOSTS_LINE=` for dbclient's `~/.ssh/known_hosts` — dbclient has no `UserKnownHostsFile`, matches by host name, and a trailing comment breaks the match; the uninstall and `remove_tunnel.sh` remove exactly those lines) and reports **five states** (files installed / starts at boot / process running / tunnel connected / login verified), "Done" only on verified. `remove_tunnel.sh` knows procd init scripts, the record and the dbclient lines. **Dropbear caps an exec command at 9000 bytes** (`MAX_CMD_LEN`): long POSIX scripts go through `ssh::exec::run_script` (`script_commands`: `printf` pieces ≤ `MAX_COMMAND` into `${TMPDIR:-/tmp}/telepy-script-<tag>.sh`, then run and removed) — the survey / delete scripts use it — and `device_keys::remote` falls back to exec (`cat`, `exec::upload_commands` pieces into a tmp file + `mv -f`; the view's `file` then shows the real path) when the sftp subsystem is missing or `sftp init` fails (Dropbear accepts the request, then dies without sftp-server). **Built-in client (`--client openssh|builtin|dbclient`; tests `without_any_ssh_client_the_join_uses_the_built_in_one` in `tests/join_script.rs` (a PATH without any ssh tool), `a_built_in_client_service_is_surveyed_renamed_switched_and_deleted` in `tests/device_install.rs`, `the_built_in_clients_command_line_is_recognised` in `tunnel_service.rs`, `plan::procd_tests`, `src/carrier/tests/e2e.rs`; user doc `docs/device-join.md` §1b):** the order is a real OpenSSH → the built-in client of `telepy-carrier` (when Telepy has one for the CPU: `builtin_client` fetches it with `fetch_carrier` in binary mode and needs `tunnel --help` to answer) → dbclient. With it: the key is `telepy_tunnel_ed25519` (ssh-keygen when present, else `telepy-carrier keygen`; `keygen -y` = the public line), host-key candidates are verified with `tunnel --probe --host-key '<key>'` and, without ssh-keyscan, read over loopback by the same probe, the gateway preflight is one `tunnel --probe --known-hosts <file> <way>` (no compat mode: its keepalive is its own timer), the binary is copied to `~/.ssh/telepy-<id>-ws.bin` and the service runs it directly — `tunnel --identity <key> --known-hosts <telepy-<id>.known_hosts> --user telepy --server <host>:<port> [--ws <url>] --no-proxy|--proxy <url> --forward 0:<sshd addr>:<port> --keepalive 30` (`--server` / `--ws` / both from `--via-web` / `--auto`); `facts.client` = `builtin (<carrier desc>)` (frontend chip "Built-in client", `lib/joinScript.builtinClient`), record `CLIENT=builtin (…)`, `facts.compat` empty. The device side recognises that command line like `ssh -R`: `remove_tunnel.sh` reads the key from `--identity`, the forward from `--forward` (`ANY_R_RE`), the port from `--server` / `--tcp` (`dial_ports`, so another server's is kept), the known_hosts from `--known-hosts`, quoted or not (procd / unit files quote every word); `plan::parse_ssh` → `SshSpec.builtin` (`Builtin {server, ws, proxy, known_hosts, keepalive}`; a `--probe` or a line without a key is no tunnel), so a builtin service is renamed / switched (`builtin_args`: same key and target, the new route's `--server` / `--ws`; the install script copies the running binary to the new `ws_bin` instead of downloading) and deleted. MIPS (no `telepy-carrier` target) still falls back to dbclient. **Known gap — pure dbclient devices wait for a russh fix (only where there is no built-in client, i.e. MIPS):** every Dropbear client sends a `first_kex_packet_follows` guess (its kex list starts with `kexguess2`) and modern ones (2024.84+, OpenWrt's 2022.82 backport) negotiate strict kex, so the real `KEX_ECDH_INIT` sits at sequence 2 and russh 0.64.1's strict-kex check drops the connection ("strict kex violated at sequence no. 2, message type: 30"); OpenSSH clients never guess. The ~20-line fix (shift the check by one after an ignored guess) is proposed upstream as Eugeny/russh#804 / PR #805 and was verified on the stock OpenWrt rootfs, but Telepy does not carry a patched russh; until then the script's gateway preflight (before any token) reports `closed` and tells the user to install the OpenSSH client (`--client openssh`). Verified for real: OpenWrt 23.05.5 rootfs (stock dbclient path with the patched gateway, incl. a container reboot; OpenSSH-client path), Alpine (ash + Dropbear + OpenSSH, loop + crond), and the two GL.iNet routers (`--check` on both; a full compat-mode join → verified → uninstall on the GL-AR750S, OpenSSH 8.9 + Dropbear 2022.82, OpenWrt 22.03). Windows stays "Step by step". **Frontend:** the create page (`/tunnels/create`) has a "One command (Linux / macOS / OpenWrt)" | "Step by step" switch (one command is the default; the choice is kept in localStorage `telepy.createMode` and read with `useSyncExternalStore`); `hooks/useDeviceJoin.ts` mints / cancels the ticket, polls `GET /api/reverse/join/{id}` every 2 s plus `JOIN-UPDATED`, and counts down `expires_at`; `components/tunnels/JoinPanel.tsx` shows the command (sudo / no-sudo × paste / download-check-run), the facts chips, `components/tunnels/JoinScriptFlow.tsx` (the script's seven steps on `FlowSteps`, lit by the phase through the pure `lib/joinScript.scriptProgress`), the four-step progress and the result, and drives the wizard's `SetupDiagram` (waiting = step 1, registered = 4, connected/verified = 5). Copy is under `join.*`.
- **Device platforms + way in (`lib/devicePlatforms.ts` + `lib/platformArt.ts`, pure + tested; `components/tunnels/DevicePlatform.tsx`, `SupportedDevices.tsx`; backend columns `telepy_tunnel_endpoint.transport` / `transport_tls` and the tunnel's `way_in`, tests in `tests/gateway_ws.rs` / `tests/tunnel_endpoint.rs` / `tests/join_api.rs`):** `PLATFORMS` = what can be added and how (one command: service / loop / untested / no; which wizard scripts; whether the web-port carrier works) — keep it in sync with `templates/join_install.sh` and the scripts. `platformOf(facts)` maps device facts (`os` / `kernel` / `cpu_model`) to linux / macos / raspberrypi / openwrt / windows / unix; `shortOs` makes the chip name. Each platform has an original 12 × 12 pixel icon (`PLATFORM_ART`, fixed colours on a fixed light tile in both themes). **Way in = how a tunnel was added + how it actually came in:** `authorized_keys_reverseserverauthorizedkeys.way_in` (`ssh` | `websocket` | `auto`, NULL = unknown) is set by the join register (the script's `facts.transport` = what it really installed, else the ticket's transport), by the device downloading a one-time script (websocket only when the carrier was rendered) — both overwrite, a rejoin / reinstall changes it — and filled by the gateway's first connection when still NULL (`db::tunnels::set_way_in` / `fill_way_in`); data migration `2026-10-30-tunnel-way-in` backfilled older tunnels from the earliest `accepted` event's `(over websocket)`, the endpoint's `transport`, and tunnels created before the web-port carrier (#189) = ssh. The gateway stores how the device last connected (`record_connected(…, transport, tls)`): `endpoint.transport` (`tcp` | `websocket`) plus `transport_tls` = the `/ws/gateway/` upgrade's `X-Forwarded-Proto` was https / wss (`ws::gateway::forwarded_tls`; `Transport::WebSocket { tls }`; label only). List items and the single retrieve carry `way_in {setup, last, live, tls}` (`serialize::way_in_json`) for **every viewer** (no address, unlike `endpoint`). A future switch of the way in should call `set_way_in`; `setup` ≠ `last` is shown as a difference, not an error, except for `auto` (either way matches; the tooltip says it is automatic). Frontend `wayInOf(tunnel, https)` → `{via: ssh | wss | ws, state: live | last | setup, setup: <via when it differs>, auto}` (unknown TLS = Telepy's own scheme; an older backend without `way_in` falls back to `endpoint.transport`), `liveTransport` feeds the SSH config dialogs' transport explainer. UI: `TransportBadge` ("SSH" / "SSH over WSS" / "SSH over WS"; solid while connected, dashed when offline (last time) or not connected yet (how it was set up), ⇄ when it came in another way than set up; a click opens a short note, also in the tunnel page's header) and `DeviceOsChip` (pixel icon + short OS name, opens the tunnel page's Device tab) on cards and rows; the create page's "Works on" row (`SupportedDevices`: chips that don't fit the chosen mode say which mode to use, a popover with one command / scripts / ways in / needs and a switch; one sideways row on phones); search `os:` (linux includes Raspberry Pi) and `via:ssh|wss` (`ws` / `http` / `websocket` / `web` = any web-port way, `matchesVia`). - **`telepy-carrier vpn-agent`** = the device-side helper of `telepy vpn --carrier` (see the CLI bullet), started over SSH only while that VPN runs.
- **Web-port carriers — the prebuilt binary first, python3 second (`src/carrier/` = `telepy-carrier`, `templates/telepy_ws.py` = the python3 twin with the same `[--tcp host:port] [--proxy URL | --no-proxy] <ws url>` arguments, `carriers.rs` = the server-side cache, `scripts::carrier_setup` / `carrier_case_sh`, `join_install.sh` `carrier_target` / `fetch_carrier` / `--carrier auto|binary|python`, `device_install::plan` install script; tests: `src/carrier/tests/e2e.rs`, `carriers::tests`, `scripts::tests::automatic_scripts_try_the_ssh_port_first`, `tests/gateway_ws.rs`, `tests/join_script.rs`, `tests/join_api.rs`):** a device that is set up for the web port (auto / websocket) needs a carrier as its ssh `ProxyCommand`; every install path (join script, the wizard's ssh / autossh / autossh-service scripts, the Device tab's transport switch) looks for one in the same order — (1) the prebuilt `telepy-carrier` for the device's `uname -s`/`-m` (`carriers::target_for`; x86_64 / aarch64 / armv7 / armv6 Linux musl, macOS, Windows), downloaded from **this server** at `GET /api/join/carrier/<target>` (public; `…/sha256` answers `SHA256` / `SIZE` / `FILE` / `VERSION` as KEY=value, `?soft=1` like the other device endpoints) and checked against that sha256 (`sha256sum` / `shasum` / `openssl`), then run once with `--version`; (2) `python3` + `telepy-ws.py`; (3) none = the SSH port only, said out loud ("installing python3 would enable the web-port fallback") — never an error for `auto`, an error for `--via-web`. The server fetches each platform's archive from `TELEPY_RELEASES_URL` (`<releases>/latest` redirect → tag, or `v<TELEPY_VERSION>` first on stamped builds; `SHA256SUMS.sig` checked against `release_key.rs` (or `TELEPY_RELEASE_KEYS` = `config.release_keys`), then `SHA256SUMS` verified, the binary extracted into `CARRIER_DIR/<target>/telepy-carrier` + `sha256` = `<hash> <tag>`) on the first request, remembers a failure 10 min (`RETRY_AFTER`); files placed by hand in `CARRIER_DIR/<target>/` are served as they are (no `sha256` file = computed, version null). Doctor check `carriers` lists each cached platform with its version. **Staying current (test `tests/carriers.rs` on a fake signed release + `carriers::tests`):** `carriers::run` (spawned in `main.rs`; first look after 2 min, then hourly) calls `auto_update_once`: only with the site setting `carrier_auto_update` (default on, Devices tab), only when something cached came from a release (nothing cached = no network at all), at most once per `CHECK_EVERY` (24 h, in memory) — it reads the latest tag and `update`s the copies whose version is older (`outdated`, pure; hand-placed and newer ones are never touched, never downgraded). `Carriers::update(wanted, trigger, by)` = the shared path (manual “everything” also fetches missing and replaces hand-placed ones); one at a time (`begin()` → 409 `busy`); `prefetch` = `telepy-server fetch-carriers` = update everything to the latest. `carriers::announce(state, run)`: gateway events `carriers_updated` / `carriers_update_failed` (admin Audit log), hub `CARRIERS-UPDATED {tag, targets, by}` / `CARRIERS-UPDATE-FAILED {tag, error}` to active superusers except the clicker (`components/health/CarrierNotice.tsx` toasts them), and the site-only webhook kinds `carriers.updated` / `carriers.update_failed` (group admin, `Kind::site()`); an automatic failure is announced once per distinct error (`first_time`), a manual run's failure only as an event. Admin API `api/carriers.rs`: `GET /api/site/carriers` (view: per target cached `{version, sha256, size, fetched_at}`, `update_available`, `failure`; `latest {tag, checked_at, error}`, `next_check_at`, `keys`, `last_run`, `auto_update`), `POST …/check`, `POST …/update {targets?}` (empty body = every platform; 400 for an unknown target) — superusers, 403 `admin_only`. Frontend: Server health → Companion services tab → `components/health/CarriersPanel.tsx` (`id="carriers"`; rows per platform with dot + state, Check now, Update all / per row, auto-update switch saving the site setting, last run, release page / trusted key / folder; info button → path diagram release page ─ signed SHA256SUMS ─ Telepy ─ download + sha256 ─ devices), `hooks/useCarriers.ts`, pure + tested `lib/carriers.ts`; copy under `carriers.*`. On the device the files are `telepy-<id>-ws.bin` or `-ws.py` plus the wrapper `telepy-<id>-ws.sh` (`exec <carrier> [--proxy …] [--tcp host:port] <ws url>`; the join bakes the install environment's `HTTPS_PROXY` into it because services have no environment); `remove_tunnel.sh` / the undo / `-ws.*` patterns cover `.bin`. The join reports `facts.carrier` = `binary <target>` | `python3` | `none` (chip "Web-port helper" on the join panel), the `.install` record `CARRIER=`, and a switch that ends up with no carrier reports `no_carrier` (was `no_python`). Both carriers honour an HTTP CONNECT proxy (`HTTPS_PROXY` / `https_proxy` / `ALL_PROXY`, `NO_PROXY` with curl's rule, `--proxy` / `--no-proxy`) for the SSH port and the web port alike. Reputation note: an unsigned fresh binary is likelier to be flagged by endpoint security than python3, which is why `--carrier python` exists and Windows devices stay on the SSH port (PowerShell scripts unchanged). The same binary is also the **built-in SSH client** (`telepy-carrier tunnel`): on a device without a usable ssh it runs the whole tunnel itself, see the built-in client paragraph of One-command device join; the wizard's ssh / autossh / systemd scripts stay OpenSSH-based.
- **Release signing (`release_key.rs`, shared with the CLI through `#[path]`; both crates alias the ssh-key crate as `crate::ssh_key`; tests `release_key::tests` (a fixed `ssh-keygen` vector, runs in both crates), `carriers::tests::carriers_come_only_from_a_release_signed_with_a_trusted_key` (fake release server), `src/cli/tests/update.rs` (signed fake releases via `ssh-keygen -Y sign`)):** the release job of `release-cli.yml` signs `SHA256SUMS` with the `RELEASE_SIGNING_KEY` secret (an OpenSSH ed25519 private key; `ssh-keygen -Y sign -n telepy-release` → `SHA256SUMS.sig`, OpenSSH's SSHSIG format; no secret = the job fails rather than publish unsigned) and every build job attests its archives (`actions/attest-build-provenance`, `gh attestation verify <file> --repo NatLee/telepy`). `release_key::RELEASE_KEYS` holds the public key lines (rotation = add a line); `verify_with(keys, message, sig_pem)` checks namespace + signature with `ssh_key::PublicKey::verify`; the backend's carrier fetch and `telepy update` refuse an unsigned or foreign-signed release (the old per-file `.sha256` fallback of `telepy update` is gone). `doctor`'s `carriers` line names the trusted keys. Users verify by hand with `ssh-keygen -Y verify -f allowed_signers -I telepy-release -n telepy-release -s SHA256SUMS.sig < SHA256SUMS` (docs/cli.md). Apple / Windows code signing is deliberately not done (needs paid certificates).
- **Automatic transport (`scripts::WsCarrier.tcp`, `api::join::parse_transport` = `ssh` (the API default) | `websocket` | `auto`; tests `the_automatic_carrier_*` in `tests/gateway_ws.rs`, `an_automatic_join_records_what_was_installed` in `tests/join_api.rs`, the `--check --auto` run in `tests/join_script.rs`, `automatic_scripts_try_the_ssh_port_first` in `scripts::tests`):** like Teleport's connection upgrade / Tailscale's DERP fallback, but per connection inside the ProxyCommand: the carrier connects to the SSH host's gateway port and counts it only once the `SSH-` banner arrives (a closed port, a firewall or a proxy that only carries web ports fails), else the `/ws/gateway/` WebSocket; a working WebSocket is remembered 30 min (`$TMPDIR/telepy-ws-<hash>-<uid>`) so a blocked port doesn't slow every reconnect, and the SSH port is retried after; stderr says which way. **Back to the SSH port** (test `the_carrier_returns_to_the_ssh_port_once_it_answers_again` in `src/carrier/tests/e2e.rs`, `the_python_carrier_returns_…` in `tests/gateway_ws.rs`): on the WebSocket both carriers (and the built-in client) retry the SSH port after `RETRY_SSH_PORT` = 10 / 20 / 40 / 80 / 160 / 320 s (`TELEPY_SSH_PORT_RETRY` = comma-separated seconds or `off`, for tests), banner required; once it answers they forget the WebSocket and end the connection (the built-in client disconnects cleanly and exits 1) so the service reconnects there — because after a backend restart OrbStack / Docker publish the SSH port ~9 s after Traefik already reaches the backend, and a device reconnecting in that gap stayed on WSS (through Cloudflare's SJC for HiNet: ~350 ms vs ~20 ms) until its next drop. No tries after ~10 min, so a connection in use is never cut later. Devices installed before this keep the old carrier until reinstalled / switched. Device scripts: ssh / autossh put it in a bash array (`PROXY_ARGS`, empty without any carrier = the SSH port only), the systemd flavour strips the ProxyCommand from the written unit when no carrier could be installed (`${unit_fixup}`), PowerShell / Docker render the SSH port (web-port-only is still refused there). Join: `--auto` (wrapper `telepy-<id>-ws.sh` with `--tcp`, also as dbclient's `-J`; no carrier = `VIA_WEB=0` with a note), `facts.transport` reports what was installed. Laptops: SSH config transport `auto` = the server stanza's `ProxyCommand python3 ~/.ssh/telepy-ws.py --tcp <ssh host>:<port> <ws url>` (still python3 there; `telepy ssh` uses the Rust carrier). Web defaults: the create wizard's Connect step and the one-command join start on **Automatic**, the SSH config dialogs keep the SSH port (laptops need python3 for the helper). Copy `wizard.connect.transportAuto*`, `join.transportAuto*`, `config.transportAuto`, `config.ti.auto*`, `platforms.via.auto`.
