# LAN discovery + jump hosts

- **LAN discovery + jump hosts (#20; `lan/`, `lan/scan.rs`, `api/lan.rs`, `db/lan.rs`; tests `tests/lan_api.rs` on the SSH lab):** agentless — the scan connects to the device (`ssh::device::connect`, its own connection, not the pool) and every probe is a `direct-tcpip` channel the **device's sshd** opens (needs `AllowTcpForwarding`). Steps: detect the device's IPv4 networks (`ip -o -4 addr` → `ifconfig` → PowerShell `Get-NetIPAddress`, virtual interfaces skipped, networks larger than /22 narrowed to the device's /24) or use the given private CIDRs (≤ 1024 addresses; never public ranges); probe the first port on every address (48 in flight, 1.5 s each, which also primes ARP); read the neighbour table (`ip neigh` / `arp -an` / `Get-NetNeighbor`) for live hosts without open ports; probe the other ports on live hosts only; read a banner on every open port (SSH is recognised on any port); names via `getent hosts`, then mDNS (`avahi-resolve -a`) for unnamed hosts and NetBIOS (`nmblookup -A`) for unnamed hosts with SMB open (best effort, skipped when the tool is missing; parsers `parse_avahi` / `parse_nmblookup`). Host JSON adds `vendor` from the MAC prefix (`oui.rs`: IEEE MA-L CSV in `OUI_DIR`, default `<DATA_DIR>/oui`, fetched by `telepy-server oui`, read at startup; none = no vendors) and `mac_private` (locally administered bit — randomized MACs have no vendor); the topology shows a short vendor tag (`shortVendor`), the host panel the full name, and the search matches it. Parsers are pure functions with unit tests (`lan/mod.rs`). Results upsert into `telepy_lan_host` (unique per tunnel + address; label / username / ssh_port / source are never overwritten by a scan; deleted with the tunnel). One scan per tunnel at a time (`LanScans`, in memory). Scanning needs owner or ADMIN plus the site switch `lan_scan_enabled`; VIEW sees hosts, EDIT edits them. Each scan writes a `lan_scan` gateway event (the tunnel's Logs) and sends `LAN-SCAN-PROGRESS` / `LAN-SCAN-DONE` to the scanner and `UPDATED-LAN-HOSTS` to the tunnel audience. API: `/api/reverse/server/{id}/lan/{hosts,scan}`, `/api/reverse/lan/topology`; MCP tools `lan_hosts` (`tunnels:read`) and `lan_scan` (new scope `network:scan`). Errors are `{error, code}`. **Web terminal to a LAN host:** the terminal auth frame may add `lan_host_id` (+ optional `lan_username`, default = the host's `username`); access is the device terminal's (VIEW + allowed device username, which is the jump account), the host must belong to the tunnel (else 4004), and the login must pass `ssh::process::valid_login` (`[A-Za-z0-9._-]{1,64}`, no leading `-`; else 4003; the API enforces the same rule on `username`). The first hop is a direct-tcpip channel the device's sshd opens on the pooled connection, exposed to OpenSSH as a one-shot `127.0.0.1:<ephemeral>` entry (`ssh::bridge::one_shot`: first connection only, 30 s); `lan_terminal_args` dials it with `HostKeyAlias=<host>` and allows publickey, keyboard-interactive and password, so prompts appear in the web terminal. **How that hop logs in is the user's choice** (`lan_auth` in the auth frame; `ssh::process::{LanAuth, prepare_lan_auth}`; test `lan_hop_logs_in_with_the_chosen_key` in `tests/lan_api.rs`): `telepy` (default) = this tunnel's own service key (unsealed from the vault, written to a 0600 temp file) plus the shared `SSH_IDENTITY` file, `IdentitiesOnly=yes`, password prompt as the fallback; `prompt` = `PubkeyAuthentication=no`, the password is typed in the terminal; `credential` + `lan_credential_id` = an `ssh` row of the credential vault (own, bound to this tunnel + host; else **4010**): its private key as a 0600 temp file and / or its password handed to OpenSSH through a one-line `SSH_ASKPASS` script (`SSH_ASKPASS_REQUIRE=force`, `NumberOfPasswordPrompts=1`) so it never crosses the PTY or the command line; the temp dir lives in `Shell._lan_auth` until the shell ends. The `lan_terminal` event names the choice (`with Telepy's key` / `password prompt` / `saved login '<label>'`).
