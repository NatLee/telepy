# Personal API tokens, the `telepy` CLI, the CLI page

- **Personal API tokens + the `telepy` CLI (`auth/api_tokens.rs`, `api/api_tokens.rs`, `db/api_tokens.rs`, `db/api_calls.rs` + `api_calls.rs` (call log), `api/browser.rs`, `auth/mcp.rs` `Credential`, `auth/extractor.rs` `Delegated`; crate `src/cli/`; tests `tests/api_tokens.rs`, `src/cli/tests/e2e.rs` (the built binary against the SSH lab, `#[path]`-including `backend-api/tests/common`), unit tests in both; user doc `docs/cli.md`):** `telepy_api_token` (name, `prefix` = first 10 chars of the secret, SHA-256 only, scopes, optional `tunnel_ids`, required `expires_at` ≤ 365 days, `last_used_at` / `last_used_ip`, `revoked_at`). Web sign-ins only (a delegated token gets 403 `token_route`): `POST /api/auth/tokens` (`reauth` once the account has a factor; the secret `tpt_…` is returned once; ≤ 50 live per person; feature `api.tokens`), `DELETE /api/auth/tokens/{id}`, `GET /api/auth/tokens/routes`; **readable with a token** (allow-list rows with no scope, like the profile): `GET /api/auth/tokens` and `GET /api/auth/tokens/calls` (own; `scope=all` still admin-only, a tunnel-limited token only gets its tunnels' names), admins `GET /api/user/users/{id}/tokens` + `DELETE …/tokens/{tid}`; create / revoke are tunnel-less `api_token` gateway events; revoke clears `state.api_tokens` (lookup cache ≤ 5 s) and closes the token's exec sessions; deleting a tunnel drops it from every token's list; dead rows go 30 days later with the OAuth cleanup. Scopes = the OAuth ones + `tunnels:manage` (tokens only). **Delegated tokens on REST:** the `AuthUser` extractor accepts a `tpt_…` token *and* an OAuth `mcp_access` token (the CLI's browser sign-in) through `auth::mcp::resolve_delegated` (PAT: live token + active user + enrolled + feature `api.tokens`; OAuth: as before + `mcp.connect`), then `api_tokens::rest_route` — a pure, tested **allow-list**, kept as the table `ROUTES` (`RouteRule {methods, pattern, scope, tunnel}`; pattern segments: literal, `a|b`, `{t}` = tunnel id, `*`; first match wins; unit test `every_allow_list_row_matches_an_openapi_operation` fails on a row whose route was renamed or removed) (method + path → scope + where the tunnel comes from: `Path(id)` checked by the extractor (404 outside the token's tunnels), `Handler` (handler checks), `Unrestricted` (403 `token_tunnels` for a limited token), `None`); anything else is 403 `token_route` (account, 2FA, tokens, site settings, keys…); a missing scope is 403 `token_scope` + `scope`; the route's feature (`features::for_route`) applies too; the `X-Telepy-Step-Up` header is dropped (step-up tunnels refuse tokens, like MCP). The extractor puts `Delegated(Some(Arc<McpPrincipal>))` in the request (a `Delegated` extractor after `AuthUser` reads it; web sign-ins = `None`): list handlers filter by the token's tunnels (dashboard / keys list, `/api/sessions`, `/api/recordings` + cast, `/api/ai/sessions`); the profile adds `credential {kind, name, scopes, tunnel_ids, expires_at}`. A middleware (`app::token_calls`) logs **every** delegated REST request (reads and refusals included) into the call log and writes a `token_call` gateway event ("alice via API token "ci": DELETE … → 200", tunnel from the route) after every delegated REST write that passed the checks, except `/api/ai/*`. **Call log (`telepy_api_call`; test `tests/api_token_calls.rs` + `browser_rest_api_with_tokens_and_web` in `tests/mcp_api.rs`):** one row per call (user, token_id | grant_id, client_name, kind rest | mcp, method, the route **template** from `MatchedPath` (never a query string), tunnel (only inside the token's restriction), status, duration, IP, error); `/mcp` logs a personal token's `tools/call`s in `require_token` (`MCP <tool>`, 200 / 400 when `isError`; pure `mcp::tool_call` / `tool_error`; OAuth apps' MCP calls are only in the AI audit). The request path only does `state.api_calls.record` (bounded channel, 10k; full = dropped + counted, `dropped()`); a background writer batch-inserts ≤ 500 rows / 1 s and adds to `telepy_api_token.call_count` (`flush()` for tests). Not hash-chained on purpose (high volume; a deleted user's rows must go, a chain only prunes from its head); 90 days + 200k rows (`db::retention`, trim in the writer). `GET /api/auth/tokens/calls?scope=mine|all&token_id=&grant_id=&user_id=&username=&status=ok|4xx|5xx|error&method=&limit=&before=` (`ViewScope`; `user_id` / `username` need `all`, an unknown username is a 400; tunnel names only for tunnels the viewer can see; `{calls, limit, has_more, dropped}`), and `GET /api/auth/tokens` adds `call_count` + `calls {calls_24h, calls_7d, errors_7d, last_call_at, last_status}` + `browsers`. **Endpoint catalogue:** `GET /api/auth/tokens/routes` → `{base_url, scopes, routes [{method, path, tag, summary, token, scope, tunnel: path|handler|unrestricted|none, feature}]}` — every operation of `app::openapi()` (cached) run through `matching_rule` / `features::for_route` on `sample_path` (params → `1`), so the page can't disagree with the server. **LAN hosts and scripted browsers are open to tokens:** `GET /api/reverse/lan/topology` (`tunnels:read`, filtered by the token's tunnels) and `POST/PATCH/DELETE …/lan/hosts*` (`tunnels:manage`, tunnel in the path, same EDIT rule as the web, feature `network`); `/api/browser/sessions*` (`api/browser.rs`, scope `browser:use`, feature `remote_browser` for opening and actions — listing / closing stay open): open `{tunnel_id, username?, url?}`, `navigate`, `text?selector=`, `screenshot` (image/png, `X-Telepy-Page-Url`), `click`, `type`, `DELETE`, list — the REST form of the MCP `browser_*` tools on the same `ai::browser` helpers (`open_at`, `lookup`, `run_action`, `audit_action`, `type_detail`), so limits, presence, live sessions, reaper and audit match; web sign-ins may call them too as `McpPrincipal::web` (`Credential::Web(user_id)`, client "Telepy web sign-in"); a browser belongs to the credential that opened it; step-up tunnels answer 403 `step_up_refused`; errors are `{error, code: browser_open_failed | browser_action_failed | browser_not_found | browser_closed}`. **MCP:** `/mcp` accepts PATs too (`resolve` = `resolve_delegated` + `mcp.connect` for tokens); `McpPrincipal.credential` / `AiSession.credential` / `AiBrowser.credential` = `Credential::Grant(id) | Token(id)` (sessions, shells, browsers are scoped to the credential; the reaper checks `Credential::is_live`); audit rows of a token carry `client_name = API token "<name>"` and `grant_id` NULL; command events store `token_id` (approval reuse per grant *or* token). **REST exec** (`POST /api/ai/sessions`, `POST /api/ai/sessions/{id}/exec`; delegated tokens only, 403 `token_required` otherwise; features `terminal`) share `mcp::open_session` / `mcp::exec_in_session` with the MCP tools (command rules, audit, reaper). **CLI** (`src/cli`, binary `telepy`, blocking reqwest + rustls, clap): `login <url>` (OAuth 2.1 + PKCE as a dynamically registered public client with a loopback redirect, `--scope`, default `tunnels:read ssh:exec ssh:files`; or `--token tpt_…`), `logout` (revokes the OAuth refresh token), `whoami`, `ls` (`--label`, `--group`, `--online`, `--json`), `status`, `ssh` / `scp` / `sftp` (writes `~/.ssh/telepy/<alias>.conf` from `/tunnels/server/config/{id}` with the ProxyCommand pointing back at it + `known_hosts-<server>`, then the system OpenSSH with `-F`; never touches `~/.ssh/config`), `config install` (the SSH config dialog's marked blocks in `~/.ssh/config`, same markers, backup, 0600), `exec` (one session per tunnel in parallel, `name | ` prefixes, `--wait-approval`), `cp` (SFTP REST), **`ssh` / `scp` / `sftp` reach Telepy through the web port by default** (`src/cli/src/carrier.rs`: the hidden `telepy _carrier --url <ws_url> --tcp <ssh host:port> --fallback … --server …` is the server hop's ProxyCommand in the generated file, tokio-tungstenite on rustls / ring, Ping → Pong, `ServerAliveInterval 30` on that hop; `TELEPY_WS_URL` overrides the URL), so Telepy records the real address that OrbStack's / Docker's port forwarding hides on the SSH port; `--via ssh` (`TELEPY_SSH_VIA`) = straight to the SSH port; when the web port fails it falls back only with consent — `--fallback ask|always|never` (`TELEPY_SSH_FALLBACK`), else the per-server `telepy config fallback` (`src/cli/src/prefs.rs`, `<config dir>/prefs.json`, default `ask`): ask = a `/dev/tty` / `CONIN$` prompt (y once / a always, saved / N), no terminal = no fallback with how to allow it; `doctor` shows it (tests: `src/cli/tests/e2e.rs` web by default + `--via ssh` + every fallback, unit tests in both modules), `ssh` passes `-N` / `-L` / `-R` / `-D` on as ssh spells them (`forward_args`), `rsync` (the system rsync with `-e 'ssh -F <generated config>'`, the remote side rewritten to the alias like `scp`; rsync's own options pass through, so telepy's go first and the key is `--identity` — rsync keeps `-i`; a user's `-e` / `--rsh`, `host::module` and `rsync://` are refused; pure `rsync_remotes` / `rsync_argv` skip the values of rsync options that take one; e2e `rsync_syncs_a_folder_through_telepy` runs a real `rsync --server` on a lab machine with `MachineOpts { shell: true, stream_exec: true }`, the lab's streaming exec), `vpn <target> [<network>…] [--dns-domain d] [--dns-server ip] [--carrier]` (`src/cli/src/vpn.rs` pure + unit-tested, `vpn_engine.rs` unix only; user doc `docs/cli.md` "A whole network (VPN)"; the web's Command sheet recipe `vpn` = the CLI example in every way, with `sheet.next.vpnTelepyOnly` outside the telepy way): routes networks behind a device to this computer until Ctrl+C. **It never touches the device's environment** (the user's rule): no exec, no shell, no file, no probe — every connection is a direct-tcpip the device's sshd opens for `ssh -D`, so sshuttle (Python on the device) was dropped on purpose; don't bring back anything that runs on the device. macOS / Linux (`tun-rs` + `ipstack`, both Apache-2.0): `ssh -D` on a free local port through the generated config, kept up by `keep_socks` (reconnects after `vpn::reconnect_delay` 1, 2, 4… ≤ 30 s; Ctrl-C / SIGTERM only set `VPN_STOP`, so telepy waits for the engine to undo its setup), then the privileged half `sudo telepy _vpn --socks … --owner <pid> --net … [--dns-domain …]` (hidden `Cmd::VpnHelper`, no sign-in; in-process when already root; stops on Ctrl-C / SIGTERM / SIGHUP or once `--owner` is gone) creates a TUN `198.18.0.1` ↔ `198.18.0.2`, adds routes (`ip route replace` / `route -n add -net … -interface`), and turns every TCP connection into a SOCKS5 CONNECT through the device's sshd. **Connect first, accept after** (`vpn::classify` / `tcp_syn` / `rst_for`, pure + tested, in the TUN reader): ipstack answers SYN+ACK the moment it sees a SYN, so every port looked open and programs that wait for the server to speak first hung; the reader holds a new SYN (resends while connecting are dropped), connects through SOCKS, and only then passes it to the stack (the upstream waits in `Conns.ready` for `accept`); a failure answers an RST ("connection refused" at once), SOCKS unreachable (reconnecting) drops it so the program resends. ipstack's `TcpConfig.timeout` (default 60 s) reset any connection quiet for a minute — set to 7 days (`IDLE`). UDP to port 53 of any server = DNS carried as TCP through the device (`dns_relay`); ping / other UDP / other protocols get ICMP type 3 code 13 from 198.18.0.2 (`icmp_prohibited`: ping prints "Packet filtered", UDP sockets get EHOSTUNREACH at once) and one note a minute (`Ctx::note`). `ssh -D`'s stderr is filtered (`vpn::ssh_stderr_line`): per-forward "open failed: connect failed" lines dropped, "administratively prohibited" = one AllowTcpForwarding hint. **`--carrier` (opt-in, the user's choice: only what is already on the device):** a second SSH session (`-T`, BatchMode) runs `telepy_carrier::agent::remote_command()` — a read-only `sh -c` that execs the first `~/.ssh/telepy-*-ws.bin` whose `--help` mentions `vpn-agent`, else prints `TELEPY-AGENT-NONE` — so `telepy-carrier vpn-agent` (`src/carrier/src/agent.rs`: framed protocol `[u32 len][u8 kind][body]` after the line `TELEPY-AGENT 1` — Hello / UdpOut / UdpIn / Close / Ping / Pong / Resolve / Resolved, pure encode / decode shared with the CLI; UDP sockets per flow (120 s idle), ping over an unprivileged ICMP datagram socket (`PONG_NOT_ALLOWED` = `net.ipv4.ping_group_range`), names via the device's getaddrinfo) lives only in that session: no files, no root, ends with stdin. The parent's `agent_bridge` listens on 127.0.0.1 with a 32-byte token in a 0600 file (`<config dir>/vpn-agent-<pid>.token`, removed at exit; root in-process gets it directly) and pumps the helper's connection ⇄ that ssh with plain read / write loops (`pump`) — **never `std::io::copy`**: on Linux it splices, and socket → pipe held each frame until the next one arrived (one ping reached the device only with the next). The engine's `Agent` (`run_agent` reconnects after 2 s; `NoCarrier` = say once and stop): pings → echo replies built here (`vpn::echo_reply`), any UDP → per-flow frames with replies from the original destination (`vpn::udp_packet`), fake-IP names resolved by the agent and connected by IP (also for a Mac device, so `--carrier` lifts the Mac refusal; `--no-sshd-names` keeps names away from a Mac's sshd when the agent is missing). Only carriers from this release on have `vpn-agent`; older ones answer NONE. - **`telepy vpn --all`, the same network on both sides, `--check` (`src/cli/src/vpn.rs` pure + unit-tested: `EVERYTHING`, `routed_nets`, `DefaultRoute` / `parse_default_route` / `default_route_command`, `bypass_add` / `bypass_del`, `v6_routes`, `reject_v6`, `config_hostnames`, `resolv_nameservers`, `host_routes`; `vpn_engine.rs` `Bypass`; `lib.rs` `vpn_cmd` / `vpn_check` / `socks_probe`; user doc `docs/cli.md` "A whole network (VPN)"; the sheet's vpn task has a `scope` choice network | all):** `--all` (= `0.0.0.0/0`, conflicts with networks) sends everything through the device so sites see its address. **Never touch the default route:** `routed_nets` turns /0 into `0.0.0.0/1` + `128.0.0.0/1`, which beat the default route and vanish with the TUN device (a crash can't leave the computer without a default route); connected networks are more specific and stay local. **The Telepy server keeps its own path** whenever the routed networks cover it (`swallows` now means "bypass", not "refuse" — also for a named network): the hosts = the API host + the directly dialled `HostName`s of the generated ssh config (`config_hostnames` skips stanzas with `ProxyJump` or an `ssh … -W` ProxyCommand: a device stanza's HostName is the tunnel alias, not a DNS name — found by running `--check` on a real tunnel) go to the root half as `--bypass <host>`; `Bypass::set_up` reads this computer's default route, resolves the hosts and adds one /32 per address **before** the VPN routes, a thread looks them up again every 30 s (a server behind a CDN changes addresses), and they are removed at exit. **IPv6 is refused, not ignored** (`--block-v6`, set by `--all`): the TUN device gets `fd00:7e1e::1/64` and `::/1` + `8000::/1`, and `reject_v6` answers a TCP segment with a RST and anything else with ICMPv6 type 1 code 1 (never ICMPv6 itself, multicast or a RST), so dual-stack sites fall back to IPv4 at once instead of leaving from the computer's own address; a failed IPv6 route says so. Names: a DNS server on this computer's own LAN stays local (not sent through the device); a public one is carried as TCP like any network. **Same network on both sides:** a default network (or, with `--all`, any known host) that falls inside a network this computer is on is not routed whole; `host_routes` routes the hosts Telepy knows there (the device's own `endpoint.lan` addresses + `GET …/lan/hosts`) as /32s (≤ `MAX_HOST_ROUTES` 64), skipping this computer's own addresses, its default gateway and its `/etc/resolv.conf` name servers, and the CLI lists what it routed, what it skipped and how to name another host. **`--check [--probe host:port]…`** needs no root: prints the plan (routed / host by host / kept on your own network / what is carried / names), then opens the real `ssh -D` and SOCKS-connects to the probes plus ≤ 5 scanned hosts with an open port inside the routed networks; exit 1 when one failed; ssh closing the SOCKS connection without a reply = "the device could not connect to it". The "Networks behind …" line now says the default is only what the device's own interfaces are on (a cloud device reaches other subnets through its router: the report that started this — hd-dev knows one /20 of its VPC). Verified in the container lab (`~/Library/Caches/telepy-vpnlab`: laptop / device / LAN host / an address-echo server on a third network; the echo and the LAN host answer with the peer address): one network, `--all` (echo sees the device, API still reachable, IPv6 refused in 3 ms, routes clean after Ctrl-C), a dummy interface on the device's subnet → host routes, `--check` ok / closed port; and against a real device from the dev Mac without root (`--check --all --probe`, and the exit address through `ssh -D` differs). **Not run:** the macOS TUN half of `--all` (no passwordless sudo on the dev Mac), the default-mode overlap message with a real `endpoint.lan`, the 30 s bypass refresh.
