# Deployment — environment variables, TLS, SSH host, env-backed settings

## Environment variables beyond the core list

**Many of these are optional overrides of Site settings → Server** (`server_settings.rs`, test `tests/settings_env.rs`): `TRUSTED_PROXY_HOPS`, `CLIENT_IP_HEADER`, `DEVICE_PROBE`, `KEEP_SHARED_SERVICE_KEY`, `GATEWAY_PROXY_PROTOCOL_FROM`, `LOG_LEVEL` / `DEBUG`, `OPENAPI_ENABLED`, `SOCIAL_GOOGLE_CLIENT_ID`, `PUBLIC_URL`, `SSH_SERVER_DOMAIN`. Precedence: a variable that is **set** (present, non-blank) wins and locks the field → else the saved site setting → else the built-in default (`Config::effective(key)` → `(value, Source::Env | Setting | Default)`; typed accessors `client_ip_hops()`, `public_base()`, `google_client()` …; read at use time, so a save needs no restart — log level through a `tracing_subscriber::reload` handle, OpenAPI by a per-request 404 layer, PROXY protocol per gateway connection, device probe per cycle). Keep compose passing them as `${VAR:-}` so an unset variable stays empty and doesn't lock anything. Only-in-.env (needed before start / read by Compose / shared with another container / secret): `SECRET_KEY`, `INTERNAL_API_TOKEN`, `WEB_SERVER_PORT`, `REVERSE_SERVER_SSH_PORT`, `SERVER_DOMAIN`, `PROJECT_NAME`, `GEOIP_DIR` / `OUI_DIR`.

- `TRUSTED_PROXY_HOPS` — which X-Forwarded-For entries are proxies: `auto` (default; every internal address at the right end — Traefik, an upstream Nginx Proxy Manager — is skipped, the first public one is the visitor) or a fixed count, Traefik included (`1` = Traefik only, `2` = plus an upstream TLS proxy / LB; needed when a proxy in front has a public IP); `CLIENT_IP_HEADER` — optional header to take the client IP from (e.g. `CF-Connecting-IP`)
- `CARRIER_DIR` (default `<DATA_DIR>/carriers`) / `TELEPY_RELEASES_URL` (default the GitHub releases page; a mirror for offline sites) — where the device carriers (`telepy-carrier` per platform) are cached and fetched from (`carriers.rs`); `TELEPY_RELEASE_KEYS` (public key lines, newline / `;` separated) replaces the built-in release public keys of `release_key.rs` for a mirror that re-signs releases
- `GEOIP_DIR` / `OUI_DIR` — offline GeoIP databases / IEEE vendor list, container paths (default `<DATA_DIR>/geoip` / `<DATA_DIR>/oui`; compose passes both, empty = default; `telepy-server geoip` / `oui` or the Server health panel download into them)
- `GATEWAY_PROXY_PROTOCOL_FROM` — IPs / CIDRs of an L4 proxy in front of the gateway that sends a PROXY protocol header (empty = off)

## Deployment notes

- **TLS / deployment:** prod sits behind an upstream TLS-terminating proxy that forwards `http` to Traefik `:80`; Traefik keeps the upstream `X-Forwarded-*` headers (`forwardedHeaders.insecure: true`), and the backend uses `X-Forwarded-Proto` / `X-Forwarded-Host` for the one-time script URL. If Traefik `:80` is reachable from untrusted networks, switch `insecure: true` → `trustedIPs`.
- **SSH host vs web host (`ssh_host.rs` pure verdicts + DNS lookup, `api/ssh_host.rs` `GET /api/site/ssh-host` superusers, `api::scripts::ssh_host`, doctor check `ssh_host`; tests `a_separate_ssh_host_*` / `ssh_server_domain_in_env_locks_the_field` in `tests/settings_env.rs`, unit tests in `scripts/mod.rs`, `ssh_host.rs`, `doctor.rs`; frontend `components/settings/SshHost.tsx` (`SshHostControl` + `SshHostDialog`), pure + tested `lib/sshHost.ts`; copy under `sshHost.*`):** `server_ssh_host` / `SSH_SERVER_DOMAIN` is the host every SSH client dials — device scripts (`ScriptContext.ssh_host`; templates' `$server_domain` is always it), the docker known_hosts lines (`[host]:port`), the laptop server block's `HostName`, the join's `GATEWAY_HOST`; empty = the web host (`server_domain`). **The identity stays the domain:** the server alias / `HostKeyAlias` `telepy-<domain>-<port>` and device-key aliases never change with it (the join gets it as `GATEWAY_ALIAS`), so existing configs are not taken for another server. Values: host name or IPv4 (`check_ssh_host` = `lib/sshHost.hostProblem`; `.env` may say `ssh://host:port/`, `strip_host`). The check resolves both names with the system resolver: an SSH host on Cloudflare's ranges = `ssh_proxied` (doctor ✗); only Cloudflare can be recognised — other proxies (CDNs, HTTP load balancers, tunnel services) look like any address, and the UI says so ("web proxy", Cloudflare named only when detected). Settings row = input + both names' lookups + verdict; "Why two names?" = web lane and SSH lane on `PathFlow` with switches (web name proxied? / SSH own name?). Installed devices keep the name they were set up with. **The SSH name must not serve the web** (`ssh_host::{request_host, web_host, arrives_on_ssh_host}` pure; `app::ssh_host_guard`; test `sign_ins_through_the_ssh_host_name_are_refused`): only when `PUBLIC_URL` is set, the SSH host is set and differs, and the request's `X-Forwarded-Host` / `Host` is the SSH host — never otherwise, so nobody is locked out — `POST /api/auth/{token,token/refresh,google/token,passkey/login,register}` answer 421 `{code: ssh_host, public_url}`; the public `GET /api/auth/sign-in-page` adds `web_host` / `ssh_host` / `public_url` and `components/auth/SshHostGate.tsx` (root layout, pure `lib/signinLook.onSshHost` = the same rule) replaces the page with the wrong-door scene — a pixel signpost (web ←, ssh →) with Tapi beside it, the 404 page's family, so it counts as an egg — + link to the same path at `PUBLIC_URL` (renders normally until the look is known, so prerendered HTML stays neutral); saving `server_ssh_host` refuses the name the admin is browsing on when PUBLIC_URL names another (400 field error, the lock-out case); the settings row probes `https://<ssh host>/api/auth/setup-status` from the browser and warns when that name serves the web (`sshHost.webOnSshHost`). This blocks mistakes, not a forged `Host`: lock the origin to the proxy for that. **A switch (#341) first resolves the SSH host on the server** and refuses `ssh_host_proxied` (a name on Cloudflare's ranges) before touching the device; a name the *server* cannot resolve is only logged (split DNS / `host.docker.internal` resolve on the devices' side) and the standby wait decides.
- **Env-backed site settings (Settings → Server, `?tab=server`; `server_settings.rs`, `api/site_settings.rs`; frontend `components/settings/ServerSettings.tsx`, `SettingRow.tsx`, `SettingSourceDialog.tsx`, pure + tested `lib/settingSource.ts`; tests `tests/settings_env.rs`, `settingSource.test.ts`):** keys `client_ip_hops` (auto / 0–10), `client_ip_header`, `client_ip_cloudflare` (`auto` default / `always` / `off`), `server_device_probe`, `server_keep_shared_service_key`, `server_gateway_proxy_protocol_from`, `server_log_level`, `server_openapi_enabled`, `server_google_client_id`, `server_public_url`, `server_ssh_host`; `lib/siteSettingsTabs.ts` sends `client_ip_` / `server_` to the Server group. `GET/POST /api/site/settings` (admins) add `env {key: {var, set, value}}`; saving a key whose variable is set = 400 `{key: ["Set by VAR in .env; …"]}`, nothing saved. The UI locks those fields ("Set by .env · VAR" chip + how to unlock), hints the variable on the others, and the info button opens `SettingSourceDialog`: `.env` ─ this page ─ built-in default ─▶ in effect with the deciding layer lit per key, a table of every env-backed key's source, and the only-in-.env list with reasons. **Cloudflare:** `CF-Connecting-IP` is used in `auto` only when the hop the chain would pick as the visitor is inside Cloudflare's published ranges (`server_settings::CLOUDFLARE_RANGES`, checked against cloudflare.com/ips-v4 + ips-v6 on 2026-10-30 — update both lists together), `always` = whenever present (spoofable unless only Cloudflare reaches the origin), `off` = never; the address check adds `cloudflare {mode, header, edge_seen, used}`, `sources` and `hints: ["cloudflare_masked"]` (header present but a proxy in front replaced Cloudflare's address — e.g. NPM in Docker). **Google client id at runtime:** the public `GET /api/auth/sign-in-page` answers `google_client_id` (effective value, "" = no Google sign-in); the sign-in / first-login pages and the preview read it through `useGoogleClientId()` (cached with the sign-in look) and fall back to the build-time `NEXT_PUBLIC_GOOGLE_CLIENT_ID` only when an older backend omits it.
