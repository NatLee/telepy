# Create wizard, SSH config dialog + editor, command sheet

- **Create wizard (`/tunnels/create`, `hooks/useCreateTunnelWizard.ts`, `components/tunnels/CreateWizardSteps/`, pure helpers in `lib/tunnelSetup.ts`):** five steps — Device (paste the device public key; private keys are rejected client-side, `/api/reverse/create/key/duplicate/{token}` runs before the create for friendly field errors; the tunnel is created on submit and step 1 is read-only afterwards, so Back never creates a second one) → Login accounts (target usernames) → Authorize Telepy (one append-only, idempotent `authorized_keys` command for Linux/macOS or PowerShell built by `authorizeKeysCommand`; service key always included, user keys optional) → Connect (six script kinds, one-time `curl | bash` URL from `/tunnels/server/script/one-time/token`, live status from `/ws/tunnel_connection/{id}/`) → Verify (a real login per account through the tunnel via `GET /api/sftp/shell/{id}/{username}`; `classifyLoginError` maps "device auth" → key not in authorized_keys, "connect to"/timeout → tunnel down). `SetupDiagram` (shared with the one-command `JoinPanel`, same props) is a network scene: the device inside a private network behind a router/firewall wall — inbound blocked (✗), outbound allowed (gate) — with the tunnel the device dials out to Telepy. **Straight lines and right angles only** (no curves): you, Telepy, the gap in the wall and the device share one row (one straight line — the path that works); the row below is "other devices" (anyone on the internet) running straight into the wall at a "LAN isolation" ✗ — the private network's isolation is presented as a feature Telepy keeps (no port opened), and the story / captions / step-1 why say so; flat design-language styling (neutral tiles, hatched grey wall, status-coloured hairlines, `Chip` / small square tags, no uppercase eyebrows). Landscape from a 600px container (below 760px it drops descriptions and the secondary tags), portrait below; lines and the wall in SVG (SMIL animations, gated by `hooks/useReducedMotion` because the global reduced-motion CSS does not stop SMIL), nodes and labels in HTML. Step 1 auto-plays a three-part story (blocked → device dials out → you come in through the tunnel); other steps show live state. **It must not crowd the form:** a one-row `SceneStrip` (icon + name, the tunnel line with a short hatched firewall bar, dot + text status — no boxes or stacked markers) is the default on phones and after the first focus on any form field (choice in localStorage `telepy.createScene`; "Show diagram" re-expands and pins it). Step 4's `DialInMonitor` (`components/tunnels/DialIn.tsx`) is the waiting view: radar + elapsed timer + a timeline from `/api/log/ssh/events?tunnel_id=` (accepted → forward → online, ids above a baseline only) and a troubleshooting list after 45 s; `DialInRadar` is reused by `JoinPanel`. `WizardStepper` cards show each finished step's summary and an Edit affordance; `review` in the hook marks finished steps that a later change invalidated (accounts added or keys changed since "I've run it" → step 3, device went offline → step 4, unverified accounts → step 5) with an amber badge and a jump list. `WhyPanel` explains each step. All copy is under `wizard.*`.

The install command merges known_hosts per alias (only this server's lines are replaced) and finally drops the old shared `telepy-ssh-server` block only when it is the first complete one saying `HostKeyAlias <this alias>` and no other non-comment line names it (two-pass awk / PowerShell regex / the CLI's `sshcfg::prune_legacy` — same rule; `lib/sshConfig.test.ts` runs sh always and real pwsh with `PWSH=<path>`). **Same device name from two Telepy servers:** before stripping, the command checks every alias it is about to write — a complete marked block of that name whose first ProxyCommand (last word) / ProxyJump goes through a different server alias belongs to another Telepy (through `telepy-ssh-server`: the shared block's `HostKeyAlias` decides, no such block = ours), so it is kept, our block is not written (`$telepy_skip` in sh, `$skip` in PowerShell, CLI `sshcfg::foreign_aliases` / `install_checked`) and the command says which names it kept; hand-written `Host` lines of those names outside Telepy's blocks get a note (`shadowed_aliases`). Renamed hosts under the old names stay in ~/.ssh/config until removed. `lib/sshConfig.ts` parses the backend `config` into stanzas and builds the commands: each stanza sits between `# >>> telepy <alias> >>>` / `# <<< telepy <alias> <<<`, the command backs up to `config.bak`, removes only complete marked blocks with the same aliases (an unterminated one is kept, never swallowed) and appends — re-running replaces instead of duplicating; the config is `chmod 600` (ssh refuses a group-writable one) and PowerShell writes UTF-8 without a BOM. The server stanza pins Telepy's host key: `GET /tunnels/server/config/{id}` returns `known_hosts` (`<alias> <type> <base64>` lines, empty without gateway keys) + `known_hosts_path` (`~/.ssh/telepy_known_hosts`); the install command saves that file first and the stanza carries `StrictHostKeyChecking yes` / `UserKnownHostsFile` / `HostKeyAlias`. **Device stanzas check the device's own host key the same way** (`scripts::DeviceHostKey`, test `tests/laptop_device_host_key.rs`): `UserKnownHostsFile ~/.ssh/telepy_known_hosts` + `HostKeyAlias <server alias>-device-<tunnel id>` (`scripts::device_key_alias`, survives renames), `StrictHostKeyChecking yes` once Telepy has pinned the device (`db::host_keys::pinned_lines`; the pinned lines are appended to the response's `known_hosts`, so the install command, the CLI and the by-hand step save them with the server's), `accept-new` before that (the laptop pins on its first connection, like Telepy; the per-alias merge keeps such a line until Telepy has its own) — otherwise whoever holds the tunnel key could point the tunnel at their own sshd and laptops would land there. After the owner trusts a new device key, laptops re-run the install command (`hostKey.accepted` says so). The lab's `generated_ssh_config` writes the file into the lab dir and patches the path — never the developer's `~/.ssh`. The command sheet's `SetupGuide` config step reuses `SshConfigInstall`. Change the marker format only together with a migration for blocks users already have. - **SSH config editor + simplifier (`lib/sshConfigTidy.ts` engine and `lib/sshConfigEdit.ts` edits, both pure and tested against the real `ssh -G` incl. random configs; page `/tunnels/ssh-config`, nav "SSH config editor" (`nav.sshTidy`); `hooks/useConfigEditor.ts`, `components/sshconfig/{HostsPanel,HostEditorDialog,IssuesPanel,TidyResultView,CliPanel,EffectList,TidyInfoDialog,TidyNameFlow}.tsx`; the CLI port `src/cli/src/tidy.rs` = `telepy config tidy`; copy under `tidy.*`):** rewrites a ~/.ssh/config so every name reads exactly the same, following OpenSSH's source (readconf.c / match.c / ssh.c): first value wins, except IdentityFile / CertificateFile / Local- / Remote- / DynamicForward / SendEnv, which add up in order; ProxyJump counts only while neither ProxyCommand nor ProxyJump is set; keyword aliases share one setting (`SLOT_ALIASES`); `Host` matches the name **as typed, case-sensitively** (ssh lowercases only after reading the config) with `*` / `?` and `!` turning a block off; `%h` in HostName = the typed name. Steps: drop a repeat of the same value (same block, or an earlier block that always applies to every name of a literal block); a different value that never applies is kept and reported (`shadowed`); move lines several **literal-only** blocks share into one `Host a b c` block placed after them — also as a *default*: a block that sets the option to something else is listed too, because it reads its own line first (one value per option per shared block, the most common; never for stacking options); `HostName <prefix><name><suffix>` becomes `<prefix>%h<suffix>`; identical blocks merge; Host lines split at 1000 characters. Every candidate is verified per name against the original (only literal names can change, so that is complete) and nothing crosses a `Match` / `Include` wall; a final whole-file check runs with every Match skipped and with every Match applied, and on any difference the original is returned (`failed`). Wildcards (`web-*`, `*.lab`) are opt-in, only when every name is still listed by another block and no other name / overlapping pattern in the file would match (`globsIntersect`); the widening is reported. Unknown / ignored keywords are notes. Everything runs in the browser; the pasted text is never stored. **Telepy's own blocks:** a device block (marker + `ProxyCommand ssh -W … <server alias>`) is only grouped with devices of the same server, keeps its markers, ProxyCommand and HostKeyAlias (the same-name detection reads ProxyCommand), and shared lines go into `# >>> telepy shared <server alias> >>>` (two words, so older commands never touch it). The bulk SSH config dialog's "Layout" (Compact = default, `telepy.sshConfigLayout`) writes that form (`compactMarked`, `installCommand(…, {compact, server, blocks})`); **every install / remove command (sh awk, PowerShell, CLI `sshcfg::release_shared`) takes the names it writes or removes off this server's shared blocks' Host lines and drops a shared block left with no name** — in place, never moved (moving it past the user's own later blocks would change what they read); the same-name skip also filters shared Host lines; shared blocks are not "hand-written Host" for the warning. Tests: `sshConfig.test.ts` (compact install = same `ssh -G`, idempotent, single re-install / removal release names; PowerShell variants need `PWSH`), `installing_releases_names_from_the_shared_block` in the CLI.
  **The editor page:** a sticky toolbar (paste / example / undo / redo / download / copy / clear), the text on the left and tabs on the right (Hosts / Worth a look / Simplify / Command line, `?tab=`), each column its own height (`--pane`) so a long config never stretches the page; on phones the config is a tab and host rows read like `user@host:port`. Undo = a snapshot before every whole-text change (form, fix, use simplified, paste). **Hosts** = `hostTable` (what each name uses + the line / block it comes from, own vs inherited, plus "any other name"), search then pages. **Form** (`applyHostDraft`): set / clear / stacked lists / rename / delete / add; a value always lands in the host's own `Host <it>` block where ssh reads it first (`setOption`: edit its own line in place, else an own block before the current source, else a new `Host <it>` right before that source; the global section can't be overridden → `global`); only single-value options (paths, names) get quoted; rename pins values that would read differently (`%h`, wildcards) unless told not to; Telepy hosts can't be renamed; every change previews `effectChanges` (which name's which setting, before → after). **Fixes** (`fixesFor` / `applyFix`): shadowed → make it apply (move the line with its Host line above the earliest block overriding it; same-block → drop the earlier line) or remove; unknown → remove or add to a top-of-file `IgnoreUnknown`; ignored / invalid → remove. **CLI:** `telepy config tidy [--check] [--wildcards] [--yes] [--file]` runs before sign-in, prints changes / notes / a diff (kept lines never reorder, so no LCS), asks unless `--yes`, writes `<file>.bak` first; `--check` exits 1 when it could be simpler or has notes. `src/cli/tests/tidy_cases.json` (102 cases incl. 40 random) is written by the web test (`UPDATE_TIDY_CASES=1 npm test`) and checked byte for byte by `tests/tidy_cases.rs` — change both engines together.
