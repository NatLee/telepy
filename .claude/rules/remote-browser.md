# Remote browser panel

Design and internals are in `docs/remote-browser.md`; scripted browsers (MCP `browser_*`, `/api/browser/sessions*`) are in `mcp.md` and `cli.md`; LAN web pages and the dock's browser tab are in `lan.md`.

- **The device's own ports ("On this device"; `api/remote_browser.rs` `device_ports`, pure `lan/device_self.rs` `browse_ports` + `NOT_WEB_PORTS`; tests `browse_ports_put_web_pages_first_and_never_offer_ssh`, step 0 of `a_scan_lists_the_devices_own_services_its_gateway_and_what_changed` in `tests/lan_api.rs`; frontend pure + tested `lib/devicePorts.ts`, `hooks/useDevicePorts.ts`, `components/tunnels/DevicePorts.tsx`):** `GET /api/reverse/server/{id}/remote-browser/ports?username=` (VIEW + step-up + an allowed account, feature `remote_browser`, token scope `browser:use` with the tunnel in the path) runs the scan's `LISTEN_POSIX` (then `LISTEN_WINDOWS`) **once, as the person's own account** over `pool.session_channel` — nothing is probed, nothing is stored, and it works without scan rights because it shows no more than `ss` in their terminal would. `browse_ports` keeps the ports reachable on localhost (`local_ports`) and classifies each: `seen` (the stored `source = self` row's services say http / https — its scheme and title win), `no` (the scan saw another protocol, or the port is in `NOT_WEB_PORTS`), `usual` (`lan/web.rs` table), `maybe` (anything else, tried over http); web first, by port. URLs are always `localhost` (the browser connects from the device). Answer `{tunnel_id, username, listed, scanned, ports [{port, web, scheme, url, title, proto, loopback_only}]}`; errors `{error, code: no_account | username | device_offline | ports_failed}`. Same data: MCP `browser_ports` (audited, refuses step-up tunnels) and `telepy browse ports <tunnel>[@account]` (`port_rows`). The panel asks only while it is on screen (`visible` — the terminal page keeps it mounted behind the terminal) and not in the Network dock (`bare`). **One step diagram links the screens** (`components/tunnels/BrowserStartPath.tsx`, pure `startTarget` in `lib/browserStart.ts`): three stations in a 3-column grid — ① open a proxy (SSH as …) ─ ② start Chromium (runs on Telepy) ─ ③ show the picture (VNC) — every number right above its icon, half-lines on the icons' centre line that turn green once the station before is done, names `text-xs` below a 24rem container (`@sm:text-sm`, balanced wrapping, never wider than the column), and one centred line below: what opens (`startedUrl`: `:port` + name from the ports list, a LAN URL, a new tab; on the start screen "a new tab, or a port below") + the queue (`queuedCount`). Grey on the start screen; the same diagram in the starting card lit from the step events. Measured 360–1024 px × 100/130 % × 3 languages, idle and starting (no overflow, no overlapping text). The "Start right away" card stacks centred below a 28rem container (a phone held upright). after a failure it stays on the start screen stopped on that step, with the full `ProgressSteps` list and **Try again** (same page) under it. Header: nothing while stopped, **Ports** + **Cancel** while starting, **Ports** + **IME** + **Stop** once connected. **Pinch zoom on phones (no trap)** (`lib/pageZoom.ts` pure + tested, `hooks/useVisualZoom.ts`): noVNC's gesture handler `preventDefault`s every touch on the canvas, so a page zoomed until the screen fills the display could never zoom back. While busy and `visualViewport.scale ≥ 1.02` the screen div gets `pointer-events: none` (`data-zoomed`), and a portal bar at the visual viewport's top (`zoomBarStyle`: offset + width × scale, `scale(1/scale)`, so normal size at any zoom) explains it with **Reset zoom** (`resetPageZoom`, async → whether the page is really back at 1×: `cappedViewport` = initial-scale and maximum-scale 1, the meta re-inserted so Safari re-reads it, held until scale < 1.02 or 1.5 s, then the original content). On false (iPhone Safari ignored it in real use, 2026-11-26) the bar switches to `browser.zoom.pinchOut` and drops the button — pinching out always works because the screen isn't taking touches. There is no standard API to undo a user's zoom, so never promise the button works. Note: Chrome honours react-resizable-panels' `touch-action: pan-y` on the terminal page, so pinching inside the panel does nothing there; iOS Safari forces pinch zoom, which is how people got in. Headless can't pinch inside the panel either — test with `Emulation.setPageScaleFactor` (verified: bar, touches pass through, reset back to 1×, canvas takes touches again at 1×). **Start screen = two ways to start, either one:** the path, then a **Start right away** card (always a new tab: clears `nextUrlRef`), an "or" rule, and `DevicePorts` titled **Start from a page on this device** (a click = `nextUrlRef` + start; no path diagram there, the steps already draw it). While starting / running the same component sits in the header's **Ports** popover (40rem; title "On this device" + the browser ─SSH─ device path; a click = `openTab`, queued while starting). **Layout for many ports:** a left rail of kinds with counts (`groupPorts` / `PORT_GROUPS`: seen / usual / maybe / no = no URL; a `NativeSelect` below the `@lg` container width), tiles of the shown kind (`shownGroup`: the chosen kind, else the first non-empty — follows a search) in a **fixed-height grid**: always 4 rows of 3rem, two columns (8 per page) when the component is ≥ 32rem (`useWide`, measured in rem so it follows the display scale, same line as `@lg`), else one column (4); empty cells stay empty, the compact pager row always takes its line, and the kind's hint (not web / never scanned) sits under the rail when wide and behind an ⓘ popover beside the select when narrow — so switching kinds or pages never changes the height (measured: every kind × 3 languages × 360–1440 px × 100/130 %). A tile = `:port` (+ lock, + **Device only** for loopback-only) over one line of name or `localhost:<port>/`, truncated with the full name in the tooltip. Search over every kind once there are more than 10 ports (`matchPort`: number substring or name). Keep kind labels short enough for the phone select (ja was shortened for that). Port names: the scan's title → its protocol → `lib/lanConnect.serviceName` (never "HTTP" for a web port). Copy under `browser.ports.*`.
