# Remote browser panel

Design and internals are in `docs/remote-browser.md`; scripted browsers (MCP `browser_*`, `/api/browser/sessions*`) are in `mcp.md` and `cli.md`; LAN web pages and the dock's browser tab are in `lan.md`.

- **The device's own ports ("On this device"; `api/remote_browser.rs` `device_ports`, pure `lan/device_self.rs` `browse_ports` + `NOT_WEB_PORTS`; tests `browse_ports_put_web_pages_first_and_never_offer_ssh`, step 0 of `a_scan_lists_the_devices_own_services_its_gateway_and_what_changed` in `tests/lan_api.rs`; frontend pure + tested `lib/devicePorts.ts`, `hooks/useDevicePorts.ts`, `components/tunnels/DevicePorts.tsx`):** `GET /api/reverse/server/{id}/remote-browser/ports?username=` (VIEW + step-up + an allowed account, feature `remote_browser`, token scope `browser:use` with the tunnel in the path) runs the scan's `LISTEN_POSIX` (then `LISTEN_WINDOWS`) **once, as the person's own account** over `pool.session_channel` — nothing is probed, nothing is stored, and it works without scan rights because it shows no more than `ss` in their terminal would. `browse_ports` keeps the ports reachable on localhost (`local_ports`) and classifies each: `seen` (the stored `source = self` row's services say http / https — its scheme and title win), `no` (the scan saw another protocol, or the port is in `NOT_WEB_PORTS`), `usual` (`lan/web.rs` table), `maybe` (anything else, tried over http); web first, by port. URLs are always `localhost` (the browser connects from the device). Answer `{tunnel_id, username, listed, scanned, ports [{port, web, scheme, url, title, proto, loopback_only}]}`; errors `{error, code: no_account | username | device_offline | ports_failed}`. Same data: MCP `browser_ports` (audited, refuses step-up tunnels) and `telepy browse ports <tunnel>[@account]` (`port_rows`). The panel asks only while it is on screen (`visible` — the terminal page keeps it mounted behind the terminal) and not in the Network dock (`bare`). **One step diagram links the screens** (`components/tunnels/BrowserStartPath.tsx`, pure `startTarget` in `lib/browserStart.ts`): three stations in a 3-column grid — ① open a proxy (SSH as …) ─ ② start Chromium (runs on Telepy) ─ ③ show the picture (VNC) — every number right above its icon, half-lines on the icons' centre line that turn green once the station before is done, names `text-xs` below a 24rem container (`@sm:text-sm`, balanced wrapping, never wider than the column), and one centred line below: what opens (`startedUrl`: `:port` + name from the ports list, a LAN URL, a new tab; on the start screen "a new tab, or a port below") + the queue (`queuedCount`). Grey on the start screen; the same diagram in the starting card lit from the step events. Measured 360–1024 px × 100/130 % × 3 languages, idle and starting (no overflow, no overlapping text). The "Start right away" card stacks centred below a 28rem container (a phone held upright). after a failure it stays on the start screen stopped on that step, with the full `ProgressSteps` list and **Try again** (same page) under it. Header: nothing while stopped, **Ports** + **Cancel** while starting, **Ports** + **IME** + **Stop** once connected. **Pointer mode + keyboard button on touch devices** (`lib/touchpad.ts` pure + tested state machine `padStep`, `hooks/useTouchpad.ts`; `pointer: coarse` only): noVNC's default touch handling clicks wherever a finger lands and its gesture handler needs 50 px of travel before a drag counts, and every tap focused the hidden input (= keyboard). Now on touch devices `rfb.focusOnClick = false`, connect blurs (setting `keyboard.enableIME` focuses by itself), `setIme` keeps focus only if already typing, and the header gets a **keyboard** toggle (`rfb.focus()` / `rfb.blur()`, `onPointerDown` preventDefault so it doesn't steal focus; pressed = the input has focus) and a **pointer / touch** toggle (`telepy.browserTouchMode`, default pointer — per device, kept in localStorage on purpose). Pointer mode catches raw `touch*` on the screen div in capture phase (`passive: false`, stopPropagation + preventDefault, so noVNC sees nothing): 8 px slop then 1:1 moves with flick gain up to 3× (`moveCursor`), tap ≤ 400 ms = left click at the cursor, hold 450 ms = left down (drag) until lift, two-finger tap = right, two-finger slide = wheel per 30 px (content follows fingers); sent with RFB's `_handleMouseMove` / `_handleMouseButton`, the cursor is noVNC's own fallback cursor moved with `_cursor.move` (remote shape, I-beam over fields); position kept as fractions of the canvas (`rfb._canvas`, not the first canvas in the DOM). The keyboard push uses the cursor's y in pointer mode. Header labels collapse to icons below `sm`; a one-time gesture hint (`telepy.browserPointerHintSeen`). Verified on the demo stack in phone emulation: a tap doesn't focus, a ~25 px nudge moves the cursor, a tap clicked Google's search box, the keyboard button + typing put "telepy" in it. **Phone keyboard: the remote keeps its size** (`lib/keyboardSteady.ts` pure + tested, `hooks/useKeyboardSteady.ts`, active only while connected, on `pointer: coarse` with focus in an editable element): noVNC asks the remote to resize on every window resize (500 ms later), so a keyboard that shrinks the page squashed the remote browser and a second resize followed on close; one that only covers the bottom (iOS, current Chrome) hid the field. Keyboard up = visual viewport height more than 120 px below the tallest seen at this width (`nextBaseline` / `isKeyboardOpen`). While up: `rfb.resizeSession = false` (the pending resize is never sent), the screen div is pinned to its pre-keyboard height and moved up with `translateY` so the last tap sits 56 px above the visible bottom (`keyboardShift`), `scaleViewport` re-applied; on close it slides back and `resizeSession` comes back 600 ms later (same size, no remote change). The frame (`frameRef`) is `overflow-hidden`. Changed imperatively, not through React, to beat noVNC's own resize handling. Verified on the demo stack in phone emulation: remote 570×867 unchanged through both keyboard kinds (layout shrink via `setViewportSize`, visual-only via a stubbed `VisualViewport.height`), screen height kept, tapped spot above the keyboard. **Pinch zoom on phones (no trap)** (`lib/pageZoom.ts` pure + tested, `hooks/useVisualZoom.ts`): noVNC's gesture handler `preventDefault`s every touch on the canvas, so a page zoomed until the screen fills the display could never zoom back. While busy and `visualViewport.scale ≥ 1.02` the screen div gets `pointer-events: none` (`data-zoomed`), and a portal **overlay** (`components/tunnels/ZoomOverlay.tsx`; `zoomCoverStyle` = the visible area at its normal size) dims it at 45 %: zoom % (`zoomPercent`), a minimap of the layout viewport with the visible box (`minimapRect`), a looping two-finger pinch-in (`animate-pinch-in`, `--pinch-from`), **Try to reset** (`resetPageZoom`, async → really back at 1×?: `cappedViewport`, meta re-inserted for Safari, held until < 1.02 or 1.5 s, then the original) and on false the pinch-out text instead of the button. Taps on it hit the overlay, two-finger pinches on it zoom the page (it sits in body, outside the panel's `touch-action: pan-y`; verified headless: back to 1× and gone). **×** folds it to a normal-sized "Zoomed 300%" tag at the visible top-left that reopens it — the screen keeps ignoring touches while zoomed either way (the user asked for this on 2026-11-26 after the plain bar's reset did nothing on a real phone and finding a spot to pinch was hard). There is no standard API to undo a user's zoom, so never promise the button works. Note: Chrome honours react-resizable-panels' `touch-action: pan-y` on the terminal page, so pinching inside the panel does nothing there; iOS Safari forces pinch zoom, which is how people got in. Headless can't pinch inside the panel either — test with `Emulation.setPageScaleFactor` (verified: bar, touches pass through, reset back to 1×, canvas takes touches again at 1×). **Start screen = two ways to start, either one:** the path, then a **Start right away** card (always a new tab: clears `nextUrlRef`), an "or" rule, and `DevicePorts` titled **Start from a page on this device** (a click = `nextUrlRef` + start; no path diagram there, the steps already draw it). While starting / running the same component sits in the header's **Ports** popover (40rem; title "On this device" + the browser ─SSH─ device path; a click = `openTab`, queued while starting). **Layout for many ports:** a left rail of kinds with counts (`groupPorts` / `PORT_GROUPS`: seen / usual / maybe / no = no URL; a `NativeSelect` below the `@lg` container width), tiles of the shown kind (`shownGroup`: the chosen kind, else the first non-empty — follows a search) in a **fixed-height grid**: always 4 rows of 3rem, two columns (8 per page) when the component is ≥ 32rem (`useWide`, measured in rem so it follows the display scale, same line as `@lg`), else one column (4); empty cells stay empty, the compact pager row always takes its line, and the kind's hint (not web / never scanned) sits under the rail when wide and behind an ⓘ popover beside the select when narrow — so switching kinds or pages never changes the height (measured: every kind × 3 languages × 360–1440 px × 100/130 %). A tile = `:port` (+ lock, + **Device only** for loopback-only) over one line of name or `localhost:<port>/`, truncated with the full name in the tooltip. Search over every kind once there are more than 10 ports (`matchPort`: number substring or name). Keep kind labels short enough for the phone select (ja was shortened for that). Port names: the scan's title → its protocol → `lib/lanConnect.serviceName` (never "HTTP" for a web port). Copy under `browser.ports.*`.
