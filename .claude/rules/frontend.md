# Frontend — i18n mechanics, preferences, settings page, UI building blocks, design

### How it works

- **Dictionaries:** `src/frontend/src/locales/` — `en.ts` is the **source of truth** for keys
  (`export const en = {...} as const` → `TranslationKey = keyof typeof en`). `zh-TW.ts` and `ja.ts`
  are typed `Record<TranslationKey, string>`, so a missing or extra key is a **compile error**.
  Keys are flat `namespace.camelCase` (e.g. `tunnels.deleteMessage`), namespaced by feature
  (`common`, `nav`, `api`, `login`, `firstLogin`, `tunnels`, `tunnelActions`, `tunnelDetails`,
  `wizard`, `tidy`, `platforms`, `wayIn`, `tunnelPage`, `datasets`, `discreet`, `tapiLook`, `signinLook`, `cliSignIns`, `deviceInstall`, `terminal`, `detach`, `shellHistory`, `watch`, `latency`, `kbd`, `files`, `browser`, `scripts`, `config`, `share`, `webhooks`,
  `manageUsers`, `keys`, `groups`, `orgGroups`, `personalGroups`, `peopleGroups`, `impact`, `sso`, `logs`, `deviceFacts`, `settings`, `security`, `siteSettings`, `prefs`, `apps`, `deleteTunnel`, `steps`, `language`, `network`, `join`, `commands`, `toolbox`, `apiPage`, `cli`, `clientIp`, `tunnelName`, `eggs`, `notFound`, `about`, `ui`).
- **In components/hooks:** `const { t, tn, locale, language, setLanguage } = useI18n()` from
  `@/lib/i18n`. `t(key, vars?)` returns a string; `{var}` placeholders interpolate
  (`t("tunnels.deleted", { name })`). `tn(key, vars)` accepts ReactNode values so sentences keep
  inline `<code>`/`<strong>` without splitting the translation.
- **Outside React** (e.g. `lib/api.ts` error builders): use `translate()` from `@/lib/translate`
  (module-level; the provider keeps its locale in sync).
- **Preference resolution:** `"auto" | "en" | "zh-TW" | "ja"` stored in the `telepy.language`
  cookie, resolved **client-side**: a pre-paint inline script in `app/layout.tsx` sets
  `<html lang>`, and `I18nProvider` applies the locale in a `useLayoutEffect` before the hydrated
  frame paints. **Never read `cookies()`/`headers()` in the root layout** — that makes every
  route dynamic, disables full Link prefetch, and made page navigation take seconds (real
  regression, since reverted). After login the preference syncs with the backend `UserSettings`
  (`/api/user/settings`; also included in `/api/auth/user/profile` as `language`,
  `null` = never chosen → the frontend pushes its local preference up; see `UserSettingsSync`
  in `lib/i18n.tsx`).
- **Switcher locations:** sidebar footer — four inline buttons (Auto/EN/繁/日,
  `components/layout/LanguageSwitcher.tsx`; the sidebar is collapsible — state in localStorage
  `telepy.sidebarCollapsed`) — and the user-preferences modal (gear button in the sidebar
  footer, `components/layout/UserPreferencesModal.tsx`). Admins can also set a user's language
  via Admin → Users & access → Users → Manage modal (`/api/user/users`, `/api/user/users/<id>`).
- **Other user preferences** (`lib/userPrefs.ts` + the `user_management_usersettings` row): `theme` **Card / list per page** (`view_modes` in `/api/user/settings` and the profile: a JSON map page id → `card` | `list`, replaced whole, validated by `api::users::parse_view_modes`; pages in `lib/viewModes.ts` `VIEW_PAGES` = tunnels, your SSH keys, key groups, the API page's API tokens and CLI sign-ins (`api_tokens` / `cli_signins`, list by default)) follows the account: `hooks/useViewMode.ts` + `lib/viewModeStore.ts` cache it in localStorage `telepy.viewModes` for the first paint, `UserSettingsSync` applies the server's at sign-in (or uploads the local one, including the old tunnels page's `tunnels-view`, while the account has none), Preferences → Appearance lists every page; `ViewToggle` only draws the two buttons. The tunnels page still shows cards below 1200px without changing the choice.
  (system/light/dark; class-based Tailwind dark mode, applied pre-paint by the same inline
  script from localStorage `telepy.theme`), the terminal defaults `terminal_font` / `terminal_font_size` /
  `terminal_scheme` / `terminal_bold` / `terminal_ligatures` (see **Terminal appearance** in `terminal.md`) and `ui_scale` (display size in percent, 85–130, step 5;
  localStorage `telepy.uiScale`; applied pre-paint as the `<html>` `font-size` so every rem-based size
  scales together while Tailwind's rem breakpoints stay put; presets small/medium/large = 90/100/115 in
  the sidebar footer `ScaleSwitcher`, the finer slider in the preferences modal; `hooks/useUiScale.ts`
  mirrors `useThemePreference`). All of them sync server-side via `/api/user/settings`.
- **Type scale:** `globals.css` overrides Tailwind's `--text-*` tokens so every step is 1px larger than
  stock (xs 13 / sm 15 / base 17 / lg 19 / xl 21 / 2xl 25) — jf-openhuninn reads small. Never use
  `text-[Npx]` for UI text: px ignores the display scale; use the tokens or `text-[Nrem]`.
- **Site-setting labels/descriptions:** the settings page prefers dictionary keys
  `siteSettings.<field>.label` / `siteSettings.<field>.description` (localized), falling back
  to the backend `meta` (label/description embedded in `api/site_settings.rs`). **When adding a
  site setting, add the column in `db/schema.rs`, the field in `db/settings.rs` + `api/site_settings.rs`,
  and these two keys to all three dictionaries.**
- The Settings page (`/tunnels/settings`, labelled **Site settings** / 網站設定 in the nav and title, with an "Admins only" chip) is admin-only, tabbed by `?tab=` in a grouped side rail (sticky from `lg`; a one-line select with optgroups below it), tabs and key → tab rules in the pure `lib/siteSettingsTabs.ts` (`SITE_TAB_GROUPS`, `siteTabOf`): **Accounts** = Registration & keys
  (default; `allow_registration`, `valid_register_domains`, `user_key_max_days`) / Sign-in (`signin_*` + `mfa_*`, + the sign-in page look panel with its preview); **Features** = Terminal & commands (`terminal_*` + `command_*` + `recording_retention_days`, + a link to the site-wide rules) / Remote desktop (`desktop_*`) / Remote browser (`remote_browser_*`) / Devices & network (`lan_scan_enabled`, `device_ip_lookup_url`) / AI access (`ai_*`, + MCP endpoint) / Notifications (`notify_*`: personal webhooks on / off, private targets, per-person limit; + a link to the Webhooks page). Users and feature access are pages of the admin section's Users & access area (the old `?tab=users` / `?tab=access` redirect, `adminAreas.movedSettingsTab`). **`valid_register_domains` has its own panel** (`components/settings/RegisterDomains.tsx`, pure + tested `lib/registerDomains.ts`, left out of the generic list like the sign-in look): removable chips, Enter / comma / space / paste to add, a "Test an address" check, saves on every add / remove as the same comma-joined string. A change that would refuse existing active accounts (judged by email domain, `newlyRefused`; an empty list counts as `gmail.com`) opens a danger `ConfirmDialog` listing them (you first) before saving; each chip shows how many active accounts use that domain (`coverage`). Backend truth it states: the list gates **every Google sign-in, existing accounts included** (`google_sign_in` checks the domain before looking the account up), by **exact** domain (no subdomains / wildcards); a blank list = `Config.default_register_domains` (`gmail.com`, no env var); `allow_registration` only decides whether a *new* account may be created afterwards; password sign-in is unaffected. `api::site_settings::normalize_domains` (`Kind::Domains`: lower-case, strips `@` / local part, dedupes, valid hostname, blank allowed, ≤ 512) mirrors the frontend helper — change both together. Site
  settings land in a tab by key prefix (`PREFIX_HOMES`) or an explicit `KEY_HOMES` entry — `lib/siteSettingsTabs.test.ts` reads `api/site_settings.rs` and fails when a new key has neither, so nothing falls into the first tab by accident; integer keys ending in
  `_timeout` / `_lifetime` / `_delay` / `_secs` are seconds and are edited as a number plus a unit (`DurationField`). Personal
  preferences live in the sidebar gear modal (`4xl`; tabs: General = language + desktop notifications / Appearance = theme + display size / Terminal / Remote desktop (the last two hidden when that feature is off) / Security / Saved logins / Connected apps; API tokens are on the API page).

## UI conventions

- **UI building blocks** (use these instead of hand-rolling): every dialog is `components/ui/Modal.tsx` (`title`, optional `description` / `icon` / `tone="danger"`, `toolbar` for tabs / filters — a fixed row between header and body, **never put tabs inside the scrolling body** (they get squashed when the body is a shrinking flex child), `footer` for the buttons; the body is the dialog's only scroll area — no fixed-height `max-h-* overflow-auto` boxes inside it — and a built-in "More below" pill (`ui.moreBelow`) appears while it overflows; sizes sm…5xl incl. `xl`; settings-style dialogs pass `nav` (`components/ui/nav-tabs.tsx` `NavTabs`: a left rail from `sm` up, a row above the body on phones, outside the scroll area) plus `fixedHeight` so switching tabs never resizes the dialog (a dialog may be as tall as the window minus 4rem, fixed-height ones `min(100dvh − 4rem, 54rem)`; the ones whose tabs show long one-line values — keys, fingerprints, scripts — are `5xl`; content that fits must never show a sliver of scrollbar, so measure `scrollHeight − clientHeight` per tab in all three languages at 1440×900 when adding content) — the preferences modal, the key details dialog (Overview / Edit / Devices) and the device keys panel do; it focuses the panel on open instead of the close button, and becomes a bottom sheet on phones; **on phones the fixed chrome stays small** — the description moves to the top of the scrolling body (rendered in one place only, via `useMediaQuery`, since descriptions can hold buttons), the icon tile is hidden except for `tone="danger"`, and `fixedHeight` dialogs fill the screen without the grabber; `StepFooter` drops its progress text and Back's label on phones so the footer is one row. Measured with real dialogs at 360 / 375 / 402 px × 100 / 115 / 130 %: the worst body share went from 23 % to 61 % of the screen. Filter rows of several segments become a one-line `NativeSelect` on phones (target accounts)) and confirmations are `ConfirmDialog`; long lists page with `components/ui/pagination.tsx` `Pagination` + `hooks/usePagination.ts` (`usePagination(total, {storageKey, resetKey, sizes?})` — `sizes` defaults to 10 / 25 / 50 / 100, card grids pass `CARD_PAGE_SIZES` — the page size per list in localStorage, back to page 1 when `resetKey` (the search / filter / sort) changes; `useSectionPages` = each group section pages on its own with one size) and the pure `lib/pagination.ts` (tested): search and filters always run over everything first, then the result is paged; every Refresh button is `components/ui/refresh-button.tsx` `RefreshButton` (the icon turns at least once and stops only where a turn ends — a fast request no longer flickers —, then a check; `onRefresh` answers `false` on failure = no check, so page loaders return whether the data arrived; `busy` = the page's own background loads turn it without the check, and a refresh whose answer comes later over a socket (file manager, RustDesk files) only sends the request and turns until `busy` ends, `failed` = it came back as an error; not disabled while turning, repeat clicks ignored; reduced motion = no turn, the check once the data is in; `ripple={ref}` then fades the on-screen list items in that element back in one after another — items are `data-refresh-item` elements or the children of a `data-refresh-list` container (mark the `ol` / `tbody` / card grid; `TimelineDay` already is); timings + stagger pure in `lib/refreshMotion.ts`) — actions such as Sync now / Check again / New link keep their own icons; click-to-open panels anchored to a control are `components/ui/popover.tsx` (same surface as the dropdown menu; Modal's `MoreBelow` is exported for scroll areas inside one); notices are `components/ui/callout.tsx` (`tone` info / tip / warning / danger / success, optional `title` line and custom `icon` — no more `bg-blue-50` / 💡 / tinted `bg-warning/[0.07]` boxes; the create wizard's "Why this step?" cards are `info` callouts); tabs and small single-choice toggles are `components/ui/segmented.tsx` (`fullWidth` labels wrap instead of truncating; `size="sm"` for in-form toggles); on/off switches are `components/ui/switch.tsx` `Switch` (`size="sm"`, children = a label inside the same button; all sizes in rem so the knob stays centred at every display size); form fields are `components/ui/field.tsx` `Field` (label + control + hint / error, wires `aria-invalid`) around `Input` / `Textarea` / `NativeSelect` (`components/ui/native-select.tsx`, styled `<select>`; `className` sizes the wrapper and the `<select>` follows its height and font size — `h-8 text-xs` = the small one; it used to stay h-9 and stick out next to h-8 buttons); section titles, `label : value` lists and small pills are `components/ui/section.tsx` (`Section` / `SectionHeading`, `PropertyList` / `Property`, `Chip`) — the tunnel page, the key details dialog, the preferences modal, Connected apps, Security and the MCP / settings panels all use them; **on a page, wrap stacked `Section`s in `SectionPanels`** and each becomes a card (header strip = icon tile + title + action, the description on the next row running under the action and from the left edge on phones, a hairline, the body; `tone="danger"` = red border + icon; `h2` by default; Sections inside a card, and inside every `Modal` (`SectionFlat` — context crosses portals), stay flat), optionally with `SectionOutlineProvider` + `SectionOutline` for an "on this page" list (tunnel page, Server health's overview uses the cards); `Property` stacks label over value below a 20rem list (container query) so a value never spills out on a phone at large text sizes; every page starts with `components/layout/PageHeader.tsx` (text-only title + addon, description, actions; `icon` shows only on phones; **`back={{href, label}}` = the way one level up, a small "← label" link above the title on the left** — the sidebar is on the left, so going back is too; the right-hand actions are things you do to the page, never navigation back (tunnel page, watch page, create wizard)); the header breadcrumb (`Header.tsx`, pure + tested `lib/breadcrumbs.shownCrumbs`) links every earlier crumb (`Telepy` → `/tunnels`, the section, an admin area / keys parent) and the last one too when its URL is not the current page; a page adds its own last crumb with `hooks/usePageCrumb.ts` (`usePageCrumb(name)`: tunnel page = tunnel name, terminal = device, watch = "Watching …"); phones show the last two crumbs; page-level tabs that change the URL use `NavTabs as="nav"` (a navigation list with `aria-current`, optional `below` under the current item), dialogs keep the default tablist
- **Design language** (modelled on the Cloudflare / Tailscale / Teleport consoles, deliberately not their copy): warm-grey neutrals plus one persimmon-orange `primary` (light `#bf511a` with white text, dark apricot `#f88a3d` with dark text) used only for primary actions, focus, the current item and Telepy itself; `success` (green) / `warning` (yellow-leaning amber) / `info` / `destructive` are separate hues — use them for status, never `primary`, and never Tailwind `emerald-*` / `amber-*` / `red-*` classes. Flat surfaces: hairline borders do the elevation, no glows (`shadow-glow` is gone), no `backdrop-blur`, no hover lifts, no gradient tiles — `bg-brand-gradient` is only for the Telepy glyph tile. Radius scale from `--radius: 0.5rem`: `rounded-xl` cards / panels / dialogs, `rounded-md` buttons / inputs / segmented tracks, `rounded-sm` badges / chips / segments. Status is a dot + text, not a glowing pill; avatars are `bg-foreground text-background`; dialog icon tiles are neutral unless `tone="danger"`. No uppercase-tracked eyebrow labels.
- Design tokens live in `globals.css`: surfaces `bg-card` (raised) / `bg-surface` (wells inside cards and dialogs) / `bg-muted` (tracks, chips), shadows `shadow-card` / `shadow-card-hover` / `shadow-pop` (menus, selects, tooltips, toasts) / `shadow-dialog`, overlay `bg-(--overlay)`; animations `animate-pop-in/out`, `animate-sheet-*`, `animate-toast-in` (there is no tw-animate plugin — `animate-in` / `slide-in-from-*` classes do nothing)
