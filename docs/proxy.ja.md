# デバイスプロキシ

<p align="center"><a href="./proxy.md">English</a> | <a href="./proxy.zh-TW.md">繁體中文</a> | <b>日本語</b></p>

デバイスプロキシは、トンネルをネットワークプロキシにします。プログラムはトークンを付けて Telepy に接続し、デバイス自身の SSH サーバーが宛先への接続を開きます。宛先にはデバイスのアドレスが見え、`localhost` はデバイス自身を指します。

デバイスには何もインストールせず、何も実行しません。デバイスの sshd が `ssh -D` や[リモートブラウザ](./remote-browser.ja.md)のためにすでに行っている転送と同じもので、プロキシはアプリからも使える入口を足すだけです。

## 何に使えるか

- **自分のブラウザーで、デバイスから外へ出る。** `telepy proxy box --browser` は、デバイスを経由する Chrome を開きます。リモートブラウザと同じことができ、サーバー側でブラウザーを動かす必要がなく、速さは自分のマシンそのままです。
- **プロキシを設定できるツール。** `curl`、パッケージマネージャー、データベースクライアントなど、`HTTPS_PROXY` を読むものや SOCKS5 を話すものすべてです。
- **連携するアプリ。** アプリが OAuth でサインインし、使えるトンネルを本人が選び、アプリはそのトンネルを通して接続を開きます。

目の前のコンピューターに何もインストールできないときは、引き続きリモートブラウザを使います。スクリプトによる操作（`telepy browse`、MCP エージェント）も同じで、Telepy が操作できるブラウザーが必要だからです。

## 有効にする

管理者が有効にするまではオフです。「サイト設定 → 機能 → デバイスプロキシ → デバイスプロキシを許可」で有効にします。

有効にしたあと、次のすべてを満たす人が使えます。

| 確認項目 | 設定する場所 |
| --- | --- |
| その人の「デバイスプロキシ」機能がオン | ユーザーとアクセス → 機能アクセス |
| トークンまたはアプリが `proxy:use` を持つ | API ページ、またはアプリの承認ページ |
| トンネルがそのトークンやアプリの範囲内 | トークンの作成時、またはアプリの承認時に選択 |
| トンネルが見えて、使えるデバイスアカウントがある | トンネルの共有とアカウント |
| トンネルがセッションごとの確認を求めていない | トンネルの設定（ステップアップのトンネルは拒否） |

## 自分のコンピューターから

```sh
telepy login https://telepy.example.com --scope "tunnels:read ssh:exec ssh:files proxy:use"
telepy proxy                       # プロキシに使えるトンネル
telepy proxy box                   # 127.0.0.1:8118 にプロキシ。同じポートで HTTP と SOCKS5
telepy proxy box --browser         # 同上に加えて、それを使う Chrome（別プロファイル）
curl -x http://127.0.0.1:8118 https://ifconfig.me     # デバイスのアドレス
```

`telepy proxy` には SSH 鍵も管理者権限も要りません。Web ポートだけを使うので、Telepy の Web ページが開ける場所ならどこでも動きます。プログラムが開く接続 1 本が、Telepy への WebSocket 1 本になります。

`--browser` は Chrome、Chromium、Edge、Brave を探し、プロキシ設定と専用のプロファイルフォルダーを付けて起動します。普段使っているブラウザーとその設定には触れません。ほかのブラウザーでは、プロキシを自分で `http://127.0.0.1:8118` に設定してください。

デバイスのネットワークに届くほかの方法との比較です。

| | 必要なもの | 運ぶもの | 向いている用途 |
| --- | --- | --- | --- |
| `telepy proxy` | `proxy:use` を持つトークン | TCP（プロキシ設定経由） | ブラウザー、curl、プロキシ設定のあるツール |
| `telepy forward` / `ssh -L` | デバイスに登録した自分の SSH 鍵 | 1 つのポート | 決まったローカルポートで 1 つのサービスを使う |
| `telepy vpn` | 自分の SSH 鍵と、このコンピューターの管理者権限 | すべてのアドレス（プロキシ設定なし） | プロキシを使えないプログラム |
| リモートブラウザ | 自分のコンピューターには何も不要 | ブラウザーの画面 | インストールできないコンピューター |

## アプリから

### トークンを取得する

- **OAuth**（ほかの人が連携するアプリ）：MCP クライアントが使うのと同じ認可サーバーで、[MCP](./mcp.ja.md) に説明があります。スコープ `proxy:use` を要求します。承認ページで本人が「すべてのトンネル」か「選択したものだけ」を選び、アプリが一覧して使えるのはその範囲だけです。
- **個人 API トークン**（自分のスクリプト）：API ページ →「あなたのトークン」で `proxy:use` を持つトークンを作成します。一部のトンネルに限定することもできます。

### トンネルを一覧する

```sh
curl -H "Authorization: Bearer $TELEPY_TOKEN" https://telepy.example.com/api/proxy/tunnels
```

応答には、このトークンがプロキシに使えるトンネル、それぞれのデバイスアカウント、いま使えるかどうか（`blocked` が `null`、または `step_up` / `no_account` / `offline`）、そしてエンドポイントが含まれます。

### 接続を開く

WebSocket 1 本が TCP 接続 1 本です。

```
wss://telepy.example.com/ws/proxy/?tunnel=<id または名前>&host=<ホスト>&port=<ポート>[&account=<デバイスアカウント>]
Authorization: Bearer <トークン>
```

Telepy はアップグレードの**前に**すべての確認を済ませ、デバイスに宛先へ接続させます。そのため、失敗は `{error, code}` 付きの通常の HTTP 応答になり、`101` が返ればデバイスは宛先に届いています。以降のバイナリフレームがその接続のバイト列で、どちらかが閉じれば終わりです。

| ステータス | `code` | 意味 |
| --- | --- | --- |
| 401 | `token_required`、`token_invalid` | トークンがない、または無効・期限切れ・取り消し済み |
| 403 | `proxy_disabled`、`token_scope`、`feature_disabled`、`step_up_refused`、`no_account` | 上の確認項目のどれかが通らなかった |
| 404 | `tunnel_not_found` | このトークンにそのトンネルはない |
| 400 | `bad_request`、`bad_target`、`username` | パラメーター不足、ホストが単純な名前やアドレスでない、または使えないアカウント |
| 429 | `proxy_busy` | 同時接続が多すぎる |
| 502 | `device_offline`、`device_login_failed`、`resolve_failed`、`connect_failed` | デバイスがオフライン、または宛先に届かなかった |

API ページの「プロキシ」タブには、このサーバーのエンドポイントと、値を埋めた例が表示されます。

## 標準のプロキシアドレス

プロキシ URL しか受け付けないプログラムもあります。管理者はそのために、もう 1 つの入口として通常の HTTPS プロキシを開けます。

```sh
curl -x "https://box:$TELEPY_TOKEN@proxy.example.com:8444" https://ifconfig.me
```

**ユーザー名がトンネル**（名前または id。`@アカウント` を付けるとデバイスアカウントを指定できます）、**パスワードがトークン**です。自分でヘッダーを設定できるプログラムは、代わりに `Proxy-Authorization: Bearer <トークン>` と `Telepy-Tunnel: <トンネル>` を送れます。認証情報がないと `407` が返るので、ブラウザーは入力を求めます。その先は WebSocket の入口とまったく同じで、確認もセッションもログも共通です。

有効にするには、`.env` に次を設定して再起動します。

| 変数 | 役割 |
| --- | --- |
| `PROXY_PORT` | プロキシの入口を公開するホスト側のポート。例：`8444`。空欄 = 開かない |
| `PROXY_URL` | 利用者がプロキシ設定に入れるアドレス。例：`https://proxy.example.com:8444`。「サイト設定 → サーバー → アドレス」でも設定できます |
| `PROXY_TLS_CERT`、`PROXY_TLS_KEY` | 証明書チェーンとその鍵（PEM。コンテナ内のパス。例：`/data` の下）。両方あれば入口は HTTPS プロキシになります。なければ平文の HTTP なので、前段で TLS を終端する必要があります。トークンがリクエストに含まれるためです |

プロキシアドレスには、サーバーへ**直接**届く名前が必要です。CDN や多くの Web プロキシは Web のリクエストは通しても `CONNECT` は通しません。SSH に別の名前が要ることが多いのと同じ理由です。「サイト設定 → サーバー → アドレス」には、Web アドレス、SSH ホスト、プロキシアドレスが並んで表示されます。

プロキシアドレスを設定しなくても困ることはありません。デバイスプロキシは Web アドレス上の WebSocket を通り、`telepy proxy` が利用者自身のコンピューター上で通常のプロキシを用意します。

## Telepy が確認し、記録すること

1 つのトークン（またはアプリ）が、1 本のトンネルを 1 つのデバイスアカウントで使って開いた接続全体が、1 つの**プロキシセッション**です。

- セッションの開始時と終了時に、トンネルのログへ 1 行ずつ書きます。終了の行には、接続の本数、送受信量、接続先（最初の 20 件）が入ります。
- 開いているセッションは API ページの「プロキシ」タブに並び、本人、トンネルの所有者、管理者が終了できます。終了すると、その接続はすべてすぐに切れます。
- Telepy は 10 秒ごとに確認し直します。トークンの取り消し、アカウントの無効化、共有の解除、デバイスアカウントの削除、機能やサイト全体のスイッチのオフ、いずれでもセッションは切断されます。
- Telepy は接続の中身を見ません。HTTPS 接続は、プログラムからサイトまで暗号化されたままです。

## 制限

- TCP のみです。UDP と ping は通りません。
- 既定では、トークンとトンネルごとに**同時 64 接続**まで（サイト設定 → デバイスプロキシ）、トークンごとに同時 8 トンネルまでです。
- 接続のないセッションは 60 秒で閉じ、次の接続で新しいセッションが開きます。
- 名前はデバイスが引きます。Mac のデバイスでは、Telepy が先にデバイス上で名前を引きます。Apple の sshd は名前を渡されると接続全体を切ってしまうためです。

## トラブルシューティング

| 表示 | 対処 |
| --- | --- |
| `proxy_disabled` | 管理者が「サイト設定 → デバイスプロキシ」で有効にします |
| `token_scope` | `--scope "… proxy:use"` でサインインし直すか、それを持つトークンを作ります |
| `step_up_refused` | そのトンネルはセッションごとに確認を求めます。Web か ssh を使ってください |
| どの宛先でも `connect_failed` | デバイスの sshd が転送を禁じている可能性があります。`sshd_config` で `AllowTcpForwarding yes` にします |
| ページの文字は出るが画像が出ない | そのページに必要な接続数が上限を超えています。「サイト設定 → デバイスプロキシ」で上げてください |
| `telepy proxy` がポート使用中と言う | `--port` で別のポートにするか、`--port 0` で空いているものを使います |
